# C7 安装事务锁审查记录

更新时间：2026-09-03

## 发现与修正

安装维护壳内部已有串行操作门禁，但独立启动两个维护壳，或同时从命令行启动安装、回滚和卸载脚本时，原先仍可能并行读取旧 `current.json`。两个安装事务都以旧活动版本生成指针时，后写入者可能覆盖前一个版本的回滚链。

新增 `tools/csharp-windows-install-transaction-lock.ps1`，由安装、回滚和卸载脚本在所有状态/文件操作前共同取得 `Local\\GpAutoLive.CSharp.Windows.InstallTransaction.v1` 命名互斥：

- 立即尝试，不等待；占用时返回 `install_transaction_busy`，不创建 staging、不切换指针、不删除版本；
- 进程异常退出时由 Windows 自动释放；发现 abandoned mutex 时立即接管；
- 仅限制安装事务，不改变 C# 主程序 `GpAutoLive.CSharp.MediaOutput.Owner.v1` 资源锁，也不修改 `desktop/`；
- 安装维护壳把该 helper 作为固定工具内容复制，命令行和维护壳共用同一边界。

## 验证

本轮补充安装事务边界：安装会严格校验已有 `current.json` 的 schema、活动版本、`relative_path` 和 `previous_version`，损坏指针在 WhatIf 阶段即 fail-closed；若版本目录已切换但活动指针写入失败/被取消，只清理本次新版本目录并保留旧 `current.json`。新增边界脚本覆盖损坏指针、有效 WhatIf 不落盘和指针激活失败回滚。

```powershell
& pwsh -NoProfile -File .\tools\test-c7-install-transaction-lock.ps1
& pwsh -NoProfile -File .\tools\test-c7-install-boundaries.ps1
```

结果：安装、回滚、卸载三条写操作在外部持锁时均以非零退出并包含 `install_transaction_busy`；边界测试通过，WhatIf 未创建安装根目录，指针激活失败未留下新版本目录且旧指针内容保持不变。

并复验：

- v89 发布包 Manifest/SHA-256 核验通过；`-RequireSigned` 按预期拒绝未签名开发候选；
- v89 `-PlanOnly` 不启动进程、不写冒烟报告；真实冒烟检测到 PID 19612 后返回 `blocked_preexisting_processes`，未触碰该进程；
- `artifacts/install-test-v83` 安装状态 read-only 与 WhatIf 均返回 `healthy / installation_verified`，目录内容未改变；
- v89 根目录 8 个运行文件、`1,450,736` bytes，`GpAutoLive.exe` `162,816` bytes。
