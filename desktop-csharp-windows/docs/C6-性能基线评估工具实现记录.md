# C6 性能基线评估工具实现记录

## 1. 实现内容

`tools/evaluate-process-baseline.ps1` 只读取 `collect-process-baseline.ps1` 生成的本地 JSON，不启动应用、不访问网络、不访问控制面，也不触碰已有进程。它完成以下边界：

- 输入文件大小最多 16 MiB，样本最多 36,001 个；输入文件和输出文件拒绝重解析点。
- 根对象、`summary` 和每个样本均要求固定字段集合；未知字段、缺失字段、重复 JSON 字段、错误类型、超范围数值和非 Windows 平台 fail-closed。
- 时间戳必须是带时区的合法字符串；样本 `elapsed_ms` 必须严格递增，并以首尾样本计算真实观测跨度。
- `summary` 的数量、最小值/最大值和 CPU 最大值必须与样本重新计算的结果一致，避免只信任可伪造的汇总字段。
- `IdleCpu` 使用至少 3 个有效 CPU 样本、至少 30 秒观测窗口和 nearest-rank P95；P95 必须严格小于 1%。
- `NoPlayback30m` 与 `JointPlayback30m` 要求至少 30 个样本、真实跨度至少 1,800 秒，并核对私有工作集首样本到峰值/末样本的增长预算（分别 20 MiB/40 MiB）。
- 外部 `Process` API 无法证明目标进程 GC 后回落稳定，因此两个 30 分钟场景始终把 `gc_stability` 标记为 `not_ready`，必须结合应用内 GC 快照和长稳记录；不会把一次采样或填大的 `duration_seconds` 判为达标。

输出是最多 64 KiB 的 UTF-8 JSON，使用同目录临时文件后原子替换写入。`status` 为 `passed`、`failed` 或 `not_ready`；退出码分别为 `0`、`3`、`2`。输入格式或安全边界错误退出码为 `1`，且不产生评估报告。

## 2. 使用方式

必须使用 PowerShell 7（`pwsh`）：

```powershell
pwsh -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass `
  -File .\desktop-csharp-windows\tools\evaluate-process-baseline.ps1 `
  -InputPath .\desktop-csharp-windows\artifacts\baseline.json `
  -OutputPath .\desktop-csharp-windows\artifacts\baseline-evaluation.json `
  -Scenario NoPlayback30m
```

可选场景为 `JointPlayback30m` 和 `IdleCpu`。采集器的 `DurationSeconds` 只是请求时长；30 分钟门禁使用样本中的 `elapsed_ms` 实际跨度。由于暖机样本不计入趋势，建议采集 1,802 秒或更长，并保留至少 30 个样本。

## 3. 夹具与测试

固定夹具位于 `tests/fixtures/performance/`：

- `baseline-single-sample-claims-30m.json`：声明 1,800 秒但只有一个样本，必须返回 `not_ready`。
- `baseline-three-samples-30m.json`：跨度达到 30 分钟但样本稀疏，并且没有跨进程 GC 证据，必须返回 `not_ready`。
- `baseline-idle-cpu-over-budget.json`：30 秒、3 个有效 CPU 样本，P95 为 1.5%，必须返回 `failed`。
- `baseline-unknown-field.json`：含未知根字段，必须以格式错误拒绝。
- `baseline-duplicate-field.json`：含重复根字段，必须以格式错误拒绝。

运行脚本测试：

```powershell
pwsh -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass `
  -File .\desktop-csharp-windows\tools\test-evaluate-process-baseline.ps1
```

本地结果：`C6 baseline evaluation tests passed`。该结果只证明评估器边界和夹具行为，不代表目标设备、播放负载、GPU、声卡或 30 分钟实机门禁已通过。
