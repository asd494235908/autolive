# C# Windows GUI 控件与像素还原整改方案

日期：2026-09-04  
范围：`GpAutoLive.App` WPF 授权态工作台、两张 v2 设计稿、登录门禁覆盖层  
结论：当前版本不能判定为与设计稿 1:1；先整改控件主题和显示链路，再重新做像素级验收。

## 本轮实施状态（2026-09-04）

- 已完成阶段 B 的第一轮接入：新增 `Themes/ColorTokens.xaml`、`Themes/TypographyTokens.xaml`、`Themes/ControlStyles.xaml`，并由 `App.xaml` 统一合并。
- 已移除旧的重复按钮、文本框、密码框、下拉框和焦点样式，避免局部资源覆盖共享主题；下拉框已接管箭头、Popup、选中值、条目高亮、键盘焦点和禁用态。
- 禁用下拉框现在保留可读值和边界，仅降低交互强调；按钮、输入框、密码框和普通复选框统一使用新的字号、内边距、圆角、焦点和禁用态。现有资源映射为 `AccentButtonStyle=Primary`、`ButtonStyle=Secondary`、`TabButtonStyle=Ghost`、`IconButtonStyle=Icon`，不额外复制同义模板。
- 媒体池已移除目标图不存在的重复“就绪”列；标题栏产品图继续使用 Rust 同源 PNG，显示尺寸从 `22×22` 调整为 `26×26`，并补充像素对齐和高质量缩放设置，避免小尺寸下品牌副标识不可辨识。
- 针对最新截图复核已补齐顶部“工作区”页签边界、左侧播放设置两个 `34px` 下拉框、普通复选框和底部/麦克风 Slider 的几何；Slider 使用独立 `6px` 圆角轨道和 `12px` 带边界滑块，避免默认轨道过细。右栏输入框保持原卡片高度，防止放大后卡片溢出。
- 针对 2026-09-04 最新截图，视频处理首屏的 8 个结果卡已收窄为紧凑只读卡，每项只保留参数标签和结果值，移除大图标、γ 符号和迷你趋势线；标题行状态徽标固定 `28px` 高度，文字垂直居中，避免顶部裁切。参数绑定、系统生成和只读边界不变。
- 按最新验收意见，视频处理 8 个结果参数已由 `4×2` 调整为单行 `1×8` 紧凑网格，继续只显示标签和值，宽度按中央参数区均分；不新增横向滚动，所有结果仍为系统生成的只读快照。
- 声音、场景与设备状态续页的快照徽标同步复用 `28px` 高度和统一的垂直居中文本样式，避免同一类“自动生成 / 只读快照 / 待接入”文案在不同页面出现高低或裁切差异。
- 中央左侧分类入口（视频处理、声音处理、场景与合成等）统一显式设置水平/垂直居中、零内边距和像素对齐，避免分类文字受 WPF 按钮默认内容对齐影响而偏移或被边界挤压；视频入口继续使用目标图的主色激活态。
- 登录门禁的账号 `TextBox` 与密码 `PasswordBox` 已统一补齐 `36px` 高度和最小高度，避免只按文本行高测量导致输入框被压成细条；账号绑定、密码事件、登录命令和密码清空边界不变。
- 登录区“登录”“刷新会话”“离线续播（需已授权）”和“设备需要激活？”按钮已分别设置明确高度（主按钮 `34px`、辅助按钮 `30px`），并统一内容垂直居中，避免被默认文本高度压扁。
- 自绘标题栏的设置、最小化、最大化/还原和关闭按钮已声明 `WindowChrome.IsHitTestVisibleInChrome=True`，修复 `WindowChrome` 命中测试拦截导致按钮点击事件不触发的问题；原有窗口关闭和状态切换处理保持不变。
- 标题栏右侧按钮组已为最小化、最大化/还原和关闭按钮增加统一 `4px` 左间距，修复按钮相互贴合的视觉问题，同时不改变按钮命中区域和窗口边界。
- 构建前检查发现媒体导入结果与播放池 UI 投影结果类型不一致，已补齐局部兼容重载以恢复 App 构建；该修复只复用公共快照投影，不扩展 UI 或媒体行为。
- 为确保本轮登录视图能生成 x64 产物，修正播放完成方法中两个同作用域 `startedAudio` 局部变量的命名冲突；不改变播放分支、错误处理或声音启动行为。
- 实机窗口复核发现启动时参数滚动容器会被初始化阶段的 `BringIntoView` 错误带到续页；已移除该自动跳转，窗口加载时明确回到首屏，用户主动滚动和分类点击定位仍保留。
- 已重新生成授权态首屏/下滑 WPF 夹具，构建无警告无错误；真实原生窗口、下拉打开态、键盘/DPI 和任务栏图标仍待阶段 A/D/E 的实机验收，当前仍不能宣称 1:1。

## 2. 检查结论

### P0：控件显示链路不达标

1. `ComboBox` 的自定义外框内部仍直接使用默认 `ToggleButton`，下拉箭头区域出现系统灰块，和目标图的暗色细线箭头不一致。
2. 禁用态通过降低整块 `Chrome` 的 `Opacity` 实现，导致已选文字、箭头和边框一起变淡；当前下滑页的预设池、周期范围等内容几乎不可读。
3. `ComboBoxItem`、`ContentPresenter` 没有统一的垂直基线、最小高度和选中态，文字在不同控件中出现高低不一致。
4. 部分右栏控件在当前夹具中出现空值或截断，例如麦克风设备、固定话术字段；空值、禁用和未接入没有使用统一显示语义。

### P0：按钮和文字层级不一致

1. 全局按钮只有一个通用模板，主按钮、次按钮、幽灵按钮、图标按钮和禁用按钮的几何及对比度没有分层。
2. 图标与文字大量以内联 `StackPanel` 和局部 `Margin` 拼接，按钮宽度变化时容易出现文字偏移、压缩或截断。
3. 当前字体、字号、字重和辅助文字对比度整体偏小；目标图的标题、字段标签、结果值、状态徽标有明确层级，当前实现没有稳定复用的排版 token。
4. 结果值、状态徽标和辅助说明使用相近的灰色层级，用户难以区分“可操作”“只读快照”“待接入”和“不可用”。

### P1：整体画面仍不是目标 GUI

1. 三栏大结构接近，但控件内部视觉不一致，不能用“列宽接近”替代 1:1 验收。
2. 左侧媒体项多出当前状态文字，和目标图的缩略图、文件名、时长、媒体参数层级不一致。
3. 右栏卡片存在内容压缩和字段截断；目标图要求五张卡片在同一右栏中保持完整的标题、字段、状态和操作层级。
4. 中央滚动区的内容高度、滚动拇指长度和下滑后的可见边界仍受文字/控件尺寸影响，当前首屏和续页不能只靠静态网格判定合格。
5. 当前登录覆盖层没有独立目标图。它应作为单独的登录门禁视觉任务，不应继续以工作台设计稿反推。

### P1：图标“资源存在”但“显示链路未验收”

1. Rust 同源 `app-icon.png`/`app-icon.ico` 已复制到 C# 项目，但当前标题栏 22px 显示下完整品牌组合不够清晰，不能仅凭文件哈希判定完成。
2. EXE、主窗口、设置窗口、最终效果窗口、任务栏/快捷方式是不同显示链路，需要分别截图确认；旧 `bin`、历史 `artifacts` 和 Windows 图标缓存也会造成误判。
3. 顶栏产品标识应只保留一条真实资源路径，不能再出现旧的字母占位、缩放裁剪或窗口图标与标题栏图标不一致。

## 3. 整改原则

- 结果参数仍由系统随机生成，视频/声音本周期结果只读；用户只能修改规则、范围、预设池和输出配置。
- 控件的 enabled、disabled、empty、loading、error、待接入状态必须分别设计，不能用统一透明度覆盖所有语义。
- 所有尺寸以 `1586×992`、100% DPI 为基准，再验证 125%、150%、200% DPI；重要文字不得截断。
- 业务事件、命令名、ViewModel 和认证/播放状态机保持不变；本轮先修显示层，不借机改变媒体处理逻辑。
- 继续使用 WPF 原生 `ControlTemplate`、`Path` 和现有资源，不新增第三方 UI 框架。

## 4. 实施分阶段

### 阶段 A：冻结目标和建立验收基线

1. 将两张 v2 图登记为唯一工作台视觉基准，登录页另建一张明确的门禁目标图。
2. 以真实 WPF 窗口而不是仅使用注入夹具，分别捕获未登录覆盖层、授权首屏、授权下滑页、下拉框打开态、禁用态和错误态。
3. 建立分区检查表：顶栏、操作带、媒体池、播放设置、实时预览、参数首屏、参数续页、右栏五卡、底部播放栏。
4. 每个区域记录目标坐标、实际坐标、字体、颜色、边框、圆角、状态和文字截断情况；目标差异超过 2px 或文字不可读即不通过。

### 阶段 B：重做共享控件主题

新增职责明确的 WPF 资源字典，建议拆为：

- `Themes/ColorTokens.xaml`：背景、边框、正文、辅助、强调、警告、错误。
- `Themes/TypographyTokens.xaml`：标题、字段、正文、状态、数值、说明。
- `Themes/ControlStyles.xaml`：按钮、文本框、密码框、下拉框、复选框、滚动条。

重点修复：

1. 按钮拆成 Primary、Secondary、Ghost、Icon 四种模板，统一图标尺寸、文字基线、内边距、焦点、悬停、按下和禁用态。
2. `ComboBox` 完整接管 `ToggleButton`、箭头、选中值、Popup、Item 高亮和键盘焦点；禁止混入系统默认灰色模板。
3. 禁用下拉框保留可读的选中值和边界，只降低交互强调，不整体压暗文字。
4. 文本框统一 28/30/34px 控件高度；长文本按字段规则显示省略号，并提供完整 Tooltip。
5. 复选框、Expander、ScrollBar 的尺寸和颜色与设计稿统一，辅助文字满足可读对比度。

### 阶段 C：按设计稿重排工作台

1. 保留当前三栏和单中央滚动区，但把大 `MainWindow.xaml` 按真实边界拆成顶栏、工具带、媒体池、预览、参数区、右栏输出、底部播放栏等组件。
2. 首屏严格复刻视频单行 `1×8` 只读结果卡；续页严格复刻声音 8 项、规则行、高级视觉、频谱、设备状态和有界日志。
3. 删除目标图中不存在的重复状态文字；保留业务需要的状态时，放入目标图对应的位置和层级。
4. 重新校准右栏五张卡的高度、字段间距、按钮宽度和内容截断策略，保证首屏完整可读。
5. 规则编辑控件与结果快照分离：规则控件可编辑并有校验，结果卡只读且继续由系统随机生成。

### 阶段 D：统一图标显示链路

1. 保留 Rust 同源 PNG/ICO，验证 ICO 的多尺寸帧和 EXE `ApplicationIcon`。
2. 顶栏使用明确的产品 Logo 显示资源，增加适合 16/22/24/32px 的显示尺寸和留白，不再依赖缩放后不可辨识的占位效果。
3. 主窗口、设置窗口、最终效果窗口和任务栏分别核对图标，不允许只验证源码资源存在。
4. 清理旧构建输出的使用说明，所有截图和验收只能来自当前 Release 产物；不修改 Rust 目录。

### 阶段 E：交互和状态验收

逐项点击并截图验证：

- 按钮：默认、悬停、按下、禁用、键盘焦点、文字完整度。
- 下拉框：默认值、打开、选择、键盘上下键、空值、禁用值、错误值。
- 参数：规则修改、校验失败、取消、重新生成、生成失败、旧快照保留。
- 页面：首屏、下滑、回滚顶部、窗口缩放、100%～200% DPI、登录门禁覆盖层。
- 图标：标题栏、任务栏、设置窗口、最终效果窗口和安装/发布产物。

## 5. 完成标准

- 两张工作台设计稿在 100% DPI、`1586×992` 下逐区通过，关键几何误差不超过 2px。
- 所有按钮文字、下拉选中值、字段标签、状态徽标和说明完整可读，无默认 WPF 灰色下拉箭头残留。
- 视频/声音本周期结果仍不可手工修改；规则和范围编辑入口可用且错误状态明确。
- 图标在标题栏、EXE、任务栏和两个子窗口均显示完整且来自 Rust 同源资源。
- 登录覆盖层有独立目标图；控制面未配置、网络失败、账号错误、设备未激活等状态各自显示稳定文案。
- 本地完成 `dotnet format`、全量测试、本地 Release 构建和 WPF 实机截图；不在服务器构建。

## 6. 子任务拆分和审核方式

实施时拆为三个相互独立的子任务：

1. 控件主题、字体和下拉框模板。
2. 工作台各区域布局与文案层级。
3. 图标显示链路、截图基线和 DPI/交互验收。

子任务完成后由主线程以代码总监视角检查 diff、删除无用样式和重复模板，再统一构建、测试和截图验收；任何删除现有业务代码的清理另行确认。
