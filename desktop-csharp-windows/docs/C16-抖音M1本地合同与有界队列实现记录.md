# C16 抖音 M1 本地合同与有界队列实现记录

日期：2026-09-03

## 本轮落地

- `GpAutoLive.Contracts/DouyinLiveContracts.cs` 建立 M1 的本地配置、状态、最小弹幕 DTO、脱敏弹幕元数据、回复任务、队列统计和脱敏状态快照。配置只允许数字直播间号或标准 `https://live.douyin.com/<digits>`，本地回复池限制为 1～100 条、每条最多 80 个 Unicode 字符/320 个 UTF-8 字节，队列容量限制为 10～5000，默认 500；脱敏事件只允许报告不超过 16 KiB 的正文长度，不接收正文。
- `DouyinReplyTask` 现在在入队时生成本地 `client_action_id`，任务出队后沿用同一 ID 进入 sidecar 请求，避免把每次重试/核对误生成成不同动作；`DouyinLiveStatus.ReplySendingBlocked` 表示本轮因认证失效、限流或风控停止新发送，读取侧仍保持独立。
- `GpAutoLive.Core/DouyinLiveManager.cs` 作为会话、代际、去重集合、随机选句和有界串行队列的唯一所有者。只读取最小化的 `WebcastChatMessage` 映射，不保存完整弹幕历史，不保存 Cookie/Token，不访问网络、不调用模型、不经过 Go，也不创建无人管理的后台 Worker。
- 本账号回显、重连重放和重复消息 ID 在入队前过滤；去重集合固定 4096 条。队列满时丢弃最旧未发送项，任务等待严格超过 60 秒才过期；发送结果分为 `accepted/not_sent/rejected/outcome_unknown`，未知结果不自动重试，避免重复发送。
- `DouyinLiveManager.ObserveChatMetadata` 校验 sidecar 报告的单房间、发送者、消息 ID 和正文长度后，复用同一套去重、随机选句和有界队列；入队时间由 C# 调用方传入，不把 sidecar 时钟或正文伪造为 C# 消息对象。
- Windows parser 已按 Rust 冻结的 `live.chat` NDJSON v1 包络将 `msg_id/author_id/nickname/content` 转为上述脱敏元数据；`content` 只保留长度，当前房间由宿主注入并在 Core 再次校验。
- 会话状态按 `WaitingQr → LoggedIn → RoomResolved → Listening` 管理，支持暂停后修改队列容量、恢复、停止和确定性失败；停止/失败会清空队列和去重集合并提升代际，迟到任务不能污染新会话。
- WPF 只投影脱敏状态文案，当前显示“扫码/sidecar 待验收”或本地状态，不伪装已连接抖音；真实扫码、协议适配、单条发送和自回显验证仍由后续受管 sidecar 接入。

## 明确边界

本轮是可测试的本地合同、队列核心和脱敏事件消费边界，不是抖音平台接入。未实现 QR 登录、真实 `WebcastChatMessage` 网络读取、平台发送、回显确认、登录态持久化、多账号、多房间、多平台、模型调用或绕过平台检测。M1 凭据必须只存在内存，重启重新扫码；真实 sidecar 还必须通过 Conda 锁定环境、进程取消/超时/Job Object、许可与安全审查、远端兼容和退出清理门禁。

## 未验收项

真实抖音 QR/协议兼容、单直播间授权、受管 Python sidecar、平台发送限频、自回显确认、网络重连、下游账号安全和长稳测试均保持“正式需求·待实施/未验收”。在这些门禁完成前，不把本地状态或自动化测试描述为抖音可用产品。
