# RTMP 声音时间轴修复记录

本记录对应 2026-09-07 功能链路修复计划的 C 项。当前状态：代码已接入，自动化与实机结果以主审查报告为准，不能把连接成功等同于远端音画验收。

## 起点与声音周期

- 编码器探测完成后，先在最终 PCM 总线锁内复制本机尚未消费的尾部到现有 RTMP 环缓，再启动发布进程。起点由当前有效声音计划的 `SourceStartMs` 与复制首帧在候选内的位置计算，不使用固定零点、墙钟估算或 UI 参数草稿。
- 已预载 N+1 总线同步保留其未读头部；候选正在提交或计划与总线身份不一致时，有界等待后重新捕获，不能组合旧计划和新总线。
- RTMP 基础帧不抢跑到本机已读帧之前，两个消费者按同一候选内绝对帧边界切换。跨边界的同一个输出块分段混音，旧基础轨只配旧插话轨。
- 本机和 RTMP 插话源分别跟随各自基础轨的候选；麦克风生产者使用本机实际候选。远端仍在读取旧尾部时，不提前切换其插话源或回收旧总线。
- RTMP 插话不能独立增加基础媒体时间：基础轨临时无帧时，保留有界插话尾部等待基础轨恢复；源结束或会话停止时取消尾部。本机独立插话输出能力保持不变。
- 当前 WPF 生成声音参数保持播放倍率 1.0。底层音画推流遇到非 1 倍率明确拒绝，不宣称支持动态视频变速。独立声音启动计划使用相同源起点，首次播放结束后的循环回到源零点。

## 有界资源与失败

- 复用已有 RTMP 基础和插话环缓，容量为本机单分支容量的两倍，单分支最高 480000 帧；默认本机容量 48000 帧、双声道 float 时，四条环缓合计约 2.20 MiB。额外空间承接起播尾部复制及消费者短时滞后，不阻塞本机音频生产，也不新增历史队列。
- 接入后发生 RTMP 环缓溢出时，读取返回明确的时间轴不连续错误，由会话停止发布；不能丢掉旧帧后继续显示同一条音画时间轴正常。
- 停止和 Dispose 必须真实等待任务与进程结束。未退出时保留资源所有者，并返回错误或抛出明确的释放异常供上层重试。并发 Dispose 共享同一关闭任务。
- 本机 PortAudio 停止失败时控制器保留输出对象，拒绝创建替代流；暂停、继续和停止使用有预算的异步原生操作。插话 CTS 的取消与摘除使用同一个所有权锁。

## 验收边界

自动化重点覆盖中途接入、已有 N+1、两消费者不同进度、精确边界分段、插话不抢跑、远端滞后时麦克风总线路由、启动溢出、取消及并发释放。真实 RTMP 验收仍需回读带秒标画面与音脉冲素材，并运行连续声音周期、文件插话和真人麦克风。

本实现保证基础媒体时间轴与候选边界一致，不把无时间戳的独立插话环缓宣传为本机与远端逐采样相同；网络消费者的短时滞后可能体现为插话起点的短时差异。必须用远端实测量化，不将虚拟静音输入当作真人麦克风验收。

## 2026-09-08 正常 RTMP unpublish 追加修复

功能边界：只修改本地 FFmpeg 停止协议，不修改 ZLMediaKit 配置。纯视频用受管 stdin 发送 `q\n`；纯音频关闭最终 PCM stdin 自然 EOF；音视频增加 `-shortest`，随 PCM EOF 完成输出。控制 stdin 不属于最终 PCM，不可被声音 API 写入。

所有停止阶段共享 Stopwatch 的 2 秒清理期限；正常退出最多占前 1.5 秒。停止先拒绝新 PCM，等待在途写入；取锁超时不关闭 stdin，先 Kill 并等待进程退出，再重新取锁清理。正常退出期间继续 drain stderr；进程、写入和读取完成前保留所有者。

失败优先验证：1）三轨道命令和控制 stdin/PCM 区别；2）视频 q 正常退出；3）音频 EOF 正常退出且没有 q；4）排队 PCM 取得锁后复核状态和输入身份；5）不配合退出或写锁超时走有界强杀，未完成清理保留所有者。真实 FFmpeg 正常退出及同 stream key 快速复用由独立验收补充，不能用夹具成功替代真实业务结果。
