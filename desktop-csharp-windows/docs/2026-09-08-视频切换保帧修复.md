# C# 视频文件切换保帧修复

状态：代码修复完成，2026-09-08 本机定向测试与六项真实 WPF/WGC 像素验收通过；尚未重新发布安装包，不代表所有显卡/DPI/跨机矩阵验收完成。

## 功能边界

用户要求视频文件切换期间不能出现程序引入的黑屏。当前 C# Windows 客户端在同一 mpv 视频会话中换源，但 `loadfile replace` 与异常停止会使原生黑底暴露。本次覆盖自动 EOF、上一项/下一项、末项回首项、单文件循环、暂停切换和文件池替换后的再次播放。

允许在准备新文件期间暂时保持上一张最终画面；不把保帧宣传为连续解码或无停顿。素材自身的黑帧、明确切到纯音频的黑色表面及用户主动关闭窗口保持现有语义。RTMP 直接读源的生命周期保持独立，不用窗口截图替代直接推流；当前手动换源停止 RTMP 的行为不属于本次预览保帧验收。

## 实现约束

1. 继续使用单个受管 mpv 进程。只在切换边界通过受限 IPC `screenshot-to-file … window` 获取本播放器的最终画面，包含实际视频效果；不截图桌面或第三方窗口。
2. 截图路径由程序在当前用户目录生成，使用唯一文件名、路径/重解析点校验、有限 PNG 大小和尺寸以及操作超时；命令完成后读入内存并删除临时文件，不生成视频版本或长期图片缓存。
3. `ReservedVideoSurface` 通过与 mpv 宿主同级的原生覆盖 HWND 显示保留画面，坐标映射后仅覆盖视频区域，先填充像素再显示；覆盖层不放在 mpv 管理的宿主内部，避免播放器退出对子窗口或宿主样式的操作暴露黑底。WPF 图片不能直接覆盖 HwndHost。保留单帧像素，位置及尺寸变化时重绘，完成、纯音频切换、主动停止或宿主窗口关闭时释放，并检查原生覆盖 HWND 存活状态。
4. 新源就绪必须绑定本次加载的事件和媒体身份，验证视频输出、非 seeking、有效视频帧及可提取的最终画面。暂停换片同样需要首帧，不能以路径变化或播放时间估计冒充完成。
5. 所有 App 切换通过现有播放命令串行入口；捕获旧帧失败时拒绝卸载旧视频，新源加载失败时保留旧帧并显示失败，不把旧图当成新视频已成功播放。
6. 保帧换源期间保持当前最终效果窗口尺寸，新源适配同一个输出表面；记录新源尺寸以避免后续快照重复自动缩放窗口。首次显示和明确退出全屏后的强制尺寸计算保持原逻辑。这样不同分辨率文件切换不会因窗口自动 resize 触发 WGC 的 FrameSizeChanged 停止；用户主动调整窗口尺寸仍遵守原有捕获生命周期。

- 删除了无效的 `video-pts` 属性及相关判断，以实际输出截图验证画面；删除了与六项真实夹具重复的旧长流程截图断言，不扩大无关长测试。
