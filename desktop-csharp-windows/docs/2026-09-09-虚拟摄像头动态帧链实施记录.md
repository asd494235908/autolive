# 虚拟摄像头动态帧链实施记录

日期：2026-09-09。状态：核心代码与定向验证完成；安装设备、sidecar 与实际下游收帧由总任务分别验收。

## 边界与接口

- 本次 C# 输出由调用方根据源视频分辨率提交 `VirtualCameraConfig`。宽度必须为正偶数，高度为正数；各边不超过 4096，总像素不超过 4096×2160。YUY2、30fps、一次 GPU→CPU 回读、设备名保持既有契约。1280×720 仅为未配置默认值；上层负责奇数源宽偶数对齐并显示实际尺寸。
- `VirtualCameraOutputManager.ConfigureOutput` 仅允许 Unavailable/Installed/Failed 状态更新配置；修改清除旧帧、GPU 事实并递增 generation。运行期间改尺寸必须先停止完整链路再启动。
- `VirtualCameraFrame` 和 `SidecarFrame` 尾部携带 Width/Height（默认值仅兼容既有 720p 调用）。manager 检查帧尺寸与会话一致，不允许同字节数但宽高不同的帧混入。
- GPU 转换器按配置创建半宽 RGBA 打包纹理和三个 staging 槽，viewport、逐行回读和 payload 大小均按配置计算。采样偏移按输出像素间距计算，避免缩放源纹理时 YUY2 对偏移错误。每次 Start 创建配置对应实例；WGC 确认停止后释放。
- `TryBuildFacts` 接收本次输出配置，报告真实输出尺寸；设备硬件信息仍由 D3D11 查询，禁止 WARP。
- sidecar 发送协议 v2，保留 `GPAKVC01` magic 与 52 字节头；36/40 为真实宽高，44 为 width×height×2。解码兼容 v1，但 v1 只允许 1280×720；v2 验证边长/像素/长度后才复制 payload。单帧最大 17,694,720 字节。
- writer 每次启动复用契约黑帧构造器生成对应尺寸黑帧，最新帧继续容量一。现有管道随机令牌、ACL、取消和超时不变。
