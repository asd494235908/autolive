# Phase C2：控制面契约与会话状态机

## 本阶段已实现

- `GpAutoLive.Contracts/AuthContracts.cs`
  - 登录、Refresh、Logout、设备自动激活、心跳请求/响应 DTO。
  - 所有跨进程字段显式使用 `snake_case`；`ContractJson` 拒绝未知字段。
  - 固定 `product=autolive`、`audience=desktop` 和稳定错误码。
  - 账号、密码、设备、版本、心跳指标和 Token 均有长度/范围上限。
- `GpAutoLive.Core/AuthSession.cs`
  - `Unauthenticated → Authenticating → Authenticated → Activated` 门禁。
  - 服务端设备非 `active`、授权过期、设备禁用/撤销和绑定冲突均保持工作台 fail-closed；这些设备授权失败不再冒充账号退出，除明确 401/`UNAUTHENTICATED` 外保留已登录会话以便直接重试授权。
  - `Offline` 只表示已进入过本地会话后的暂时断网；允许既有本地播放继续，但不能直接进入工作台或伪造激活成功。
  - 写操作按幂等键缓存有限终态；重复键返回同一结果，跨操作复用返回冲突。
  - 临时网络失败采用 `1/2/4/8/15s`、最多 5 次退避；重试未到时间时拒绝发起。
  - Refresh Token 只通过短暂 `CredentialAction` 交给后续 Credential Manager 适配器；不会出现在会话快照。无效/过期 Token 只产生删除动作，不产生保存动作。
- `GpAutoLive.Windows/ControlPlaneHttpClient.cs`
  - 使用 `HttpClient` 访问桌面专用登录、Refresh、Logout、设备自动激活和心跳路径；统一发送 `X-Request-Id`、Bearer 和幂等键。
  - 基地址只接受 HTTPS；显式测试配置下仅允许 loopback HTTP。请求超时、取消、网络失败、服务端稳定错误和未知响应均映射为脱敏结果。
  - 响应流默认限制 1 MiB（可在 4 MiB 内显式收窄/调整），使用严格 UTF-8、`ContractJson` 未知字段拒绝和 DTO 二次校验；不会把请求体、Token 或 URL 写入错误。
- `GpAutoLive.Windows/WindowsDeviceIdentity.cs` 与 `ControlPlaneAuthCoordinator.cs`
  - 设备标识存入 Windows Credential Manager，不采集 MAC、硬盘序列号或用户目录列表；服务端多设备模式下 C# 与 Rust 设备身份相互独立。C# 自身尚无 ID 时只读取固定 Rust 旧目标 `device-id.autolive.desktop`，按 Windows keyring 的 UTF-16LE 密码编码解码，合法则一次复制，损坏则拒绝自动创建第二设备；已有 C# ID 时不覆盖。
  - 串行驱动登录→自动激活、Refresh→重新激活、心跳和 Logout；不迁移 Rust 密码或 Token。远端撤销失败时本地立即退出，并把最多 8 条待撤销 Refresh Token 写入 C# 独立凭据槽，启动恢复前重试一条。
  - `GpAutoLive.App/LoginViewModel` 与 `MainWindow` 已接入该编排器；只有显式配置 `AUTOLIVE_CONTROL_PLANE_BASE_URI` 且地址校验通过时才创建 HTTP 客户端，未配置时保持无网络预览壳。
- `GpAutoLive.App/Features/Settings/DesktopPreferencesCoordinator.cs`
  - 将低敏感窗口尺寸/位置偏好接入用户数据目录 `GpAutoLive/config/app.ini`；读取失败回退默认值，写入继续使用 Core 的临时文件 + Flush + 原子替换边界。
  - 偏好协调器不接触媒体池、播放位置、URL、Token 或其他凭据；窗口几何应用时限制在 Windows 虚拟屏幕范围内。

## 重启恢复与后台心跳（最小边界，2026-09-02）

- 启动时只从当前 Windows 用户 Credential Manager 读取 Refresh Token；缺少凭据保持 `Unauthenticated`，非法 UTF-8/格式或服务端明确判定账号会话失效时 fail-closed 并删除凭据，不把 Token 放入 JSON outbox 或日志。设备授权失败只关闭工作台，不再冒充账号退出。
- 多设备登录下“账号认证”和“当前设备授权”分离：激活非 401 失败与本地授权到期退回 `Authenticated`，保留 Refresh Token 供管理员扩容、解绑或续期后直接刷新并重试；明确 401/`UNAUTHENTICATED` 会完整清空认证快照和本地凭据。
- 恢复成功必须再完成设备激活，服务端返回的 `user_id` 用于冷启动绑定；只有 `Activated` 才启动心跳。默认每 30 秒一次，调度器只持有一个可取消任务，发送经认证所有者串行化。
- 激活响应必须携带合法且晚于当前时间的授权到期时间；每轮心跳前按本地时钟收回到期授权。心跳产生的禁用、撤销、离线和恢复转换会单向投影到 WPF，不建立第二份认证状态。
- 网络/超时/408/429/5xx 等暂态失败最多保留一条当前账号/设备的无凭据心跳，恢复后先按原幂等键补发；永久授权/参数失败丢弃 outbox。退出先取消，再等待唯一循环任务 Join，测试可注入时钟，避免依赖真实睡眠。
