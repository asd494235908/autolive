# C5 固定话术与声音实施边界评估

日期：2026-09-02  
范围：仅审查 `desktop/`，并在 `desktop-csharp-windows/` 建立 C5 固定话术合同、状态机和 Windows 本地语音适配边界。未修改 Rust/Tauri/React 参考目录；已修改 `MainWindow` 接入固定话术卡片，未修改 `MpvPlaybackStateMonitor`。

## 1. 结论

C5 本轮已完成“固定话术合同 + 单操作状态机 + 可注入 Windows SAPI 适配边界”，并补充 RTMP/RTMPS 配置与 FFmpeg 参数合同；后续增量已经接入 PortAudio、插话混音、RTMP Windows 宿主、AkVirtualCamera 契约/协议/Named Pipe 传输客户端和抖音 sidecar 边界，但真实设备、网络和外部 sidecar 仍未通过门禁。

固定话术合同和状态机不需要音频设备或媒体进程；Windows 适配边界通过注入桥接器完成可测试的启动、取消、超时和释放规则。纯逻辑和替身测试不能把“适配器代码存在”误报成“Windows 语音已可用”。

本增量已新增：

- `src/GpAutoLive.Contracts/FixedSpeechContracts.cs`：固定话术命令/状态 DTO、版本/类型常量、Unicode 文本和错误摘要边界；
- `src/GpAutoLive.Core/FixedSpeechStateMachine.cs`：单一活动操作、starting → playing → completed/failed/cancelled、旧操作身份门禁和麦克风优先拒绝；
- `tests/GpAutoLive.Contracts.Tests/FixedSpeechContractTests.cs`：wire 序列化、严格版本、文本和错误边界；
- `tests/GpAutoLive.Core.Tests/FixedSpeechStateMachineTests.cs`：状态转换、抢占、取消幂等和迟到回调；
- `src/GpAutoLive.Windows/WindowsSpeechContracts.cs`：脱敏 voice 描述、错误分类、桥接器和操作生命周期接口；
- `src/GpAutoLive.Windows/WindowsSystemSpeechAdapter.cs`：单操作所有者、启动超时、取消、抢占和有界释放；
- `src/GpAutoLive.Windows/WindowsSapiSpeechBridge.cs`：SAPI Automation COM 的 STA 操作线程和 RCW 释放；
- `tests/GpAutoLive.Windows.Tests/WindowsSystemSpeechAdapterTests.cs`：注入替身覆盖启动、完成、取消、超时、失败、关闭和脱敏；

以上代码不创建语音设备、不调用网络、不启动进程、不保存文本正文到运行快照。

## 2. Rust/Tauri 参考行为

参考行为以以下文件为准：

- `desktop/ui/src/fixedSpeech.ts`：版本为 `1`，命令类型为 `fixed-speech-command`，状态类型为 `fixed-speech-status`；操作 ID 上限为 128，文本按 Unicode 字符限制为 1～500；只选择本地系统语音并优先 `zh-CN`；状态为 `starting/playing/completed/cancelled/failed`。
- `desktop/ui/src/fixedSpeechPresets.ts`：预制文本最多 10 条，标题最多 80 个 Unicode 字符，正文最多 500 个 Unicode 字符；旧 key `autolive.voice-clone-presets.v1` 迁移到 `autolive.fixed-speech-presets.v1`。
- `desktop/ui/src/App.tsx`：主窗口经 `BroadcastChannel` 发送 speak/cancel；最终效果窗口使用 `window.speechSynthesis`，等待本地 voice，启动确认超时 1500ms；新朗读抢占旧朗读；麦克风说话时取消固定话术；朗读期间主效果音频静音，完成/取消/失败后恢复。

Rust `src-tauri` 当前没有独立的 C# 固定话术实现可直接复用；固定话术实际在 WebView 层通过 Web Speech API 执行。C# 不能把现有 `desktop/` 代码复制进新目录，只能以这些 wire 和状态事实作为只读参考。

## 3. 当前 C# 状态与边界

当前 C# 已有声音处理开关、纯音频播放壳；Windows SAPI 固定话术适配边界已接入 `MainWindow` 卡片，可提交本地文本、单操作取消并投影脱敏状态；PortAudio 已接入独立 DLL 动态加载、设备枚举、WPF 输出设备刷新、固定容量 PCM 双消费者总线、长期输出流和显式输入流边界；`AudioPriorityCoordinator` 已固定麦克风/固定话术/插话/原媒体的层级、静音和 duck 策略，并由 SAPI 适配器共享。插话文件/PCM 混音、RTMP Windows 宿主、AkVirtualCamera 固定规格/GPU 事实/52 字节协议/BCL Named Pipe 客户端和抖音 sidecar 受管宿主已建立边界，但普通声音候选的完整链路、AEC/降噪/AGC/VAD、麦克风抢占实际可听输出、最终音频时钟、真实 RTMP 网络、WGC/D3D11/DirectShow/真实 sidecar 仍待验收。上述边界均不等同于完整普通声音候选链路。

本次纯逻辑切片的约束：

1. `FixedSpeechStateMachine` 是唯一状态所有者，调用方必须串行调用；实际 Windows 适配器后续只能通过它提交状态。
2. 新 speak 接受时返回 `SupersededOperationId`，适配器必须先为旧操作发布 `cancelled`，再发布新操作 `starting`。
3. 任何 `playing/completed/failed` 回调都必须匹配当前 operation ID；过期回调返回 `Ignored`，不得污染新操作。
4. 麦克风优先时，新 speak 返回 `Cancelled`，不覆盖当前状态；麦克风开始说话时由更高层调用 `CancelActive`，并负责同步停止插话/固定话术实际输出。
5. 状态快照不保存文本正文；错误摘要最多 500 个 UTF-16 code unit，超限时收敛为固定脱敏文案。
6. 状态机不负责暂停/恢复插话、不负责主音频静音、不负责输出音量；这些属于未来唯一音频所有者，避免 C5 再造第二个播放事实源。

## 4. Windows 语音依赖判断

### 4.1 本切片不新增依赖

固定话术合同和状态机使用 .NET 标准库与现有 `System.Text.Json`。当前项目没有 `System.Speech` 包，也没有把 PortAudio 引入任何 C# 生产程序集；不应为了“先能发声”把音频设备、TTS、媒体混音一起塞进 C5。

### 4.2 实际朗读的推荐顺序

Windows 适配器放在 `GpAutoLive.Windows`，通过一个窄接口调用本机语音：

1. 已实现 Windows 系统 SAPI 的 COM `SpVoice`（仅 Windows，延迟绑定），将异步 `Speak`、取消和本地 voice 枚举封装在一个可释放对象内；不把语音 DLL 嵌入主 EXE。
2. 只有在 COM 事件、中文 voice 选择或目标 Windows 版本兼容性验证不足时，才评估 Microsoft `System.Speech` NuGet；引入前必须锁定版本、许可证、发布体积、线程模型和移除路径，并做 A/B 实机矩阵。
3. 不使用在线 TTS、模型、WebView2 作为 C# 最终实现，也不生成中间音频文件；否则会改变“本地系统朗读、取消、抢占和恢复”的既有语义。

SAPI 适配器已明确：单一活动操作、1500ms 启动门禁、取消时终止当前异步朗读、仅本地语音、`operation_id` 迟到事件丢弃、窗口/应用退出时有界等待和释放。SAPI 是否能达到 Web Speech API 的中文 voice 选择和发音效果，必须用 Windows 10/11 与中文语音包实机验收，不能由合同或替身测试推断。

## 5. 其他 C5 能力为何不作为下一切片

| 能力 | 参考现状 | 当前 C# 状态 | 结论 |
| --- | --- | --- | --- |
| 普通声音/PortAudio | Rust 有音频候选、PCM 总线、设备恢复和音画时钟 | 已有 PCM 环缓、双消费者总线、设备枚举、PortAudio 输出流、健康观察/有界重开和 RTMP 分流泵边界 | 仍依赖候选链路、SAPI 静音/恢复、真实拔插/睡眠唤醒、线程和 PTS；完成真实门禁后才能宣称可用 |
| 插话文件 | Rust 有目录扫描、22 套预设、多轨混合、duck、随机周期 | 未接入 | 需要音频所有者和优先级协调，不与固定话术状态机混写 |
| 麦克风插话 | Rust 有本地 DSP/VAD、PortAudio 输入和抢占回调 | 未接入 | 需要真实声学/设备/长稳门禁，不能先做假输入 |
| RTMP/RTMPS | Rust 有配置校验、FFmpeg 发布、PCM 分流、重试和 Job Object | 已接入独立 URL/轨道配置合同、FFmpeg 参数计划和 Windows 长生命周期宿主，真实发布未验收 | 仍不能宣称发布能力；需 PortAudio/最终 PCM、编码器探测、重试和网络门禁 |
| AkVirtualCamera | Rust 有 WGC/D3D11 + GPL sidecar 与安装/许可门禁 | 已接入固定合同、GPU 事实/状态、52 字节协议和 BCL Named Pipe 客户端；真实链路未验收 | 需要签名、ACL、DirectShow x86/x64 和设备矩阵，必须独立资源包 |
| 抖音 M1 | Rust 有 Python 探针草案和本地回复校验 | 未接入 | 需要 Conda 锁定、扫码、协议兼容、自回显和限频；不得因面板复刻抬升成熟度 |
