# C4 普通声音 PCM 环缓边界

## 状态

当前状态：代码已接入·待普通声音候选、真实设备恢复门禁与真实声卡验收。

## 已实现边界

- `AudioPcmRingBuffer` 使用固定容量的交错 `float` PCM 数组，不扩容、不保留历史音频正文。
- 写入端按完整帧校验样本数；环缓满或单次写入超容量时丢弃最旧帧，记录丢弃帧数，保持实时延迟有界。
- 读取端只返回完整帧且不阻塞；关闭后保留已缓存帧供排空，拒绝新的写入。
- PortAudio 回调使用 `TryReadRealtime/TryWriteRealtime`，临界区繁忙时立即输出静音或丢弃当前输入帧，不等待普通 UI/混音读写锁。
- 所有状态通过短临界区保护，快照只返回容量、声道、可读帧数、丢弃计数和关闭状态，不返回音频正文。
- `FinalPcmBus` 负责把最终 PCM 有界发布到本机与 RTMP 两个消费者环缓；`WindowsPortAudioDeviceEnumerator` 负责固定 DLL 的设备枚举；`WindowsPortAudioOutputStream` 负责单一长期输出流，预分配回调缓冲，消费本环缓并在欠载时输出静音，不执行文件/网络 I/O。
- `WindowsRtmpFinalPcmPump` 负责从 RTMP 消费者环缓串行写入 FFmpeg `pipe:0`，不再从源媒体读取第二份声音。
- 本边界不实现 A/B 候选、duck、插话抢占或音画时钟；输出流的真实声卡恢复、音频总线接入和长稳仍需单独验收。

## 验证

`GpAutoLive.Media.Tests/AudioPcmRingBufferTests.cs` 覆盖环绕读写顺序、满载丢弃、超容量写入、帧形状校验、关闭后排空和关闭写入拒绝。

- 普通声音候选的 N/N+1 预载、A/B 切换和恢复；
- 真实可听 PTS 主时钟、mpv 视频纠偏、纯音频/视频混排和 30 分钟稳定性。
