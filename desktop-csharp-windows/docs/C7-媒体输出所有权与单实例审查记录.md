# C7 C# 媒体输出所有权与单实例审查记录

更新时间：2026-09-06

## 当前边界

Rust/Tauri 与 C# 是隔离的两个桌面客户端。Rust 只作为实现参考阅读对象，C# 不启动、探测、调用或联调 Rust，也不与 Rust 共用媒体/输出互斥。

本专项只验收 C# 自身的：

- 单实例门禁；
- mpv、PortAudio、RTMP、虚拟摄像头等本端媒体/输出生命周期；
- 崩溃后的本端锁释放与重新启动；
- C# 安装事务的签名、升级中断恢复、回滚和卸载边界。

## 结论与最小修正

- C# 使用专属 `Local\\GpAutoLive.CSharp.MediaOutput.Owner.v1` 命名 Mutex，立即尝试、不等待、不启动或探测其他客户端；同一 C# 进程内重复获取、内核 Mutex 争用和 abandoned Mutex 均 fail-closed 或安全接管。
- C# 启动顺序为：Windows 运行时/AppUserModelID 配置 → C# 媒体/输出租约 → C# 单实例锁 → 主窗口。失败路径释放已取得的本端租约，退出时按输出资源锁再单实例锁的顺序释放。
- 已删除 C# 对 `autolive-desktop-core` 的进程探测、Rust 运行状态判断和跨客户端错误码；Rust 进程存在与否不会改变 C# 启动结果。
- 保留媒体输出租约是为了保护 C# 自身多个进程/输出生命周期；它不是 C#↔Rust 协议，也不要求启动 Rust 验证。
