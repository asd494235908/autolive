# C3–C5 本地 Windows 离线验收矩阵

## 目标与边界

`tools/verify-c3-c5-local-acceptance.ps1` 把现有 C3–C5 自动化合同组织为一个可重复执行的本地 Windows 门禁。它只运行已编译的测试程序集，不执行 restore/build，不启动 `GpAutoLive.exe`，不连接 ZLMediaKit、RTMP/RTMPS 地址或控制面，也不上传媒体、音频、路径和设备信息。

脚本与 C7 发布冒烟职责不同：本矩阵验证媒体和设备边界的合同及测试期间新增的 `mpv/ffmpeg/ffprobe` 残留进程；C7 的 `smoke-csharp-windows-release.ps1` 才负责启动发布 EXE、等待窗口、优雅关闭、退出码和整机同名进程冲突。

## 矩阵

| 门禁 | 自动化范围 | 不代表 |
| --- | --- | --- |
| C3 媒体池 | 最多 100 项、绝对路径/扩展名、原子批次、播放身份 | 真实媒体可解码 |
| C3 输入探测 | FFprobe 固定参数、输出上限、超时、取消、失败回滚 | 启动真实 FFprobe |
| C4 资源与 mpv | Manifest 路径/大小/SHA-256、启动计划、JSON IPC、状态监视 | GPU83/CPU4 像素生效 |
| C4 进程生命周期 | 本机隐藏进程、Job Object/进程树回退、mpv/FFmpeg 取消与停止 | 30 分钟长稳或嵌套 Job 全矩阵 |
| C4/C5 音频设备 | PortAudio DLL/资源缺失、非法设备配置、输入输出取消、麦克风本地门控 | 真实无输入/输出设备、打开声卡、AEC/降噪/AGC |
| C5 RTMP 合同 | 地址校验与脱敏、轨道组合、FFmpeg 参数数组、编码器降级 | 连接真实 RTMP/RTMPS |
| C5 RTMP 生命周期 | 缺失 FFmpeg、声音会话、PCM 分流、幂等停止、有限重连策略 | ZLMediaKit 鉴权、真实断线信号与恢复 |

超时/取消进程夹具只使用 `127.0.0.1` 回环地址。脚本执行前会暂时移除当前进程可见的全部 `AUTOLIVE_TEST_*` 环境变量，避免显式真实 mpv、FFmpeg 或 PortAudio 夹具被意外启用；退出前恢复原值。测试命令固定带 `--no-restore --no-build`，因此不会在验收阶段从 NuGet 下载依赖。

## 使用

先在本机完成锁定依赖恢复和 Release 构建；恢复依赖本身不属于离线验收脚本：

```powershell
desktop-csharp-windows\.tools\dotnet\dotnet.exe restore desktop-csharp-windows\GpAutoLive.Windows.slnx --locked-mode
desktop-csharp-windows\.tools\dotnet\dotnet.exe build desktop-csharp-windows\GpAutoLive.Windows.slnx -c Release --no-restore
```

查看计划，不启动测试、不写报告：

```powershell
pwsh -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -File desktop-csharp-windows\tools\verify-c3-c5-local-acceptance.ps1 -PlanOnly
```

执行矩阵并原子写入不超过 64 KiB 的 JSON 报告：

```powershell
pwsh -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -File desktop-csharp-windows\tools\verify-c3-c5-local-acceptance.ps1 `
  -OutputPath desktop-csharp-windows\artifacts\c3-c5-local-acceptance.json
```

任一筛选测试失败，或测试结束宽限期后出现新的 `mpv/ffmpeg/ffprobe` 进程，脚本返回非零。既有进程只记录为基线，不终止、不计为本轮残留。

JSON 中的 `deferred_gates` 始终单独列出真实资源/设备/服务才能验证或当前尚未实现的门禁。它们不计入离线合同退出码，也不能因脚本 `status = passed` 被解释为已经通过。

## 边界审查发现的未闭合风险

- `WindowsPortAudioOutputRecovery` 的首次重开失败路径现已保留恢复资格，后续最多 3 次都会进入同一重开入口；自动化已覆盖三次上限和首次失败后的第二次分类。真实设备拔出、驱动重置及原生调用硬超时仍需目标声卡门禁。
- 麦克风输入现已投影 `Pa_IsStreamActive/Stopped` 健康状态；缺少可选导出时明确返回 `Unknown` 并继续运行，观察到 `Stopped`、`Inactive` 或 `QueryError` 时异步停止并进入 `Failed`，不自动无限重开。PortAudio 原生 Start/Stop/Close/Terminate 仍没有可从同进程强制打断的硬超时。
- `WindowsFfmpegPcmDecoder` 已修正 stderr 反压边界：达到 16 KiB 诊断计数上限后仍持续读取并丢弃，不保留原文；真实 FFmpeg 的 stderr 进程级持续写入仍需目标资源门禁。
- RTMP `StartAsync` 在进程启动后即进入 `Publishing`，不代表 RTMP 握手或首包成功；有限 `Reconnecting` 策略已有本地合同测试，但尚未接入真实断开信号，长生命周期计划的 Timeout 也未形成验收证据。
- 部分真实 mpv/FFmpeg/PortAudio 测试在环境变量缺失时直接返回，普通全量测试会把它们计为 Passed。本脚本不选择这些真实夹具，并将对应证据列入 `deferred_gates`。

这些问题本轮只形成验收门禁和事实记录，没有扩大为媒体运行时修复；后续实现时应分别补充可失败的测试，并继续保持真实设备/服务状态不抬升。

## 仍需真实设备/服务

- 真实 mpv HWND 首帧、长 GOP/混排、连续 EOF/seek、GPU83 → CPU4 → Original 和目标 GPU 矩阵；v85 已在本机临时 2 秒素材上单独通过 `Original/Cpu4/Gpu83` 各 1/1，但该证据不替代目标设备矩阵。
- PortAudio 真实声卡听感、输入/输出设备拔插、默认设备切换、睡眠唤醒和 30 分钟资源趋势。
- 麦克风真实 VAD 阈值、回声环境、优先级听感；AEC/降噪/AGC 仍未接入。
- 本机或隔离测试网内的 ZLMediaKit 音画/单轨、RTMPS TLS、鉴权拒绝、断线恢复和硬件编码器矩阵。
- C7 发布 EXE 启动/关闭、签名、安装/升级/卸载和跨 Windows 10/11 验收。

在这些证据完成前，相关能力继续保持“代码已接入·待真实设备/服务验收”，本矩阵通过不能提升成熟度声明。
