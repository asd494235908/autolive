# C3 媒体探测边界

本阶段先落地纯逻辑边界，不把 `ffprobe.exe` 嵌入主 EXE。`GpAutoLive.Media` 只负责输入校验、固定参数计划、有限结果映射和取消/超时语义；通用进程合同位于 `GpAutoLive.Core.Processes`，真实 Windows 适配器由 `GpAutoLive.Windows.WindowsExternalProcessRunner` 实现。这样 `Media -> Core`、`Windows -> Core`，不会形成 `Media <-> Windows` 循环引用。播放池状态由 `GpAutoLive.Core.MediaPoolOwner` 单独持有，最终效果窗口只接收脱敏快照。

## 已实现

- 视频扩展名：`.mp4/.mov/.mkv/.avi/.webm/.m4v/.ts/.m2ts/.flv/.wmv/.3gp`。
- 纯音频扩展名：`.mp3/.wav/.m4a/.aac/.ogg/.flac`。
- 路径仅允许绝对路径，拒绝控制字符、超长路径、目录和不支持扩展名；路径失败返回固定结构化错误，不回显路径。
- FFprobe 可执行文件只接受绝对路径且文件名必须为 `ffprobe.exe`；不接受任意可执行文件。
- 参数使用不可变数组，固定包含 `-v error`、`-hide_banner`、`-print_format json=compact=1`、`-show_format`、`-show_streams` 和 `-show_chapters`，不拼接 shell 命令字符串。
- 默认探测预算为 5 秒、stdout 512 KiB、stderr 64 KiB。输出超过上限必须由 Runner 终止进程树，并映射为稳定错误。
- Windows 启动策略固定为 `UseShellExecute=false`、`CreateNoWindow=true`、重定向 stdout/stderr，并要求超时与取消清理整个进程树。
- 播放池已完成 17 种扩展名、最多 100 项、路径/文件/元数据和媒体类别一致性校验；失败批次保持旧快照，EOF 只接受匹配 generation/revision/index/loop 身份的回调。手动 `SelectAt`、`Previous`、`Next` 同样要求匹配四维身份：切换目标时只递增 generation、更新 source_media_index 并将 loop_index 归零，source_revision、播放池回绕计数和 `Ready/Playing/Paused/Stopped` 状态保持不变；首项/末项手动切换按播放池回绕，单项切换为空操作。
- 最终效果窗口已完成单实例控制器、脱敏快照、纯音频黑色表面和 Windows 视频 HWND 预留；当前 HWND 只创建黑色 `STATIC` 子窗口。
- `FfprobeSourceParser` 已将受管 JSON 转换为 `SourceMediaDto`，校验 format 时长、视频尺寸/帧率、音频采样率/声道和纯音频不能含视频流。
- `MediaImportCoordinator` 已将路径列表、FFprobe 探测、文件大小读取和 `FfprobeSourceParser` 串成逐项有界流程；仅当整批成功时才调用 `MediaPoolService.ReplaceAll/Append/ReplaceAt`，失败或取消均保留旧快照。
- 导入请求最多读取 100 项；探测按用户顺序串行执行，最多保留 100 个解析后的候选，导入请求之间由单一有界门控串行化。重复路径不在 Media 层重复实现，最终由 Core 播放池提交规则拒绝并保持旧快照。
- WPF 媒体池已接入 Windows 原生 `FileDrop` 拖放；只复制数量合法的文件候选并保留系统返回顺序，拖放批次统一以 `Append` 请求交给 `MediaImportCoordinator`，仍遵守整批探测、失败回滚和登录门禁。选中项移除、清空均需原生 `MessageBox` 确认，`Delete` 键复用同一移除路径；确认取消不会改变播放池。

## 尚未接入

- Windows 适配器已接入最小 Job Object 创建/分配/终止增强；创建或分配不可用时回退到 .NET `Process.Kill(entireProcessTree: true)`。真实媒体进程的孤儿进程、嵌套 Job 和权限矩阵仍待验收，详见 [`C4-外部进程执行边界`](./C4-外部进程执行边界.md)。
- WPF 组合根通过固定安装目录资源清单按需创建已验证 FFprobe 探测器，再交给 `MediaImportCoordinator`；缺少清单或校验失败时不会打开导入流程，也不会把路径/异常正文展示给 UI。
- mpv/PortAudio 的真实播放、seek、EOF、换源和视频/纯音频混排实机门禁。

## 验收

`GpAutoLive.Media.Tests` 使用内存 Runner 验证白名单、参数数组、隐藏无 Shell 策略、取消/超时/输出上限、脱敏错误，以及整批导入成功、逐项失败回滚、取消停止后续项、重复路径交由 Core 拒绝和 100 项边界。`GpAutoLive.Core.Tests` 覆盖媒体池原子 CRUD、循环身份、手动上一项/下一项与错误回滚；`GpAutoLive.App.Tests` 覆盖最终效果控制器、壳层投影和 Windows FileDrop 顺序/数量边界。测试不创建子进程，不依赖本地 FFprobe，也不会把媒体运行资源嵌入主 EXE。
