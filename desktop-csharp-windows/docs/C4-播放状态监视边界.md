# C4 播放状态监视边界

日期：2026-09-02  
状态：代码已接入·待真实 mpv 验收

## 目标

为单一 mpv 会话提供最小播放状态读取入口，覆盖：

- `time-pos` → `PlaybackTimeMs`；mpv 在尚未有有效位置时返回 `null`，保留为可选值；
- `eof-reached` → `EofReached`；
- `pause` → `Paused`。

## 实现边界

- [`MpvPlaybackStateMonitor.cs`](../src/GpAutoLive.Media/MpvPlaybackStateMonitor.cs) 位于 `GpAutoLive.Media`，只依赖已有 `MpvPlaybackIpcGateway` 和 Core 的 `MediaPlaybackIdentity`，不引用 `GpAutoLive.Windows`，不启动 mpv。
- 每轮按固定顺序串行读取恰好 3 个属性，复用现有 request ID、响应配对和属性白名单；轮询间隔限制为 50ms～5s，默认 250ms。
- `WatchAsync` 是可取消的异步迭代器，不创建后台无人管理任务，也不维护无界队列；单轮失败后结束，调用方负责持有并取消枚举。
- 轮询开始、三项读取完成后、快照应用前均检查活动身份。身份缺失、变化或候选快照身份不一致时 fail-closed。
- 相同身份的完全重复快照返回 `Changed=false`，不重复触发上层动作；EOF 推进仍须由 Core `CompleteCurrent` 使用四维身份门禁完成。
- 播放时间只接受有限非负数，并转换为毫秒；超出 mpv IPC 可精确表示范围、负数、非数值或布尔/时间类型错误均拒绝。
- `WindowsMpvPlaybackRuntime` 只在“宿主进程已启动且 IPC 已连接”后创建并保存状态监视器；启动失败、停止或释放时不会把未连接/已释放的网关交给上层。`WindowsMpvPlaybackController` 仅转发该受管观察器，不复制状态或创建第二个轮询所有者。
- `PollPlaybackStateAsync` 在同一运行时生命周期信号量内完成整轮读取，保证 `StopAsync`/`DisposeAsync` 不会与状态轮询并发释放网关。
- `WatchPlaybackStateAsync` 是运行时拥有边界的可取消异步迭代器：每一轮重新取得生命周期锁，并校验监视器实例仍属于当前运行时；停止或释放后在接触网关前返回 `RuntimeUnavailable` 并结束，不创建 `Task.Run`、后台轮询任务或无界队列。
