1. 文档状态说明

本产品仍处于「实施中」，不是正式发布完成版。文中每项能力按以下口径区分：

  • 已实现并生效：真实媒体/设备/网络链路已验证。
  • 代码已接入 · 待验收：代码链路和自动化测试已通过，但真实设备、声卡、GPU、网络或安装门禁尚未完成。
  • 正式需求 · 待实施/未接入：仅有需求或占位，尚不可用。

请以「已实现并生效」作为可用判断依据，其余状态不代表可投入生产使用。

项目要求
操作系统Windows 10 2004+ / Windows 11，x64
.NET 运行时.NET 10.0.11 Windows Desktop Runtime x64（安装器离线携带或在线安装）
媒体运行资源mpv / FFmpeg / FFprobe / PortAudio / D3DCompiler 外置资源包（安装目录 runtime/ 下）

3. 安装与启动

3.1 安装包

  • 安装器为 NSIS 单文件 GpAutoLive-Setup-*.exe，安装到 %ProgramFiles%\GpAutoLive\app。
  • 安装器会离线安装或修复 .NET 10.0.11 Windows Desktop Runtime x64，并创建开始菜单、桌面快捷方式和标准卸载登记。
  • 卸载保留 %LocalAppData% 配置、Windows 凭据和用户媒体文件。

当前安装候选仅用于内部测试：未签名、法律待审。文件名带 TEST-UNSIGNED-LEGAL-REVIEW 者不得作为生产安装包。

3.2 开发启动

源码开发环境使用仓库锁定 SDK 启动：

desktop-csharp-windows\tools\start-csharp-development.cmd

脚本每次先用仓库锁定的本地 SDK 以 Platform=x64 编译当前 App，再启动对应 bin\x64\Release 产物；构建失败会 fail-closed。

3.3 启动门禁顺序

程序启动按固定顺序建立门禁（App.xaml.cs）：

  1. 配置 WinRT 按需运行库解析器；
  2. 建立 Windows 应用身份（AppUserModelID）；
  3. 获取「媒体/输出资源所有权」互斥锁——同一用户已有实例占用时提示并退出；
  4. 建立「单实例」门禁——已有实例运行时新实例直接退出；
  5. 显示主窗口。

4. 登录与设备授权

4.1 状态链路

登录门禁状态机为：

SignedOut → Authenticated → Activated
  • SignedOut：未登录，工作台和播放栏禁用。
  • Authenticated：账号登录成功，等待服务端设备授权。
  • Activated：设备授权通过，才开放工作台。
  • Offline：只能从已授权会话进入，表示进入工作台后的断网续播；冷启动不能用离线状态绕过登录。

4.2 控制面配置

  • 未配置控制面时只做本地输入/状态投影，不发网络请求。
  • 测试联调：设置 AUTOLIVE_CONTROL_PLANE_ENV=test 与 AUTOLIVE_CONTROL_PLANE_BASE_URI=http://101.96.208.132:9090。
  • 本地开发：AUTOLIVE_CONTROL_PLANE_ENV=development，允许固定测试地址或 loopback HTTP。
  • 正式环境：要求显式 HTTPS 地址；其他远程 HTTP 一律拒绝。
  • NSIS 安装版通过应用目录内 GpAutoLive.control-plane-profile 决定口味：cloud-test-v1 自动连接唯一测试地址并隔离测试凭据；production-v1 只接受显式 HTTPS；offline 强制禁网。安装器不写全局环境变量。

4.3 凭据存储

  • Refresh Token、待撤销 Token、设备身份均存入 Windows Credential Manager（当前用户），不落盘、不进日志。
  • 设备 ID 为随机 desktop-<GUID>，不采集硬件序列号。
  • 登录成功且设备授权通过后，后台每 30 秒发送一次心跳；播放状态上报 idle/playing/paused/error。

5. 主界面布局

主窗口为三栏工作台 + 顶栏 + 底栏：

  • 顶栏：设备授权状态、账户、授权到期、CPU/GPU/内存、设置按钮、最小化/最大化/关闭。
  • 操作带：主页/工作区、添加媒体、整理媒体、导入列表、保存配置、加载配置、开始推流、打开效果窗口、主菜单（退出登录）。
  • 左栏：媒体池（搜索、类型筛选、条目列表）与「播放设置（本地有序循环）」卡片。
  • 中栏上半区：音频诊断（最终 PCM 音谱、三条周期进度）。
  • 中栏下半区：参数 / 播放队列 / 快捷键 / 日志 Tab，以及视频处理、声音处理、场景与合成分类导航。
  • 右栏：RTMP 推流、虚拟摄像头、麦克风插话、固定话术、抖音弹幕五张输出/能力卡片。
  • 底栏：播放、暂停、停止、上一条、下一条、时间轴、当前媒体、独立的视频处理/声音处理开关、音量。

6. 媒体池操作

6.1 支持格式

  • 视频：.mp4/.mov/.mkv/.avi/.webm/.m4v/.ts/.m2ts/.flv/.wmv/.3gp
  • 纯音频：.mp3/.wav/.m4a/.aac/.ogg/.flac

扩展名只用于选择过滤，最终以 FFprobe 的真实流、时长和可读性探测为准。

6.2 添加媒体

  • 点击「添加媒体」按钮或按 Ctrl+O：按所选顺序追加到当前播放池，不删除已有条目或本地源文件。
  • 拖放文件到媒体池：保留系统顺序，按「追加」语义送入同一导入协调器。

6.3 导入链路（原子提交）

选择文件 → 逐项 FFprobe 探测 → 文件大小读取 → 解析 SourceMediaDto
        → 整批成功后才原子 Append/ReplaceAll/ReplaceAt
        → 任一探测失败/重复路径/超限/取消 → 保留旧播放池并显示错误
  • 最多 100 项；探测按用户顺序串行执行；默认预算 5 秒、stdout 512 KiB、stderr 64 KiB。

6.4 编辑操作

  • 上移/下移：调整选中项顺序。
  • 移除：删除选中项（需确认，不删除本地源文件）。
  • 清空：清空播放池（需确认）。
  • 搜索：按文件名或媒体类型过滤，空白恢复完整池。
  • 类型筛选：全部 / 视频 / 音频。
  • 以上操作只修改进程内播放池引用，用户本地源文件不进入删除路径。

6.5 播放设置

播放触发方式：本地有序循环 / 手动播放当前项；播放完成后保持最后一帧 / 回到首项；可勾选循环播放。「应用到全部」批量设置尚未接入正式配置。

7. 播放操作

7.1 播放链路

点击播放 → mpv 单一受管进程 + JSON IPC（命名管道）
        → 视频：GPU83(gpu-next/libplacebo) → CPU4 → Original 单向降级
        → 声音：FFmpeg PCM 解码 → FinalPcmBus → PortAudio 输出 / RTMP 分流
  • 视频与声音周期独立，但共享源时间轴；PortAudio 启用时以实际可听 PTS 为主时钟校正 mpv 视频 PTS。
  • 纯音频项不创建 mpv 视频会话。
  • 播放池顺序循环：末项结束回到首项，单项池自循环。
  • 视频处理模式切换（Original/CPU4/GPU83）会从当前 mpv 位置有界重启单一会话；GPU83 启动失败单向降级到 CPU4，再失败保持 Original。

7.2 播放控制

  • 底栏：播放、暂停、停止、上一条、下一条、时间轴（进度条 + 当前位置/时长）。
  • 鼠标拖动时间轴、方向键、Home/End 可执行受身份保护的绝对 seek。
  • 切换媒体源时短暂保留旧帧，加载失败不暴露播放器黑底。

8. 视频 / 声音处理

  • 视频处理和声音处理是两个独立开关，分别控制视频效果和普通声音效果。
  • 周期结果由系统自动/随机生成并只读展示，用户只编辑规则（周期范围、预设池等），不直接改本周期效果值。
  • 状态栏显示当前真实会话模式：GPU·GPU83 / CPU·CPU4 / 未处理·Original / 等待视频。
  • 视频周期低感知范围：亮度 ±0.1～0.35%、对比度/饱和度相对 100% 偏移 ±0.1～0.3%、色相 ±0.05～0.2°、锐化 0.1～0.4%（界面以两位小数显示）。
  • CPU4 只允许亮度、对比度、饱和度和色相。
  • 视频/声音/插话三条 0–100 周期进度在音频诊断卡底部显示。

9. 插话文件

  • 配置目录 + p01～p22 预设白名单（固定/随机选择、多轨 1～4、间隔、音量、duck 深度、attack/release）。
  • 默认：固定预设 p01、随机候选 p01～p20、插话间隔 8～13 秒、预设周期 8～15 秒、duck 深度 -60 dB、attack/release 50/250 ms。
  • 配置写入 %LocalAppData%\GpAutoLive\profiles\interlude\default.json（版本化 JSON + 原子写入）。
  • 重启读取 Enabled=true 且目录非空的配置后，后台有界扫描恢复候选快照，但不自动播放。
  • p01～p22 目前是「ID-only 选择合同」的最小消费边界，22 套完整 DSP 字段映射尚未接入。

10. 麦克风插话

  • 只在存在活动最终 PCM 总线时允许启用；媒体切换、媒体池编辑和停止播放前先停止麦克风。
  • 本地能量门控（RMS/VAD）判断说话/挂起，说话帧进入最终 PCM overlay，静音期间丢弃积压。
  • 当前未实现 AEC、降噪、AGC、完整 VAD——代码已接入 · 待真实设备验收。

11. 固定话术

  • 使用 Windows SAPI 本地语音朗读（SAPI.SpVoice），不调用模型、不经过 Go。
  • SAPI 输出捕获为 48kHz/16-bit PCM 送入最终 PCM 总线；没有活动总线时拒绝启动，不回退默认设备。
  • 单操作：新话术抢占旧话术，麦克风优先时拒绝新固定话术；启动确认预算 1500ms。
  • 当前真实 SAPI voice、声卡、RTMP-only 输出仍未验收。

12. RTMP / RTMPS 推流

12.1 配置与链路

输入 rtmp:// 或 rtmps:// 地址 → 配置校验 → 本机 H.264 编码器逐候选探测
        (h264_nvenc → h264_amf → h264_qsv → h264_mf → libopenh264)
        → 受管 FFmpeg 直接读取源媒体发布 H.264 + AAC FLV
  • 只接受 rtmp:// / rtmps://，拒绝反斜杠、凭据、片段、非法主机/端口；至少选择画面或声音一项。
  • 画面直接读取当前活动源，不捕获桌面/窗口；声音从最终 PCM 总线分流。
  • 视频帧率固定 25/30/50/60 FPS。
  • 编码器按 h264_nvenc → h264_amf → h264_qsv → h264_mf → libopenh264 单向降级。

12.2 重连与状态

  • 通过 -progress pipe:2 建立正向进度证据，出现正 out_time/total_size 才投影「推流中」。
  • 默认初次启动后最多 5 次重试，退避 1/2/4/8/15s；只有所选轨道都达到已发布状态才报告成功。
  • 切换媒体源会先停止活动推流，避免旧媒体身份继续发布。

13. 虚拟摄像头

  • 契约：GpAutoLive Camera、YUY2、1280×720、30fps、zero_copy=false。
  • 链路：WGC 捕获本应用最终效果窗口 HWND → D3D11 GPU 缩放/色彩转换 → 一次有界 GPU→CPU 回读 → AkVirtualCamera sidecar → DirectShow。
  • 只允许捕获本应用最终效果窗口，不扩展为桌面/第三方窗口采集。
  • 黑帧使用 Y=16/U=128/V=128（limited-range），避免全零被下游渲染成绿色。
  • 启动前执行 Authenticode 校验，未签名/无效 sidecar 拒绝启动。

当前状态：合同与状态机已接入，真实 WGC/D3D11/AkVirtualCamera sidecar/DirectShow 注册/签名/许可门禁未完成，界面显示「待验收」，不创建系统设备、不启动未签名 sidecar。

14. 抖音弹幕 M1

14.1 配置

  • 直播间号（纯数字或 https://live.douyin.com/<digits>）。
  • 回复池：1～100 条，每条最多 80 个 Unicode 字符 / 320 个 UTF-8 字节。
  • 队列容量：10～5000，默认 500。

14.2 行为

  • 只读取 WebcastChatMessage，从本地回复池随机选句，经有界队列串行发送。
  • 自回显、重连重放、重复消息 ID 入队前过滤；队列满丢最旧未发送项；任务 60 秒过期。
  • 未知发送结果不自动重试；accepted 不冒充本人回显。
  • 凭据只存内存，重启重新扫码；不调用模型、不经过 Go、不保持抖音登录。
  • 「实时弹幕」窗口显示最近 500 条昵称/正文/时间，支持置顶、清空、回到最新、手动单条发送。

当前状态：本地合同、队列与脱敏状态投影已接入；真实 QR 扫码、受管 Python sidecar、平台发送、自回显仍待验收。按钮是本地合同/状态演练入口，不是抖音可用连接。

15. 最终效果窗口

  • 单实例窗口；视频使用独立 mpv 视频子 HWND，声音使用黑底，窗口内不重复放置播放控制。
  • 首次显示按当前视频宽高比等比缩放到工作区内；拖拽边缘/角点时锁定视频宽高比；全屏期间不拦截系统尺寸。
  • 默认尺寸 1280×720、最小 320×180。

16. 设置（Ctrl+,）

  • 性能采样：启用后每秒更新标题栏 CPU/GPU/内存。
  • 启动时展开快速参数卡。
  • 下次输出入口：本地预览 / RTMP·RTMPS / 虚拟摄像头（只记住选择，不自动启动）。
  • 偏好只写入本机用户配置，不包含媒体文件、地址或凭据；Enter 保存、Esc 取消。
  • 当前版本固定深色主题与简体中文。

18. 声音优先级

固定优先级：麦克风插话 > 固定话术 > 插话文件 > 普通声音 / 原媒体。

麦克风开始说话时停止或数字静音低优先级声音；麦克风结束后不自动续播已被截断的插话文件或固定话术。

19. 关闭与退出

  • 退出顺序固定：关闭新任务门禁 → 取消计划 → 停止输出 → 回收子进程树 → Join 读取任务 → 释放窗口/音频/管道句柄 → 退出。
  • 退出后应无 GpAutoLive/mpv/ffmpeg/ffprobe 残留进程。
  • 窗口关闭异步 Join；先释放麦克风输入和门控观察器，再释放 mpv、PortAudio、RTMP 输出总线。

21. 常见问题

  1. 提示「媒体/输出资源已被占用」：同一用户已有另一个 C# 实例在运行，先关闭它再启动。
  2. 提示「设备未授权」：账号已登录但设备尚未通过服务端授权，点击重试设备授权；DEVICE_LIMIT_EXCEEDED 表示设备额度已满。
  3. RTMP 地址被拒：地址必须为 rtmp:// 或 rtmps://，不能含反斜杠、凭据或片段。
  4. 虚拟摄像头/抖音显示「待验收」：属正常状态，对应真实设备/网络/签名门禁尚未完成，不表示功能故障。
  5. 无法播放：确认媒体文件在支持扩展名白名单内，且 FFprobe 探测通过；纯音频项不会创建视频画面。
