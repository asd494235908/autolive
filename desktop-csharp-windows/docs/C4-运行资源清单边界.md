# C4 运行资源清单边界

## 目标

C# 客户端只把媒体大文件放在安装目录外置资源包中，主 `GpAutoLive.exe` 不嵌入 FFmpeg、FFprobe、mpv 或其 DLL。当前资源包的布局固定为：

```text
安装目录/
  GpAutoLive.exe
  runtime/media/<runtime_version>/manifest.json
  runtime/media/<runtime_version>/bin/ffprobe.exe
  runtime/media/<runtime_version>/bin/ffmpeg.exe
  runtime/media/<runtime_version>/bin/mpv.exe
  runtime/media/<runtime_version>/bin/<允许的共享 DLL>
```

用户数据目录只保存偏好、配置和日志，不作为媒体运行资源根目录。资源解析入口只接受绝对安装目录，并自行拼接 `runtime/media/<runtime_version>`；清单不能指定任意绝对路径或任意目录。

## 清单合同

`manifest.json` 使用 `schema_version = 1`，字段必须完整且不能出现未知字段：

```json
{
  "schema_version": 1,
  "runtime_version": "1.0.0",
  "platform": "windows",
  "architecture": "x64",
  "resources": [
    {
      "name": "ffprobe.exe",
      "relative_path": "bin/ffprobe.exe",
      "size_bytes": 123456,
      "sha256": "<64 位十六进制 SHA-256>"
    }
  ]
}
```

当前固定白名单为 `ffprobe.exe`、`ffmpeg.exe`、`mpv.exe`、可选 `portaudio_x64.dll`、`d3dcompiler_43.dll`、`avcodec-61.dll`、`avdevice-61.dll`、`avfilter-10.dll`、`avformat-61.dll`、`avutil-59.dll`、`swresample-5.dll`、`swscale-8.dll` 和 `libmpv-2.dll`。清单中的每一项都必须使用 `bin/<name>`，禁止 `..`、绝对路径、子目录和未登记文件名。更新原生资源版本时，应先更新白名单、许可证索引和发布矩阵，再生成新清单。

## 校验与状态

`RuntimeMediaManifestBoundary` 按以下顺序执行有界校验：

1. 限制清单为 1 MiB、资源项最多 64 个、单文件最多 512 MiB、总资源最多 2 GiB。
2. 使用 `System.Text.Json` 严格反序列化；未知字段、重复字段、缺失字段、版本/平台/架构不匹配均 fail-closed。
3. 校验安装目录为绝对路径，并将所有资源锚定在安装目录下的固定版本 `bin` 目录；安装目录、版本目录和 `bin` 目录出现重解析点时拒绝加载。
4. 逐项检查普通文件、声明大小和 SHA-256；任一项失败都返回脱敏错误且不发布部分结果。
5. 全部成功后才生成不可变 `VerifiedMediaRuntime` 快照。只有该快照可以创建 `FfprobeMediaProbe`；创建探测器本身不启动外部进程，真正探测仍由后续注入的进程执行器负责。

错误只返回稳定分类和用户可展示的短消息，不包含安装路径、资源文件名、哈希正文、命令行、异常正文或 FFprobe 输出。验证过程支持取消，取消也不会发布部分资源快照。

## 依赖方向

```text
GpAutoLive.Contracts
          ↑
GpAutoLive.Core.Processes
          ↑
GpAutoLive.Media (清单/哈希/FFprobe 资源入口)
          ↑
GpAutoLive.App
```

清单 DTO 属于 Media 的运行时边界，使用标准库和现有 `ContractJson`，不复制 `desktop/` 中的 Rust/Tauri 文件，也不新增第三方依赖；Media 不反向依赖 Windows，避免循环引用。

## 未完成与禁止宣称

- 当前不复制媒体二进制到仓库或主 EXE；普通自动化测试不启动媒体进程，显式 `WindowsMpvRealFixtureTests` 仅在用户提供外置资源、短视频和 HWND 时启动真实 mpv，并且只保留脱敏状态结果。
- 当前 SHA-256 校验是完整性和资源目录边界，不等同于发布签名、证书链或供应链证明；签名校验仍是后续发布门禁。
- 当前外部进程边界已使用受限的 Windows `Process` 和最小 Job Object 创建/分配/终止增强；不可用时安全回退，不能宣称真实媒体长生命周期孤儿进程已完成 Job Object 兜底验收。
- 当前 FFprobe 资源只完成“已验证路径 → 探测器对象”的组合入口；真实 mpv HWND、GPU83/CPU4、PortAudio、seek/EOF/换源和 Windows 实机长稳仍待后续阶段。

## 本地 staging 入口

`tools/stage-media-runtime.ps1` 只接受显式的 mpv/FFmpeg 来源目录和目标安装目录，PortAudio 通过可选 `-PortAudioRoot` 显式加入；先在同一安装目录下生成临时版本，再原子移动到 `runtime/media/<version>/`；清单记录固定资源名、大小和 SHA-256，许可证材料放在同版本 `legal/` 目录但不参与运行时命令行。示例：

```powershell
powershell -NoProfile -File .\tools\stage-media-runtime.ps1 `
  -MpvRoot ..\desktop\third_party\mpv\x86_64-pc-windows-msvc `
  -FfmpegRoot ..\desktop\third_party\ffmpeg\x86_64-pc-windows-msvc `
  -PortAudioRoot ..\desktop\src-tauri\portaudio `
  -InstallRoot .\artifacts\csharp-windows-install `
  -RuntimeVersion 1.0.0
```

该脚本不会修改 `desktop/`；正式发布仍需额外完成来源锁定、许可证复核、签名和跨机器验收。

本地验证记录（2026-09-02）：v8 从只读参考目录完成 staging 到 `artifacts/csharp-windows-controller-20260902-v8/runtime/media/1.0.0/`，生成 4 项资源（`mpv.exe`、`ffmpeg.exe`、`ffprobe.exe`、`d3dcompiler_43.dll`），资源合计 351,999,432 bytes，清单大小 1,462 bytes；包含法律材料的 staging 树合计 352,053,564 bytes。`mpv --version` 与 `ffprobe -version` 均可启动。该目录是本地验收产物，不属于主 EXE，也不代表签名或真实播放链路已通过。

v16 本地验证（2026-09-02）：通过 `-PortAudioRoot ..\desktop\src-tauri\portaudio` 显式加入 `portaudio_x64.dll`，共 5 项资源，清单 SHA-256 全部匹配；发布根目录 15 个文件、1,140,822 bytes，媒体 staging 树 352,365,694 bytes。PortAudio 动态加载冒烟成功并枚举 32 个本机设备，未启动长期播放流；该结果不代表 PortAudio 输出/设备恢复或签名门禁已通过。

v43 本地验证（2026-09-03）：正式安装候选把 PDB/XML 移入独立 symbols 包，主安装根目录 8 个运行文件、1,027,815 bytes；同一 5 项媒体资源清单 SHA-256 全部匹配，真实 mpv `Original/Cpu4/Gpu83` 夹具均通过正 `time-pos` 与 EOF。签名、跨机器来源锁定和目标 GPU 矩阵仍待发布门禁。
