# C4 外部进程执行边界

## 目标

为 FFprobe、FFmpeg、mpv 和后续 Windows sidecar 提供一个统一的本机进程生命周期边界：参数不经过 Shell，标准输出/错误有界，任务可取消，超时和取消时不遗留子进程树，执行失败不被伪装成媒体成功。

## 依赖方向

进程合同是执行层的最小数据类型，不属于媒体实现，也不属于 Windows P/Invoke：

```text
GpAutoLive.Contracts
          ↑
GpAutoLive.Core.Processes  ←  GpAutoLive.Windows.WindowsExternalProcessRunner
          ↑
   GpAutoLive.Media
          ↑
      GpAutoLive.App（组合根）
```

- `GpAutoLive.Core.Processes`：`ExternalProcessPlan`、`ExternalProcessResult`、`ExternalProcessRunStatus`、`ProcessLaunchPolicy` 和 `IExternalProcessRunner`。
- `GpAutoLive.Media`：构造 `FfprobeCommandPlan`，通过 `ToExternalProcessPlan()` 转换为通用合同；不引用 `GpAutoLive.Windows`。
- `GpAutoLive.Windows`：实现通用 `System.Diagnostics.Process` 适配器，并由 `WindowsMpvProcessHost` 消费 Media 的受信启动计划；只在 Windows 组合根使用 Media 类型，不让 Core 反向依赖具体播放器。
- `GpAutoLive.App`：未来在组合根注入 Windows runner：`new FfprobeMediaProbe(ffprobePath, new WindowsExternalProcessRunner())`。

## 已实现的安全边界

`WindowsExternalProcessRunner` 当前执行以下固定策略：

1. 仅在 Windows 运行；执行文件必须为绝对路径，参数通过 `ProcessStartInfo.ArgumentList` 逐项传入。
2. 强制 `UseShellExecute=false`、`CreateNoWindow=true`、stdout/stderr 重定向和超时/取消时的进程树清理；不接受不安全启动策略。
3. stdout 和 stderr 并发异步读取，按字节分别限制；超过上限立即取消等待并终止进程树，避免死锁和无界内存。
4. 超时、调用方取消、stdout 上限、stderr 上限、启动失败和输出读取失败映射为稳定状态；返回结果不包含异常正文、命令行或路径诊断。
5. 进程启动前尝试创建 `WindowsJobObject`，设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，启动后立即分配根进程；超时/取消优先调用 `TerminateJobObject`，随后仍执行 .NET 的 `Process.Kill(entireProcessTree: true)` 兜底，并以 2 秒窗口等待进程和读取任务退出。
6. Job Object 句柄由 `SafeFileHandle` 独占，创建、分配或终止失败只返回稳定失败状态并回到既有 `Process` 清理路径；资源由 `using` 对称释放。

`WindowsMpvProcessHost` 使用同一 Job Object 边界承载长生命周期 mpv：它不重用通用 FFprobe 双流读取路径，而是关闭 stdout/stderr 重定向、固定工作目录、仅接收不可变 `MpvLaunchPlan`，并单独提供启动、退出事件、取消和有界停止状态。`WindowsMpvPlaybackRuntime` 再把该宿主与命名管道、会话身份按固定顺序组合，避免 UI 直接管理进程句柄。

## Job Object 状态

`WindowsJobObject` 已作为最小 Windows 增强边界接入 `WindowsExternalProcessRunner`：仅在 Windows 调用 `CreateJobObjectW`、`SetInformationJobObject`、`AssignProcessToJobObject` 和 `TerminateJobObject`，不向 Core/Media 泄露 P/Invoke。Job Object 创建或分配受宿主嵌套 Job、权限和系统策略影响，因此不可用时按设计回退到既有 `Process.Kill(entireProcessTree: true)`，不把回退路径标记为 Job Object 已生效。

当前状态为“代码已接入·自动化覆盖·真实媒体待验收”：已覆盖创建/分配/终止成功路径、已释放对象拒绝新操作，以及 Job Object 不可用时的安全回退分支；尚未用真实 mpv、FFmpeg 或 Python sidecar 完成长生命周期孤儿进程、嵌套 Job、权限拒绝和退出门禁实机矩阵。

## 测试与未接入项

`GpAutoLive.Windows.Tests` 使用 Windows 自带 `cmd.exe` 验证：双流读取、Shell 策略拒绝、超时进程树清理、取消进程树清理、stdout/stderr 输出上限、缺失执行文件的脱敏失败，以及 Job Object 创建/分配/终止和释放后的拒绝操作。测试不会调用 FFprobe，也不会将媒体运行资源复制进主 EXE。

当前仍未完成：发布签名/证书链校验、正式 mpv 首帧/连续播放与目标 GPU 矩阵、PortAudio 真实设备拔插/睡眠唤醒门禁、长生命周期 sidecar 监督，以及 Job Object 在真实媒体进程上的孤儿进程和嵌套 Job 矩阵验收。App 组合根已按需调用资源清单校验并创建已验证 FFprobe 探测器；显式真实 mpv 夹具已证明单机命名管道播放时间与 EOF，资源清单、安装目录锚定、固定资源白名单、大小/SHA-256 校验见 [`C4 运行资源清单边界`](./C4-运行资源清单边界.md)。
