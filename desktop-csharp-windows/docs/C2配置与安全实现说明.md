# Phase C2 配置与安全边界实现说明

状态：配置/凭据边界与控制面编排已接入·待真实控制面联调

本阶段只在 `desktop-csharp-windows/` 内实现配置与敏感信息边界；现有 `desktop/` Rust/Tauri/React 目录保持只读。

## 文件职责

- `GpAutoLive.Core/Configuration/IniUserPreferencesStore.cs`
  - 仅保存窗口尺寸/位置、主题、语言、面板展开状态、性能采样开关和最近非敏感输出模式。
  - section/key 白名单、重复键拒绝、类型/范围/版本校验。
  - 同目录临时文件、Flush、同卷替换；读写均有文件大小上限。
- `GpAutoLive.Core/Configuration/VersionedJsonDocument.cs`
  - 结构化配置统一使用 `{ "schema_version": 1, "data": ... }`。
  - `System.Text.Json` 严格拒绝未知字段和未知版本；文件原子替换且有大小上限。
  - 写入前拒绝包含 password/token/secret/cookie/credential/api_key/authorization/rtmp_url/target_url 等敏感字段名的 DTO。
- `GpAutoLive.Core/Security/ISecretStore.cs`
  - 只定义最小安全存储边界；秘密以字节和可清零 `SecretBuffer` 传递，禁止建模为普通配置字符串。
- `GpAutoLive.Windows/Security/CredentialManagerSecretStore.cs`
  - 使用当前 Windows 用户的 Credential Manager generic credential，目标名带应用前缀并做长度/字符白名单校验。
  - 不把凭据正文写入日志、JSON、INI 或异常消息。
- `GpAutoLive.Windows/Security/DpapiSecretProtector.cs`
  - 提供当前 Windows 用户范围的 DPAPI 保护/解保护最小边界；输出仍不得直接放入普通配置而绕过访问控制。
- `GpAutoLive.Windows/WindowsDeviceIdentity.cs`
  - 只生成随机 `desktop-<GUID>` 设备标识并存入 Credential Manager；不采集硬件序列号等高敏感设备指纹。
- `GpAutoLive.Windows/ControlPlaneAuthCoordinator.cs`
  - 作为认证唯一所有者串行执行登录、冷启动恢复、自动激活、Refresh、心跳和 Logout，并按状态机结果执行 Refresh Token 凭据动作。
- `GpAutoLive.Windows/ControlPlaneHeartbeatScheduler.cs` 与 `GpAutoLive.Core/Configuration/HeartbeatOutboxStore.cs`
  - 只在 `Activated`/已授权 `Offline` 状态运行一个 30 秒后台任务；发送串行化，停止时取消并 Join。暂态失败最多保存一条无凭据心跳 outbox，账号/设备不匹配、过期或损坏项安全丢弃。
- `GpAutoLive.App/Features/Auth/LoginViewModel.cs` 与 `MainWindow.xaml.cs`
  - 显式设置 `AUTOLIVE_CONTROL_PLANE_BASE_URI` 后才启用控制面；默认启动不创建网络客户端，避免未配置环境产生隐式流量。

## 当前限制

- 已连接桌面专用登录/Refresh/Logout、激活和心跳路径的严格 HTTP 传输，并接入 WPF 登录按钮、会话状态机、Credential Manager 凭据动作和随机设备标识；待真实控制面联调。
- 重启恢复与后台心跳已接入最小可注入边界：缺少 Refresh Token 不触网；无效/过期/被拒绝恢复 fail-closed 并清理凭据；心跳周期为 30 秒。真实服务端、TLS、Credential Manager 权限、禁用响应及 Windows 实机长稳仍未验收。
- 配置迁移目前 fail-closed（只接受当前版本），迁移函数在引入旧版本真实数据后单独添加并测试。
- Credential Manager 与 DPAPI 仅在 Windows 目标框架下构建和实机测试，不提供 macOS 路径。
