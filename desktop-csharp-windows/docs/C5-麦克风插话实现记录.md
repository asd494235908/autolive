# C# Windows 麦克风插话实现记录

更新时间：2026-09-06

## 本轮接入

- WindowsMicrophoneInterludeController 继续拥有 PortAudio 输入流、能量门控和优先级通知。
- 新增 WindowsMicrophonePcmBridge：说话/挂起期间从固定容量输入环缓读取有限帧，单声道输入按活动最终 PCM 总线的 1/2 声道要求发布到 overlay；静音期间丢弃积压，避免旧帧泄漏。
- 主窗口只在存在未关闭的活动最终 PCM 总线时允许启用麦克风；媒体切换、媒体池编辑和停止播放前先停止麦克风，避免总线被关闭后继续持有输入流。
- 主窗口关闭时先释放麦克风输入和门控观察器，再释放 mpv、PortAudio 和 RTMP 输出总线，避免输入观察器在输出总线关闭后才进入失败路径。
- 固定话术、麦克风和插话文件共享最终 PCM overlay，但混音策略只静音/duck 基础轨，不再把 overlay 自身错误静音。
- 最终 PCM 总线消失、关闭或发布失败时，麦克风会进入 OutputBusUnavailable 可重试失败态并释放输入流。

## 明确未完成

- 本轮只打通 C# 的本地麦克风帧到最终 PCM 的基础可听桥接，没有宣称完成 Rust 侧的 SpeexDSP AEC、降噪、AGC 或完整 VAD。
- 2026-09-06 插话预设消费收口只作用于文件插话的 FFmpeg 单轨解码计划；麦克风仍直接进入既有最终 PCM overlay，不读取、不复用也不扩展 p01～p22 预设字段。
- 尚未通过真实麦克风、声卡、回声参考、拔插恢复和长稳门禁；这些仍是“代码已接入·待验收”。
- 不启动 ASR、LLM、TTS，不保存或上传麦克风 PCM。
