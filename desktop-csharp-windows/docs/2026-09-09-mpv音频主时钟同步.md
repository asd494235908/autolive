# mpv 音频主时钟同步

本项负责 C# Media/Windows 视频纠偏入口；App 的首次播放与换源编排、音频时钟发布和 RTMP 属于各自链路。

`WindowsMpvPlaybackController.SynchronizeAudioClockAsync` 复用既有 controller 串行操作、活动媒体四维身份与受限 mpv IPC。调用者只提交同一观察轮的源内视频 PTS、有效可听音频 PTS 和当前真实音轨倍速，不使用跨循环累计 PTS 或尚未生效的配置倍速。

- 漂移绝对值不超过 40ms：恢复音频基础倍速。
- 漂移 40～500ms：以音频倍速为基础，按2秒收敛比例温和调速，上限 ±5%，不 seek；双文件实测表明原±2%对TS开启处理后的启动漂移恢复过慢。
- 漂移超过 500ms：恢复基础倍速并精确 seek 到音频源内 PTS。
- 暂停/Ready 不执行同步，旧身份、无效倍速及越界时钟不派发命令。
- 每次 `loadfile replace` 显式设置 `speed=1`，避免处理音轨倍速遗留到下个无音轨视频。没有新线程、队列、缓存或自动重启分支。

新增 `MpvAudioClockSynchronizationTests` 覆盖两种偏移方向、实际倍速、严重漂移、暂停、旧身份、无效输入及换源速度复位；`WindowsMpvPlaybackControllerTests` 覆盖运行时与取消边界。

验证：最初通过 PATH 执行 `dotnet test ... --filter FullyQualifiedName~MpvAudioClockSynchronizationTests --no-restore` 因系统无 SDK 退出，尚未执行测试。由主线程协调专用 SDK 下的定向构建和测试，最终结果以本轮总记录为准。未执行全量测试、完整发布构建、媒体实播、容器或外部服务验收，不能据纯逻辑通过声称实机无卡顿。

消融检查：使用现有会话 partial 文件承载纯逻辑，复用既有串行 IPC；未增加策略接口、独立状态机、调度任务或新依赖。保留必要身份、时钟范围及取消边界。新代码均有当前调用或测试覆盖，未删除既有代码。

## 同源显式 seek 的真实完成边界（2026-09-10）

TS 实机在用户跳转 18 秒后立即读取 video=18788ms、audio=18013ms，原 `SeekAsync` 在 IPC ACK 后即返回，不能证明新定位已完成。命令已经使用 `absolute+exact`；随后独立mpv探针确认还有TS解复用定位偏移，最终统一启动计划增加 `--hr-seek-demuxer-offset=2`，由mpv从目标前预读并精确解码至目标，不修改TS起点、音频坐标或同步阈值。0/1秒补偿实测落18.741秒，2/5秒落18.014秒，取已验证的较小值。完整记录见[用户双视频实测](./2026-09-09-用户双视频实测.md)。

`MpvNamedPipeClient` 在现有事件消费处增加单调 `PlaybackRestartSequence`；原 `RestartedGeneration` 只代表文件代际，不能区分同一文件的连续 seek，仍保留给换源首帧门禁使用。显式 `SeekAsync` 在原 controller 串行锁中先做一次属性读取排空旧事件，再记录序列、发送 seek；复用原 2 秒下一帧观察预算，只有新的 restart 序列且 `seeking=false` 才返回成功。已知目标位于媒体末端时，也允许 `seeking=false` 与真实 `eof-reached=true` 完成，避免等待不存在的 restart。超时返回未观察到完成，取消沿原取消分类；不把 ACK 写成完成。

仅显式 `SeekAsync` 开启该观察；日常音频时钟纠偏保持原派发路径，普通调速幅度按后续TS实测调整为上述±5%。运行时监视器仍通过同一个 IPC 所有者读取，其消费到的事件更新同一序列，没有增加读取线程、worker、队列或生产测试配置。

新增命名管道定向回归先于产品改动编写，覆盖旧 `seeking=false`/旧 restart、当前 restart 后仍 seeking、并发状态监视、成功、取消、超时及末端 EOF。原 IPC 测试增加同文件连续 restart 序列断言。主任务已执行：控制器定向11项通过，Media模块162项通过，Windows模块371项通过/1项跳过，App模块192项通过/14项跳过；TS/MP4同步恢复与跳转各2项通过，本地App Release构建0警告0错误。其余双文件切换结果以[用户双视频实测](./2026-09-09-用户双视频实测.md)为准。依据：[mpv 官方事件及精确定位说明](https://mpv.io/manual/stable/)。

正在进行消融实验。保留一个必要的事件序列与现有有界观察循环；没有新策略接口、配置、队列或时间戳推算。旧首帧代际、身份、取消和 EOF 边界继续保留。
