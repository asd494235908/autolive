# C6 性能采样边界

日期：2026-09-03  
状态：代码已接入·已具备本地基线采集，性能门禁未验收

## 1. 目标与非目标

本增量只建立 Windows C# 客户端的最小性能快照边界，用于后续基线工具和实机对照。每次快照包含当前进程的私有工作集、工作集、线程数、句柄数、可选 GDI/User 对象计数、可选 Gen0/Gen1/Gen2 GC 回收计数和可选 CPU 百分比，不包含 PID、进程路径、命令行、用户名、主机名、媒体路径、凭据或网络数据。

本增量不把一次采样或一次启动冒烟写成“性能达标”；采集脚本允许按用户指定路径输出 JSON，WPF 只做 1Hz 标题栏投影，不上传控制面，不测 GPU、mpv、FFmpeg、PortAudio 或外部 sidecar。

## 2. 实现边界

- `WindowsCurrentProcessPerformanceSource` 使用 Windows `System.Diagnostics.Process` 读取当前进程计数器；非 Windows 明确返回不可用。
- `WindowsProcessPerformanceSampler` 每次只读取一次源，调用方负责调度，建议不高于 2Hz；不存在无限循环或无限队列。
- CPU 使用相邻采样的 `TotalProcessorTime` 和单调时钟计算，首个样本返回 `Warmup`；缺少 CPU 计数器、间隔非正或间隔超过 5 分钟时返回 `Unavailable`。
- 内存指标上限为 1 PiB，线程/句柄上限为 1,000,000；不符合范围的源数据返回 `Invalid`，不会生成快照。
- GDI/User 对象通过 Windows `GetGuiResources` 读取；权限或系统 API 不可用时保留为 `null`，有效值上限为 1,000,000，不因可选指标缺失而伪造 0。
- Gen0/Gen1/Gen2 通过当前 .NET 进程的 `GC.CollectionCount` 读取；计数为非负整数，异常或运行时不支持时保留为 `null`，不会把 GC 次数推算为内存或 CPU 指标。
- `CancellationToken` 在读取前后检查；已取消请求不访问采样源。源异常只映射为固定的 `Unavailable` 状态，不返回异常正文，避免敏感信息进入 UI/日志。
- CPU 百分比按逻辑处理器数归一并限制到 0～100；这是采样估计值，不是性能门禁结论。
- `tools/collect-process-baseline.ps1` 提供 Windows 本地基线采集：启动指定 framework-dependent EXE，暖机后按固定间隔采集趋势，输出版本化 JSON；运行时根目录可显式传入，不搜索 PATH。脚本记录 GDI/User 对象计数及最小/最大值；GC 计数只在应用内快照中提供，脚本不通过不稳定的跨进程性能计数器伪造 GC 字段。
- 采集脚本只输出 EXE 文件名、平台、采样参数和进程计数器，不写 PID、路径、命令行、用户名、主机名、媒体正文或凭据；退出优先 `CloseMainWindow`，超时才按进程树终止。

## 3. 测试与验收

测试通过注入 `IWindowsProcessPerformanceSource` 覆盖首样本、取消、无效范围、GDI/User/GC 无效范围、源不可用和 CPU 归一化；采集脚本已用 v67 EXE 做 5 秒本机冒烟，生成 4 个样本，状态为 `completed`，GDI 对象 5～17、User 对象 21～40。真实 Windows 源只读取当前进程，不以路径或 PID 作为输出；应用内 GC 字段由同一采样器返回。后续仍需在同一 Windows 机器、同一构建和同一素材上记录冷/热启动、私有工作集、CPU、句柄、线程、GDI/User、GC 和 30 分钟趋势，并与 Rust/Tauri 基线对照；在完成这些测量前，不得宣称计划中的性能指标已经达标。
