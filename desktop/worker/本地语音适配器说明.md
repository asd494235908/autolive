# 本地固定话术热替换适配器

这个目录提供本地 CPU 固定话术热替换 Worker 适配器，不是服务端，也不上传视频，不生成 MP4。

它和实时 speech-to-speech、普通声音处理是三条不同链路：

- 固定话术热替换：只在当前播放轮次内替换当前话术片段的基础音轨。
- 实时 speech-to-speech：保留在另一条受控实时流链路里。
- 普通声音处理：只负责独立的音频效果，不负责话术替换。

## 准备步骤

先创建单独的 Python 环境并安装这个 Worker 的依赖：

```bash
python3 -m venv .venv-voice-clone
. .venv-voice-clone/bin/activate
python3 -m pip install -r desktop/worker/requirements-voice-clone.txt
```

然后把桌面端指向本地 Worker 的绝对路径：

```bash
chmod +x desktop/worker/voice_clone_adapter.py
export AUTOLIVE_VOICE_CLONE_WORKER="$PWD/desktop/worker/voice_clone_adapter.py"
```

如果本机没有把 FFmpeg / FFprobe 放进 `PATH`，再显式指定它们的绝对路径：

```bash
export AUTOLIVE_FFMPEG_PATH="/abs/path/to/ffmpeg"
export AUTOLIVE_FFPROBE_PATH="/abs/path/to/ffprobe"
```

`AUTOLIVE_VOICE_CLONE_WORKER` 必须是绝对路径且文件可执行；桌面端会先做能力探测，再决定是否启用这条链路。

## 依赖和模型

`requirements-voice-clone.txt` 只列出这条链路实际用到的 Python 依赖：Demucs、faster-whisper 和 Coqui TTS。

当前适配器是 CPU-only：

- Demucs 走 CPU。
- faster-whisper 使用 `device="cpu"`、`compute_type="int8"`。
- XTTS-v2 使用 `gpu=False`。
- 不声明也不需要 NVIDIA / CUDA。

开发版可以使用本地模型缓存；正式版不会在用户电脑上下载模型，模型会在发布者构建安装包时准备并随安装包交付。模型通常包括：

- Demucs 的分离模型；
- faster-whisper 的 Whisper 模型；
- XTTS-v2 的 TTS 模型。

这些模型的下载会占用网络和磁盘，并受各自上游许可证、模型卡和服务条款约束。正式分发或商用前，必须单独确认对应模型的许可边界；XTTS-v2 也需要单独复核。模型权重不提交 Git，正式安装包按构建命令校验通过后随包交付。

可以用 `AUTOLIVE_VOICE_CLONE_MODEL_ROOT` 把三套模型放进指定的隔离缓存目录；Worker 会自动设置 Hugging Face、Torch 和 Coqui TTS 的缓存路径。Worker 自己的音频产物仍由桌面端统一管理在应用缓存目录下的 `voice-clone/` 目录里。

正式打包时，`pnpm --dir desktop/ui run tauri:build` 会自动依次准备 FFmpeg、固定话术 Worker 和三套 CPU 模型，再校验并复制到安装包的 `voice-models/`、`voice-worker/` resources。任一资源下载、打包或校验失败，构建会失败，不生成半成品安装包；模型权重不提交仓库。正式安装包如果缺少资源，会明确提示重新安装完整版本，不会要求用户执行命令，也不会偷偷联网下载。

XTTS-v2 首次下载会由 Coqui TTS 要求确认其商业许可或非商业 CPML 条款。构建脚本不会替发布者作出法律确认；发布者完成确认后，在构建环境中设置 `AUTOLIVE_COQUI_TOS_AGREE=yes`，再执行 `pnpm --dir desktop/ui run tauri:build`。这一步只发生在发布者构建阶段，最终用户不需要确认或下载模型。构建固定话术 Worker 前还需要在发布环境安装 `desktop/worker/requirements-voice-clone-build.txt`。CI 发布任务使用同名的仓库变量 `AUTOLIVE_COQUI_TOS_AGREE`，未确认时会直接阻止生成安装包。

## 当前行为

适配器只做本地编排：

- 读取当前源 MP4；
- 提取本地音频；
- 做人声分离和话术索引；
- 用参考音色生成当前话术替换音轨；
- 把结果写到本地缓存。

“准备人声”会一次完成参考音频、Demucs、Whisper 和 XTTS-v2 的准备；如果 XTTS-v2 尚未就绪，准备操作会失败并保留明确原因，不会等到点击替换时才首次暴露模型问题。如果普通声音处理已开启，必须先在当前视频上应用并提交处理结果；固定话术替换会以当前已处理视频的音频为基底，只替换当前话术片段。实时音频占用时，固定替换按钮会保持不可用。

它不会：

- 生成 N 个 MP4；
- 新开第二个窗口；
- 改写原始源视频；
- 把失败伪装成成功。

当能力不完整时，桌面端会把这条链路保持为不可用，继续当前窗口原声播放，不影响视频循环、下一轮恢复和其他开关。

## 失败和回退

这条链路遇到以下情况时都应该保持原播放：

- Python 依赖缺失；
- `AUTOLIVE_VOICE_CLONE_WORKER` 未设置、不是绝对路径，或者脚本不存在；
- FFmpeg / FFprobe 不可用；
- 模型还没下载完成，或者上游下载失败；
- 本地 CPU 资源不够，或者 Worker 运行失败。

当前话术替换只影响本轮播放：替换片段结束后，源音频继续；进入下一轮后恢复原始音轨。
