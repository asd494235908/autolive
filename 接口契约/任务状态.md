# 播放状态与实时音频状态契约

当前产品不创建离线媒体任务，不计算版本数量，不生成多个 MP4，也不维护视频版本队列。本文件只定义 `.mp4`、`.mov`、`.mkv`、`.avi`、`.webm`、`.m4v`、`.ts`、`.m2ts`、`.flv`、`.wmv`、`.3gp` 单源视频在同一窗口内循环播放，以及实时话术幻化对当前音轨的处理状态。

## 1. 播放状态

| 状态 | 含义 |
| --- | --- |
| `ready` | 已登录并激活，可以选择本地源视频 |
| `loading` | 正在探测源视频或读取元数据；需要完整哈希的处理/研究提交按对应阶段计算 |
| `playing` | 当前源视频正在同一窗口播放 |
| `paused` | 当前播放已暂停 |
| `stopped` | 当前播放已停止，但源视频和参数仍保留 |
| `offline_playing` | 控制面暂时断开，但本地播放继续 |
| `error` | 源视频不可读、媒体引擎不可用或播放发生不可恢复错误 |

`disabled` 属于控制面授权状态，不属于 `PlaybackState`。用户或设备被禁用时，客户端停止受保护的模型/后台操作；已打开的本地播放是否停止由产品授权策略单独决定。

播放结束时，播放器在同一窗口将当前源视频定位到 `0` 秒并递增 `loop_index`，再次进入 `playing`。这不是切换视频版本，也不创建第二个窗口。

```json
  "video_processing_status": "disabled",

  "realtime_audio_variant_enabled": true,

  "audio_processing_gain_db": 0,

  "updated_at": "2026-08-13T12:00:00Z"

```

约束：

- `source_media.mp4_sha256` 只在源文件实际为 MP4 且进入对应哈希链路时记录整个 MP4 文件字节流 SHA-256；当前导入探测默认保持 `disabled`。非 MP4 源文件不得写入该字段。
- `current_mp4_sha256` 是当前画面产物的整个 MP4 文件 SHA-256；如果只发生实时音频换轨且没有重新生成 MP4，则保持画面产物哈希不变，并单独记录 `current_audio_sha256`。
- `current_video_reference` 是当前窗口正在播放的源视频或处理缓存；`pending_video_reference` 是后台处理完成、等待下一轮循环边界提交的缓存。二者不能在播放中途强制替换。
- 三个开关互相独立：视频处理、声音处理和实时话术幻化不能隐式开启或关闭其他开关。
- 源视频不可读或媒体引擎不可用时，必须返回结构化错误，不返回伪造的播放成功；若处理或研究阶段启用了完整哈希，哈希失败不停止已开始的本地原声播放，但必须阻止对应阶段提交并显示错误。

视频/普通声音处理状态：`disabled`、`processing`、`ready`、`runtime`、`failed`、`unavailable`。`runtime` 仅表示普通声音处理作用于最终效果窗口的当前音轨，目前只覆盖已实现的增益/响度路径；未接入运行时 DSP 的高级参数必须显示 `unavailable`，不得静默跳过。处理 Worker 成功后先进入 `ready` 和待切换槽；`complete_playback_loop` 在视频结束时提交缓存并递增 `loop_index`。取消、超时或失败时保持当前可用视频，不覆盖源文件。

## 3. 实时音频状态

| 状态 | 含义 |
| --- | --- |
| `disabled` | 实时话术幻化开关关闭，不启动 Worker |
| `idle` | 已开启，等待当前音频片段 |
| `capturing` | 正在从文件或受控实时流读取音频 |
| `processing` | speech-to-speech Worker 正在执行 VAD/ASR/LLM/TTS |
| `candidate_ready` | 候选音轨已生成并暂存，等待同步和安全门禁提交 |
| `switched` | 候选通过门禁，已替换当前播放音轨 |
| `fallback` | 候选失败、超时或不安全，继续使用上一条可用音轨 |
| `error` | Worker 或模型发生需要用户处理的错误 |

实时链路固定为：

```text
文件/受控实时流
    ↓
speech-to-speech Worker（VAD → ASR → LLM → TTS）
    ↓
LLM 决策：沿用当前内容 / 改写当前内容
    ↓
音频候选
    ↓
采样率、声道、时长、延迟、完整哈希和播放代际门禁
    ├─ 通过：替换当前基础音轨，再按声音处理开关输出最终音轨
    └─ 失败：保持上一条可用音轨并记录回退原因
```

LLM 不能及时完成时，视频和上一条可用音轨继续播放。实时幻化不暂停视频、不静音、不切换空媒体源、不重新弹窗。

## 4. 开关与状态转换

```text
ready
  └─ 导入源视频 → loading → playing
                              ├─ 播放结束 → playing（loop_index + 1）
                              ├─ 暂停 → paused → 继续 → playing
                              ├─ 停止 → stopped
                              └─ 错误 → error → 重试或回退
```

实时话术幻化是播放状态的独立子状态，不改变主播放状态：

```text
disabled → idle → capturing → processing → candidate_ready → switched
                                      └──────────────────────→ fallback
```

关闭开关时，停止新的实时候选生成；已在生成中的 Worker 按取消协议终止并回收资源，当前视频继续播放。

## 5. 研究分析状态

研究分析是本地独立入口，不参与实时播放决策：

状态枚举：`idle`、`unavailable`、`running`、`ready`、`failed`、`cancelled`。

- 输入：已探测的受支持源视频或当前产物、参数快照和随机种子；当前研究 Worker 的阶段产物契约仍以 MP4 为主。
- 输出：内容相似度分析、媒体鲁棒性实验、隐形标记研究、随机扰动实验和内容指纹对比报告。
- 每个实验阶段开始前计算输入文件完整 SHA-256，完成后计算输出文件完整 SHA-256。
- 研究报告必须标明算法版本、配置值、测量值、实际生效值和失败原因。
- 状态摘要必须区分通用源/产物完整哈希与条件 MP4 专用哈希；只有实际为 MP4 时才保存 `source_mp4_sha256`、`input_mp4_sha256`、`current_mp4_sha256`，同时保存 `report_sha256`、算法版本、随机种子和报告路径；不允许用阶段输入哈希冒充原始哈希。

## 6. 管理端可见摘要

后台只展示控制面和设备摘要，不接收或处理视频文件：

- 用户、设备、激活状态
- 当前源视频名称、播放状态和播放轮次
- 三个处理开关
- 实时音频 Worker 状态、当前音频来源、延迟和回退原因
- 模型租约、请求状态和用量摘要

后台不展示版本数量、版本进度、离线合成任务或多视频队列。
