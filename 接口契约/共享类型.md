# 共享类型

本文件定义 Go 后端、React 管理端、Rust/Tauri 客户端必须保持一致的核心字段、命名和单位。

目标：

- 避免同一业务概念出现多套字段名
- 避免裸整数混淆毫秒、秒、Hz、字节和数量
- 为 OpenAPI 代码生成、手写 DTO 和本地状态持久化提供统一字典

## 1. 命名总原则

- JSON 字段统一使用 `snake_case`
- ID 字段统一命名为 `{resource}_id` 或直接 `id`
- 时间戳统一使用 RFC 3339 UTC 字符串
- 哈希统一使用小写十六进制字符串

## 2. 核心类型

| 类型名 | 说明 | 关键字段 |
| --- | --- | --- |
| `UserSummary` | 当前用户或管理端列表最小用户摘要 | `id` `username` `role` `status` |
| `DeviceSummary` | 客户端设备最小摘要 | `id` `user_id` `device_name` `platform` `app_version` `status` |
| `SourceMedia` | 受支持源视频元数据、受控本地路径与条件哈希 | `source_path` `file_name` `file_size_bytes` `duration_ms` `width` `height` `frame_rate_fps` `audio_sample_rate_hz?` `audio_channel_count?` `mp4_sha256?` `mp4_hash_status` |
| `PlaybackSnapshot` | 当前单源播放状态 | `source_media` `loop_index` `playback_state` `current_video_source` `current_video_reference` `current_video_sha256` `pending_video_reference` `pending_video_sha256` `video_processing_enabled` `video_processing_status` `audio_processing_enabled` `realtime_audio_variant_enabled` `current_audio_source` `current_audio_reference` `current_audio_start_at_ms` `current_mp4_sha256` `current_audio_sha256` `worker_status` `fallback_reason` `pending_audio_candidate` `audio_processing_parameters_version` `audio_processing_status` `audio_processing_runtime` `audio_processing_gain_db` |
| `MediaEffectProfile` | 三个开关和效果参数 | `video_processing_enabled` `audio_processing_enabled` `realtime_audio_variant_enabled` `parameters_version` |
| `ResearchReport` | 本地研究报告摘要 | `source_mp4_sha256` `input_mp4_sha256` `current_mp4_sha256` `report_sha256` `algorithm_version` `random_seed` |

当前桌面播放对象是一个 `SourceMedia` 和一个 `PlaybackSnapshot`，在单一窗口内循环，不创建离线版本、不计算 N、不建立版本队列。源视频导入白名单为 `.mp4`、`.mov`、`.mkv`、`.avi`、`.webm`、`.m4v`、`.ts`、`.m2ts`、`.flv`、`.wmv`、`.3gp`，最终以 FFprobe 实际探测为准。`mp4_sha256`/`mp4_hash_status` 只在实际 MP4 哈希链路启用时使用，非 MP4 不得伪造 MP4 哈希；任何处理阶段提交前必须完成该阶段要求的哈希校验。

### 2.1 实时话术幻化（桌面本地 IPC）

实时话术幻化不是 Go OpenAPI 资源，不恢复旧的单段试听任务。Rust/Tauri IPC 直接围绕 `AudioTrackInput`、`SpeechToSpeechContext`、`SpeechToSpeechResult` 和 `AudioVariantCandidate` 实现：

- 输入可以是本地文件或受控实时流，speech-to-speech Worker 在桌面端或受控本地环境执行。
- 候选必须带当前播放代际、循环轮次、片段 ID、时长、同步偏移和完整哈希；默认目标时长门禁为 `±3%`。
- 候选先进入待切换槽；只有通过同步门禁并收到提交动作后才替换当前音轨。失败、超时、取消或候选过期时保持上一条可用音轨。
- 不创建新 MP4、不创建第二个播放窗口、不维护版本队列。

### 2.2 实时音频幻化与 speech-to-speech（桌面本地契约）

实时音频幻化不新增 Go 音视频上传接口，输入文件/实时流和音频产物均在桌面端处理。核心对象如下：

| 类型名 | 关键字段 | 说明 |
| --- | --- | --- |
| `AudioTrackInput` | `track_id` `source_kind` `audio_sha256` `start_at_ms` `duration_ms` `sample_rate_hz` `channel_count` | 统一描述本地文件或受控实时流 |
| `SpeechToSpeechContext` | `track_id` `source_kind` `playback_generation` `loop_index` `segment_id` `start_at_ms` `sample_rate_hz` `channel_count` `transcript_text` `previous_variant_text` `locked_fields` `locked_field_values` `target_duration_ms` `max_chars` `language` `timeout_ms` | speech-to-speech Worker 的输入上下文；锁定字段和值按相同下标对应 |
| `SpeechToSpeechResult` | `decision` `text` `audio_path_or_stream_ref` `audio_sha256` `duration_ms` `sync_offset_ms` `sample_rate_hz` `channel_count` `latency_ms` `model` `fallback_reason?` | LLM 决定 `keep_original` 或 `rewrite` 后的结构化结果 |
| `AudioVariantCandidate` | `playback_generation` `loop_index` `segment_id` `start_at_ms` `variant_mode` `audio_path_or_stream_ref` `audio_sha256` `duration_ms` `sync_offset_ms` `sample_rate_hz` `channel_count` `ready` | 当前播放视频的待切换音频候选；只有播放位置到达 `start_at_ms` 才允许换入，不代表新 MP4；底层可使用双槽、单引擎预加载或其他成熟媒体能力 |

桌面本地播放开关：

| 字段 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `video_processing_enabled` | boolean | `false` | 控制视频画面处理和视频研究效果 |
| `audio_processing_enabled` | boolean | `false` | 控制普通声音处理 |
| `realtime_audio_variant_enabled` | boolean | `false` | 控制 speech-to-speech 话术决策、实时变体和当前音轨替换 |
| `loop_playback_enabled` | boolean | `true` | 控制同一个源视频是否从 0 秒继续循环 |
| `playback_loop_index` | integer | `0` | 当前播放轮次，只读运行时状态 |

统一规则：

- `target_duration_ms`、`duration_ms`、`latency_ms`、`sync_offset_ms` 均为毫秒；`audio_sha256` 只用于文件完整性和阶段追踪，不用于重复检测。
- `SpeechToSpeechContext` 必须带当前播放代际、循环轮次和 `segment_id`；旧候选不得换入当前音频槽。
- LLM 必须遵守 `locked_fields`、`max_chars` 和 `target_duration_ms`；不确定、字段校验失败或超时返回 `keep_original` 或由播放器回退原声。
- Rust 在候选提交前校验 `locked_field_values` 均保留、文本字符数不超过 `max_chars`，且生成音频时长处于目标时长容差内；校验失败回退原声。
- 运行时不维护 Chromaprint/landmark 历史库，不产生 `similarity` 或 `matched_record_id` 播放决策；内容指纹对比只在研究报告中使用。
- 当前播放代际、循环轮次和 `segment_id` 必须参与候选校验，旧候选不得换入当前音频槽。
- 当前基础音轨或 speech-to-speech 内容级变体均可以成为决策输出；实时幻化关闭时不启动 Worker，变体失败、超时或同步不通过时保持上一条可用音轨。
- 实时幻化换轨需要独立的 speech-to-speech Worker IPC；旧 `speech_preview_task` 已删除，不得重新引入。当前已注册 `start_speech_to_speech_worker`、`cancel_speech_to_speech_worker`、候选按时提交和原声回退命令；真实服务和长时间连续性仍需环境验收。
- 候选换入由 `commit_audio_variant_candidate_if_due` 根据播放器当前位置触发；未到 `start_at_ms` 时必须保持原音轨，避免提前切音造成可感知断点。
- 当前 Worker 调度只接受 `source_kind=local_file`，且输入路径必须与当前 `SourceMedia.source_path` 规范化后完全一致；`controlled_stream` 保留在契约中，但本版本拒绝启动，避免前端任意读取本地路径或伪造实时流。
- 本地 Worker 能力探测使用环境变量 `AUTOLIVE_SPEECH_TO_SPEECH_WORKER` 指定可执行文件，Rust 通过参数 `--capabilities-json <capability_output.json>` 获取并校验 `SpeechToSpeechWorkerCapabilities`；能力不可用时保持原音轨。上下文 Worker 使用 `--input-json <context.json>` 和 `--output-json <result.json>`，结果先写入 `.partial` 再原子提交。

参数面板 IPC：

- `get_default_local_research_params` 返回 Rust 统一默认值。
- `validate_local_research_params` 只校验单位、范围和字段关系，不执行媒体算法；返回 `valid` 与结构化字段错误。
- 普通声音面板覆盖自然真人模式、随机周期、音高、增益/响度、播放速度、三段均衡、降噪/环境声、淡入淡出、干湿比、混响、底噪、采样率和码率；研究分析面板覆盖 MFCC、SNR、共振峰、滤波 Q、相位、颤音、频谱和音色库。未接入 DSP/分析器的字段必须标记 `unavailable`，实时音频幻化参数本次不扩展。

研究分析 IPC：

- `get_research_worker_capabilities`：主窗口探测 `AUTOLIVE_RESEARCH_WORKER`，未配置或可执行文件无效时返回 `available=false` 与原因。
- `get_research_status`：返回 `idle/unavailable/running/ready/failed/cancelled` 和报告摘要。
- `start_research_analysis`：主窗口接收参数快照，先校验当前阶段输入产物的完整 SHA-256，再把参数写入应用缓存并启动受控 Worker；当前研究 Worker 的阶段产物契约仍以 MP4 为主，可选生成研究 MP4，不参与当前播放决策。
- `cancel_research_analysis`：取消并回收研究 Worker；失败、超时和取消都会清除临时产物。
- `cleanup_local_caches_command`：按 4 GiB 媒体缓存、512 MiB 研究缓存上限清理旧产物和过期 `.partial` 文件；当前播放视频、待切换视频、当前研究报告及运行中研究任务的参数/输出路径受保护，不清理源视频。

研究报告哈希字段语义必须分开：通用源/产物哈希记录任意受支持文件的完整字节流；`source_mp4_sha256`、`input_mp4_sha256`、`current_mp4_sha256` 只记录实际为 MP4 的对应文件，`report_sha256` 是报告 JSON 完整字节流哈希。当前研究 Worker 的多格式输入仍需后续适配。

### 2.3 本地媒体处理缓存

- `current_video_reference` 是当前播放中的视频文件路径；`current_video_source` 为 `original` 或 `processed`。
- `pending_video_reference` 与 `pending_video_sha256` 是后台媒体 Worker 已完成、但尚未到循环边界的候选缓存；二者必须同时为空或同时有值。
- 视频或普通声音处理使用本地 FFmpeg/FFprobe 受控 Worker：参数通过参数数组传递，不经过 Shell；视频处理开启时必须重新编码，不得使用视频流 `copy`；声音处理开启时使用 AAC 和音频滤镜。声音处理只生成当前播放所需的媒体缓存，不建立视频版本队列。实时幻化同时开启时，普通声音处理必须作用于最终当前音轨；当前运行时只实现增益/响度路径，其他参数待 DSP Worker 接入前返回 `unavailable`。
- Worker 输出先写入 `.partial.mp4`，随后通过 FFprobe 可读性探测、完整 MP4 SHA-256 和冲突检查后原子提交到应用缓存；原始源视频只读，不被覆盖。
- `start_media_processing` 只启动后台处理并立即返回；源视频继续在当前窗口播放。Worker 成功只写入待切换槽，`complete_playback_loop` 在视频结束时提交待切换视频；`commit_media_processing_if_ready` 可供播放边界显式提交。
- Worker 不可用、超时、取消、失败或输出校验失败时，继续当前可用视频并返回结构化状态，不伪造处理成功。

### 2.4 本地媒体 IPC

| 命令 | 调用范围 | 作用 |
| --- | --- | --- |
| `get_media_engine_capabilities` | 主窗口 | 探测受控 FFmpeg/FFprobe 版本和可用性；不可用时返回 `available=false` 与原因 |
| `start_media_processing` | 主窗口 | 接收 Rust 已校验的研究参数，后台生成当前源视频的处理缓存；不生成 N 个版本、不创建第二个窗口 |
| `commit_media_processing_if_ready` | 主窗口或最终效果窗口 | 在循环边界提交已经校验的待切换视频缓存；未就绪时保持当前引用 |

媒体处理命令通过参数数组启动本地 FFmpeg/FFprobe，不经过 Shell；输出先写入 `.partial.mp4`，经可读性探测和整个 MP4 文件 SHA-256 校验后再提交。

## 3. 单位和字段后缀

| 后缀/命名 | 单位 | 示例 |
| --- | --- | --- |
| `_ms` | 毫秒 | `duration_ms` `target_duration_ms` |
| `_seconds` | 秒 | `max_duration_seconds` |
| `_bytes` | 字节 | `file_size_bytes` `disk_free_bytes` |
| `_fps` | 帧每秒 | `frame_rate_fps` |
| `_percent` | 百分比整数 `0–100` 或业务文档明确的百分比 | `progress_percent` |
| `_sha256` | SHA-256 十六进制字符串 | `mp4_sha256` `artifact_sha256` |

约束：

- 不允许用 `duration` 这种无单位字段代替 `duration_ms`
- 不允许用 `size` 代替 `file_size_bytes`
- 不允许把 `Hz/dB/px/%` 这类媒体参数裸存成无单位整数

## 4. 枚举统一

### 4.1 角色与状态

| 类型 | 枚举值 |
| --- | --- |
| `ActorRole` | `admin` `user` |
| `UserStatus` | `active` `disabled` |
| `DeviceStatus` | `pending_activation` `active` `disabled` `revoked` |
| `ActivationCodeStatus` | `active` `used` `expired` `revoked` |
| `ModelAccountStatus` | `active` `cooldown` `exhausted` `disabled` |
| `ModelLeaseStatus` | `active` `released` `expired` |

模型号池与租约摘要字段：

- `ModelPoolAccountSummary`：`id`、`provider`、`model`、`base_url`、`status`、`priority`、`daily_limit`、`concurrency_limit`、`secret_configured`；`daily_limit` 单位为 token/UTC 日，`0` 表示不限制
- `ModelLease`：`id`、`provider`、`model`、`status`、`expires_at`、`proxy_mode=direct_lease`、`direct_base_url`、`concurrency_limit`。当前没有供应商凭证委托能力，Go 不返回 `direct_access_token`；Rust 不能把空字段或完整 API Key 当作直连凭证，必须回退当前可用音轨。
- `api_key` 只允许出现在管理员新增请求中，响应和客户端租约中禁止返回；当前文档目标是由 Go Secret Store 保存密文/引用，源码中的开发期内存实现属于待迁移状态。

模型调用类型：

- `DirectLLMCallContext`：Rust 直连供应商时，必须携带当前会话/设备上下文、有效 `direct_lease`、固定 provider/model 和消息；客户端不能携带任意上游地址、完整号池或长期 API Key。
- `DirectLLMCallRecord`：直连链路接通后，Rust 将 `client_call_id`、`lease_id`、provider/model、usage、延迟、状态和错误摘要回报 Go；Go 生成服务端 `request_id`；请求正文和音视频内容不上传。当前 Go 接口已实现，Rust 自动上报尚未接通。
- `DirectModelChatRequest`（桌面本地 IPC）：只允许主窗口提交当前租约描述、`expires_at_unix_ms`、消息和超时；委托凭证只允许短期驻留 Rust 内存，当前 Go 租约没有凭证时命令返回不可用。`direct_base_url` 必须来自受信任租约，不能由业务逻辑自行切换。
- `DirectModelChatResponse`（桌面本地 IPC）：只在客户端本地返回模型文本、模型标识、结束原因、usage 和延迟；模型正文不回传 Go，也不写入日志。
- Go 的账号测试记录：管理员触发后由 Go 使用 Secret Store 中的密钥访问 OpenAI-compatible 接口，记录测试状态、HTTP 状态、延迟、模型响应摘要和错误码。

## 6. 哈希字段契约

### 6.1 MP4

- 字段名：`mp4_sha256`
- 含义：整个 MP4 文件字节流 SHA-256
- 适用对象：源视频和当前视频处理缓存

### 6.2 非 MP4

- 字段名：`artifact_sha256`
- 含义：非 MP4 产物的完整文件字节流 SHA-256
- 适用对象：`json`、`wav`、`aac`、`txt`、`report` 等

### 6.3 不能混用

- 不能把 MP4 哈希写进 `artifact_sha256` 来替代 `mp4_sha256`
- 不能把 `json/wav` 等非 MP4 哈希写成 `mp4_sha256`

## 7. PlaybackSnapshot 关键字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `source_media` | `SourceMedia` | 当前源视频及元数据 |
| `loop_index` | `integer` | 当前播放轮次 |
| `playback_state` | enum | 当前播放状态 |
| `video_processing_enabled` | `boolean` | 视频处理开关 |
| `audio_processing_enabled` | `boolean` | 声音处理开关 |
| `realtime_audio_variant_enabled` | `boolean` | 话术实时幻化开关 |
| `audio_decision` | enum | 当前基础音轨沿用/改写/回退决策 |
| `worker_status` | enum | speech-to-speech Worker 状态 |
| `fallback_reason` | `string/null` | 候选不可用时的原因 |

`SourceMedia.mp4_sha256` 在 `mp4_hash_status=disabled`、`pending` 或 `failed` 时为 `null`；只有源文件实际为 MP4 且进入对应哈希链路时，哈希完成后才填写整个 MP4 文件字节流的 SHA-256。哈希失败不阻塞已经开始的本地原声播放，但禁止进入需要完整哈希的处理提交，并在界面显示明确状态。

## 8. speech-to-speech 与播放落地建议

### Go

- 以 OpenAPI 为服务端 DTO 契约
- 内部领域模型可不同名，但边界转换必须一一对应

### React

- 列表和详情页直接复用分页对象和枚举
- 不自己再造一套阶段/状态枚举

### Rust

- 本地缓存、离线补发队列、IPC 事件命名应与 OpenAPI 字段对齐
- speech-to-speech 请求使用播放代际、循环轮次和片段 ID 防止旧候选换入当前音频槽。
- Rust 直连模型结果只在本地供 speech-to-speech 使用；Go 只接收结构化调用摘要，不接收模型正文、视频或音频本体。
- Rust 负责 Worker 状态、候选校验、同步门禁和当前音轨替换；Go 负责租约和 OpenAI-compatible 账号测试。
