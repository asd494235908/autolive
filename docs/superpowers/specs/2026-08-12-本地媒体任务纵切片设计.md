# 本地媒体任务纵切片设计

> 文档状态：已废止（2026-08-13）。本文件是早期媒体任务方案的历史审计记录，不属于当前产品实施依据。当前产品只做单视频、单窗口循环播放和三个独立处理开关，不创建媒体任务或离线版本。

## 当前口径

当前首版导入单个视频后只在一个窗口内循环播放；视频处理、声音处理和实时音频幻化独立开关均在桌面端本地执行。本文的 VariantTask/prepare 设计只保留给未来离线 N 版扩展，当前单视频循环和实时音频幻化不创建 VariantTask。

## 目标

在不接入 RTMP/OBS、不上传本地视频、不伪造变体产物的前提下，为未来离线 N 版保留第一个真实本地阶段：

```text
创建任务 → 启动任务 → 本地 prepare → 上报阶段结果 → 可取消
```

`prepare` 只负责校验源 MP4、读取元数据、计算完整源文件 SHA-256，并生成不可覆盖的本地准备清单。ASR、LLM 改写、TTS、时长对齐、视频效果和最终 MP4 重编码仍未在本切片中宣称完成。

## 边界和不做事项

- Go 控制面继续只接收元数据、状态和产物摘要，不接收视频本体。
- Rust/Tauri 在本地执行 `prepare`，源文件只读；工作目录由 Tauri 应用数据目录派生，不接受前端任意输出根路径。
- `prepare.json` 是阶段产物，保存源路径规范化结果、源媒体元数据、源 MP4 SHA-256、处理链版本和创建时间。
- 目标任务 ID 必须符合现有 ID 约束，只能定位到应用数据目录下的任务子目录。
- 对已存在且内容一致的 `prepare.json` 重跑返回同一结果；内容不一致时拒绝覆盖。
- 任务启动、阶段事件和取消请求沿用 Go 已有幂等键与事件 ID 规则。
- 本切片不启动媒体守护进程，不实现 RTMP/OBS，不实现 A/B 播放器，不在没有可播放产物时替换同一窗口媒体源。

## 组件

### Rust 核心 `variant_pipeline`

提供不依赖 Tauri 的纯文件函数：

- `prepare_variant_task(request, work_root, cancellation) -> PrepareVariantTaskResult`
- `cleanup_variant_task_staging(task_id, work_root) -> CleanupResult`

它复用现有 MP4 探测和整文件 SHA-256 能力，输出 `source_mp4` 输入摘要和 `report_json` 输出摘要。所有 JSON 产物使用完整文件字节流 SHA-256。

### Tauri IPC

新增仅主窗口可调用的命令：

- `prepare_variant_task`：使用应用数据目录执行本地 prepare。
- `cleanup_variant_task_staging`：只清理指定任务目录下的临时 staging 内容，不删除源文件和已验收 `prepare.json`。

命令失败返回现有结构化 `code/message`，不返回自由格式日志。

### 桌面控制面客户端

补齐已有 OpenAPI 路由的最小调用：

- `startVariantTaskControlPlane`
- `reportVariantTaskEventsControlPlane`
- `cancelVariantTaskControlPlane`

UI 只在真实任务已创建、设备 active、源文件元数据完整时启用启动；本地 prepare 失败时上报 `prepare/failed`，成功时上报 `prepare/running` 和 `prepare/succeeded`。

## 状态和恢复

- 启动请求成功后任务进入 `running`，再开始本地 prepare。
- 本地 prepare 成功后任务仍停留在 `running`，控制面 `current_stage` 前进到下一个已启用阶段；不能提前调用 complete。
- 本地失败先保留错误信息并上报失败事件；不删除源文件，不覆盖已存在阶段产物。
- 取消先调用控制面取消，再清理 staging；若网络失败，仍允许本地清理 staging，但界面必须显示控制面取消未确认。
- 当前网络请求使用稳定幂等键；持久化事件补发队列属于下一切片，不在本切片伪装完成。

## 验收

1. Rust 单元测试验证：合法 MP4 生成 `prepare.json`，源文件哈希为 64 位小写十六进制，产物哈希为完整 JSON 文件哈希。
2. Rust 单元测试验证：哈希不匹配、取消、非法任务 ID、已有不同内容产物均失败且不覆盖源文件/既有产物。
3. Tauri UI 构建通过；任务启动调用顺序可由代码和 API 类型证明。
4. Go 现有任务事件状态机测试继续通过；桌面端不调用 complete，不展示“已生成 N 个视频”。
5. 真实未安装 FFmpeg 时，prepare 仍可运行；后续媒体引擎能力探测失败必须是明确状态，不能回退为成功。
