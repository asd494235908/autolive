# 语音模型下载与打包设计

## 目标

让固定话术 Worker 在开发版下载模型时向用户明确提示阶段和原因；正式桌面包在构建阶段预下载 Demucs、faster-whisper 和 XTTS-v2 模型，并把完整模型缓存随安装包交付，用户首次使用不再临时下载。

## 范围

- 固定话术 Worker：Demucs 人声分离、faster-whisper 话术索引、XTTS-v2 声音生成。
- Rust/Tauri：启动 Worker 时传递模型资源目录，并把阶段状态同步给播放快照。
- React/Tauri UI：显示“下载模型 / 人声分离 / 话术识别 / 已完成 / 失败”等状态。
- Tauri 构建：构建前下载并校验三类模型，复制到 bundle resources。

不改变 MP4 选择、视频处理、普通声音处理、实时音频幻化和播放窗口生命周期；不上传视频或声音；不加入 NVIDIA/CUDA。

## 运行时设计

Worker 使用现有 JSON 请求/结果协议，新增可选进度 JSON 文件参数。准备流程在以下阶段写入原子状态：

1. `checking-models`：检查本地模型缓存。
2. `downloading-models`：开发版缺少模型时下载，并提示具体模型名称。
3. `separating-voice`：Demucs 人声分离。
4. `transcribing`：faster-whisper 生成完整话术索引。
5. `ready` 或 `failed`：写入最终结果。

Rust 在 Worker 运行期间读取进度文件并更新 `VoiceCloneReplacementState` 的阶段、提示和百分比；UI 继续以 500ms 快照刷新。正式包资源存在时，模型检查直接通过，不显示下载阶段。

Worker 子进程的 stderr 必须持续排空并限制保留长度，避免 Demucs 输出填满管道后阻塞；取消和超时要同时回收读取线程与进程组。

## 打包设计

新增构建前模型资源准备脚本。脚本使用当前目标平台的 Python 3.11 环境，设置隔离的模型缓存目录，依次加载：

- `demucs` 的 `htdemucs`；
- `faster-whisper` 的 `small`；
- `TTS.api` 的 `tts_models/multilingual/multi-dataset/xtts_v2`。

三者全部成功加载后，将缓存复制到 Tauri 配置声明的 `voice-models/**` 资源目录；任一下载或校验失败，构建失败，不生成半成品安装包。模型权重不提交 Git，构建缓存可以复用。

Rust 启动内置 Worker 时优先使用 `resource_dir()/voice-models`，开发环境仍允许通过 `AUTOLIVE_VOICE_CLONE_MODEL_ROOT` 覆盖；同时设置 Hugging Face、Torch 和 Coqui TTS 的缓存变量，使三类库读取同一套只读资源。模型缺失时返回明确的“安装包模型资源不完整”，不静默联网下载。

## 错误与恢复

- 开发版下载失败：显示模型名称和错误原因，允许取消后重试。
- 正式包资源缺失：固定话术保持不可用，其他播放和处理开关不受影响。
- Worker 失败/超时/取消：清理当前操作临时目录，保留已完成的源视频和其他处理缓存。
- 模型下载只写临时缓存，校验成功后原子替换为可用缓存，避免中断留下伪完整模型。

## 验收

- 开发环境缺少模型时，界面明确显示正在下载哪个模型，而不是固定显示“准备中 35%”。
- 三类模型都存在时，准备人声不再触发联网下载。
- stderr 高输出 Worker 可以正常退出，不发生管道阻塞。
- `tauri:build` 会在模型资源不完整时失败，并把完整模型目录放入安装包 resources。
- 原有 Rust、UI、Worker 测试全部通过；普通视频播放和声音处理回归验证不受影响。
