# 当前话术人声克隆热替换设计

## 1. 文档状态

- 状态：已完成需求确认，等待文档复核
- 日期：2026-08-14
- 范围：Rust/Tauri 桌面端 + 本地 CPU Worker
- 关联需求：视频人声提取、用户输入文本后复刻参考音色，并在播放中的当前话术片段内替换

## 2. 已确认的产品行为

用户先在现有桌面端流程中选择一个 MP4。当前项目已经提供“选择 MP4 → `probe_media` → `source_media`”链路，本功能直接复用它，不新增文件选择器、媒体队列或后台上传。

用户可以：

1. 通过“准备人声”从当前源 MP4 提取人声并建立话术时间索引。
2. 手动输入一段文本，或从最多 10 条本地预制文字中选择一条填充输入框。
3. 在视频正在播放时点击“替换当前话”。

点击替换后的行为：

- 记录点击时刻 `t0`，定位 `t0` 所在的人声话术片段 `[start, end]`。
- 从 `t0` 开始切断当前话术剩余部分，使用参考人声生成用户文本。
- 新话播放完成后，原音频从 `end` 继续，原话剩余部分不再重复播放。
- 替换只发生在当前播放轮次；视频进入下一轮后恢复原始音频。
- 视频画面继续播放，不创建新窗口，不生成 N 个 MP4，不修改原始 MP4。

## 3. 功能边界

### 3.1 本次包含

- 当前源 MP4 的本地音频提取。
- Demucs CPU 人声分离，生成参考人声。
- faster-whisper CPU/int8 + VAD/时间戳，建立话术片段索引。
- Coqui XTTS-v2 CPU 参考音色克隆，默认语言 `zh-cn`。
- 当前话术热替换，支持手动输入和最多 10 条本地预制文字。
- 本地临时完整替换音轨生成、格式检查、完整 SHA-256 和原声回退。
- Rust Worker 的取消、超时、代际校验、资源释放和缓存保护。

### 3.2 本次不包含

- 背景音乐保留、伴奏分离后的重新混音或多轨编辑；当前话术区间整体替换。
- 多说话人区分、说话人聚类、口型同步、自动连续改写和永久成片导出。
- Go/OpenAPI/模型号池/服务端模型代理改动。
- NVIDIA/CUDA、GPU 推理或 GPU 专属安装路径。
- RTMP/OBS、平台接入、自动发布或检测规避能力。

## 4. 与现有功能的隔离边界

### 4.1 复用但不改动的入口

- 复用 `desktop/ui/src/App.tsx` 现有 MP4 选择和导入状态。
- 复用 `desktop/src-tauri/src/commands.rs` 当前媒体探测、播放窗口和 `get_snapshot` 能力。
- 复用现有 Tauri Worker 的线程所有权、取消令牌、超时、临时文件和缓存保护模式。
- 复用现有最终效果窗口的本地文件播放和音频分析能力。

### 4.2 明确不触碰的能力

- 不调用或修改现有视频处理 Worker、视频缓存、视频处理开关和 `current_video_reference`。
- 不调用或修改现有普通声音处理参数、声音处理 Worker、声音处理开关和参数重置逻辑。
- 不抢占现有实时 speech-to-speech 音频候选；实时音频候选正在占用时，固定文本替换按钮返回“当前实时音频正在占用”。
- 不修改登录、激活、心跳、模型租约、Go API、后台管理端和数据库迁移。

固定文本替换使用独立的 `VoiceCloneReplacementState` 和独立音频槽。启用已有普通声音处理时，替换音频只经过现有已实现的增益/响度输出路径；它不改变任何声音处理配置，也不把声音处理参数传给克隆 Worker。参考人声始终来自原始 MP4，而不是视频或声音处理后的缓存。

## 5. 组件与职责

### 5.1 React 桌面界面

在现有源视频控制区域增加独立的“声音克隆替换”卡片：

- `准备人声`：按需启动当前源视频的参考人声和话术索引准备。
- 预制文字下拉框：本地最多 10 条。
- 当前文本输入框：支持手动输入和编辑，最多 500 字。
- 保存/删除预制文字：只写本地 `localStorage`，不上传。
- `替换当前话`：要求当前源存在、准备完成、文本非空、播放器正在播放且没有实时音频候选占用。
- 状态、进度、失败原因和取消入口。

预制文字数据结构：

```ts
type VoiceClonePreset = {
  id: string;
  title: string;
  text: string;
  createdAt: string;
  updatedAt: string;
};
```

运行时从 API、IPC、窗口消息和本地存储读取的数据仍需运行时校验；预制文字达到 10 条上限或文本超过 500 字时，界面拒绝保存。

### 5.2 Rust 领域状态

新增独立状态，不复用实时音频候选字段：

```text
VoiceCloneReplacementState
  status: disabled | idle | preparing | ready | generating | playing | failed | cancelled
  source_generation: u64
  source_path: string
  replacement_audio_reference: optional string
  replacement_audio_sha256: optional string
  replacement_duration_ms: optional u64
  replace_at_ms: optional u64
  resume_at_ms: optional u64
  input_text: optional string
  model: optional string
  error: optional string
```

状态必须绑定当前播放代际、源路径和操作 ID。源视频切换、停止、下一轮或取消时，未提交结果失效并删除；旧 Worker 结果不得覆盖新源或新操作。

### 5.3 Rust Worker 边界

建议新增：

- `desktop/src-tauri/src/voice_clone.rs`：输入/输出 DTO、状态校验、片段定位和替换音轨契约。
- `desktop/src-tauri/src/voice_clone_worker.rs`：固定 Worker 进程的启动、能力探测、超时、取消、输出文件校验和 Join。
- `desktop/worker/voice_clone_adapter.py`：只负责本地 FFmpeg、Demucs、faster-whisper 和 XTTS-v2 编排，不直接拥有 Tauri 播放状态。

Python Worker 通过显式 JSON 文件通信，不接收任意 shell 字符串。Rust 传入当前已探测源路径、FFmpeg/FFprobe 绝对路径、操作 ID、播放位置、话术片段边界、用户文本和输出目录；Worker 返回结构化结果。Worker 不访问 Go API，不读取模型密钥，不写日志中的用户文本或本地完整路径。

## 6. 处理流程

### 6.1 准备人声与话术索引

准备动作按需触发，不在用户选择 MP4 或播放时自动启动，避免影响现有播放、视频处理和声音处理。

1. Rust 校验当前 `source_media` 仍存在且路径规范化后未变化。
2. FFmpeg 从原始 MP4 提取本地音频。
3. Demucs 以 CPU 模式分离 `vocals`。
4. 参考音频归一化为适合 XTTS-v2 的本地 WAV，并裁剪到受控长度；没有有效人声时失败。
5. faster-whisper 以 CPU/int8、VAD 和时间戳生成话术片段：`start_ms`、`end_ms`、`text`。
6. 结果写入按源 MP4 完整 SHA-256 隔离的缓存目录，并对参考音频、索引 JSON 和中间产物计算完整字节流 SHA-256。
7. 准备成功后才启用“替换当前话”。

准备失败不影响源视频播放、视频处理、声音处理和实时 speech-to-speech。

### 6.2 当前话术替换

1. Rust 获取当前播放快照和 `t0`，确认状态仍为 `Playing`。
2. 在已缓存片段中查找 `start_ms <= t0 < end_ms` 的当前人声片段。
3. Worker 使用参考人声和用户文本生成克隆音频。
4. 以 `remaining_ms = end_ms - t0` 为当前替换时长目标：输出短于 `remaining_ms` 时保留语音并在尾部补静音；输出长于 `remaining_ms` 时，仅当 `generated_duration_ms / remaining_ms` 位于 `0.8–1.25` 时使用 FFmpeg `atempo` 调整到目标长度，超出该范围则拒绝替换。
5. FFmpeg 拼接完整临时音轨：

   ```text
   source[0,t0) + cloned[0,remaining_ms) + source[end,video_duration)
   ```

6. 输出音轨通过容器可读性、采样率、声道、总时长、文件大小、路径范围和完整 SHA-256 校验。
7. Rust 再次校验操作 ID、播放代际、源路径和当前时间仍在原片段有效窗口内；不满足则删除临时产物并回退。
8. 最终效果窗口切换独立 voice-clone 音频槽，视频继续播放且不重新创建窗口。
9. 完整替换音轨自然播放到原音频尾部；本轮结束时清除替换状态并恢复源视频原声。

## 7. 错误、超时与资源策略

- 文本为空、超过 500 字或包含无效输入：界面立即拒绝。
- 当前不在话术片段、源没有音轨、参考人声为空：返回可理解的业务错误，不修改播放状态。
- Worker 未配置、Python 依赖或模型缺失：能力探测显示不可用，继续原声。
- 预处理和单次替换分别只能有一个 Worker；新源、停止、取消和关闭窗口都会取消并等待旧 Worker。
- Worker 必须设置超时并杀死子进程；超时、异常退出和输出冲突均删除 staging 文件。
- 所有输出路径必须位于应用媒体缓存目录；禁止使用用户输入直接构造任意文件路径。
- 文本、完整本地路径、模型文件路径和临时 Worker JSON 不进入结构化日志、Go API 或审计记录。
- 原始 MP4 永不覆盖。临时替换音轨只有在完整校验通过后才成为当前引用。
- 生成音轨播放前若当前话已结束、源已切换、播放已停止或操作 ID 已变化，结果直接丢弃。

## 8. 测试与验收

### 8.1 自动测试

- Rust 单元测试：片段边界命中/未命中、当前时间代际校验、替换音轨 JSON、路径/哈希/格式校验、过期结果丢弃、取消和超时。
- Rust Worker 合同测试：使用假 Worker 验证参数数组、输出提交、错误退出、超时、取消和临时文件清理。
- Python 测试：能力探测、输入边界、输出 JSON 校验和无模型环境的结构化失败。
- React 测试：手动输入、最多 10 条预制文字、保存/删除/填充、按钮禁用、状态恢复和错误展示。

### 8.2 手工验收

1. 复用现有 MP4 选择功能，确认视频正常导入和原有播放不变。
2. 点击准备人声，确认视频播放、视频处理、声音处理和实时音频开关不被阻塞或改变。
3. 播放到一句话中间，手动输入文本并点击替换；确认当前话剩余部分被切掉，克隆话播放后从原话结束处继续原声。
4. 选择一条预制文字替换，再手动编辑文本替换；确认两条路径一致。
5. 在停顿处、当前话结束后、视频切换时和播放暂停时点击；确认不会误替换后续话术。
6. 取消、超时、Worker 缺失、无有效人声和模型失败时，确认视频仍继续且恢复原声。
7. 视频循环到下一轮，确认替换音轨清除并恢复原始音频。
8. 同时开启视频处理或声音处理，确认现有处理仍按原逻辑工作，固定文本替换不改变其参数和开关。

## 9. 依赖与许可

- 复用仓库现有 FFmpeg/FFprobe 资源和 Rust 媒体路径解析。
- 使用成熟本地库 Demucs、faster-whisper 和 Coqui TTS/XTTS-v2，不自行实现人声分离、ASR、VAD、TTS 或编解码器。
- 首版固定 CPU/int8；不新增 NVIDIA/CUDA 安装与构建路径。
- 模型文件不提交仓库、不随桌面安装包默认打包；XTTS-v2 的模型许可与服务条款在正式商业分发前单独复核。
