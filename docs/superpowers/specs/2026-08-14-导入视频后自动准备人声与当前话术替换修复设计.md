# 导入视频后自动准备人声与当前话术替换修复设计

## 目标

修复固定话术替换在“准备人声”完成后仍不可用的问题，并在导入 MP4 后自动完成音频提取、人声分离和话术识别。

## 范围

- 导入 MP4 后仍立即开始原视频播放。
- 当前 MP4 的完整 SHA-256 完成后，在后台自动调用已有固定话术 Worker。
- Worker 继续负责音频提取、Demucs 人声分离、Whisper 话术识别和 XTTS-v2 模型加载。
- 以源视频 SHA-256 复用准备缓存；同一视频不重复转换，换视频自动准备新缓存。
- 准备成功后状态保持为“已准备”，替换按钮在最终效果播放器播放且位置同步后可用。
- 准备失败只更新固定话术提示，不改变视频播放、原声和其他处理开关。

## 非目标

- 不生成新的 MP4 或离线话术版本。
- 不改变普通声音处理、视频处理和实时音频幻化的执行链路。
- 不在导入阶段阻塞视频播放，也不自动替换当前话术。
- 不新增 GPU、服务端模型或网络代理能力。

## 方案

采用前端触发、现有 Rust/Worker 执行的方案：

1. `probe_local_mp4` 完成后继续调用现有播放启动流程。
2. 前端监听当前源视频的 `mp4_hash_status`，仅在状态为 `ready` 且 Worker 可用时触发一次自动准备。
3. 以“规范化源路径 + MP4 SHA-256”作为自动任务去重键，防止导入状态刷新或轮询重复启动 Worker。
4. Rust 的 `prepare_voice_clone_source` 优先读取现有准备缓存；缓存无效时才启动 Worker。
5. Worker 完成后由 Rust 写入当前源视频状态；前端继续通过快照轮询获取 `ready`、`failed` 或 `cancelled`。
6. 替换仍使用当前最终效果窗口的播放位置和当前话术片段，失败时保持原声。

## 状态与错误

- `未准备`：当前源视频尚未完成自动准备或尚未满足哈希条件。
- `准备中`：后台正在提取音频、分离人声、转写或加载 XTTS-v2。
- `已准备`：参考音频、话术索引和 XTTS-v2 均已通过校验。
- `失败`：只展示可操作错误，视频仍可继续播放原声；用户可手动重试。
- 同一源视频的已有缓存恢复为 `已准备`，不重新运行 Worker。

## 验收标准

- 导入 MP4 后，视频能先播放，固定话术区域随后显示自动准备进度。
- 自动准备完成后状态显示“已准备”，且满足播放位置条件时“替换当前话术”可点击。
- 在当前话术播放期间替换成功，话术结束后恢复原音频，下一轮仍为原声。
- 相同 MP4 重新进入页面不重复执行 Demucs、Whisper 和 XTTS-v2 准备。
- 替换或自动准备失败不影响 MP4 播放、普通声音处理、视频处理和实时音频幻化。
- 测试覆盖自动任务去重、准备缓存恢复、准备状态保持和替换按钮可用条件。
