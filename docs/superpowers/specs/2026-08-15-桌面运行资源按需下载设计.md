# 桌面运行资源按需下载设计

## 状态

- 日期：2026-08-15
- 目标版本：`v0.1.0`
- 已确认决策：自建服务器、公网 IP、HTTP 端口 `7088`、自动下载并保留本地目录导入兜底
- 替代范围：本设计替代 [`2026-08-14-语音模型下载与打包设计.md`](./2026-08-14-语音模型下载与打包设计.md) 中“FFmpeg、固定话术 Worker 和全部语音模型必须随安装包交付”的部分

## 目标

把正式桌面安装包改为轻量主程序。FFmpeg/FFprobe、固定话术 Worker 和离线语音模型不再进入 Tauri bundle；用户第一次触发对应能力时，客户端从国内可访问的自建服务器下载资源，校验完成后安装到应用数据目录，后续启动直接复用。

首版运行资源地址固定为：

```text
http://101.96.208.132:7088/autolive-resources/v0.1.0/
```

服务器只接收本地开发机或 CI 已构建完成的发布资源，不接收源码、不执行项目构建。

## 非目标

- 不在安装器执行大文件下载，避免安装中断后无法恢复。
- 不让客户端运行时访问 GitHub、Hugging Face 或国外 FFmpeg 下载站。
- 不让服务器下发可变下载地址、可变哈希或任意命令。
- 不在本次范围内引入 CDN、P2P、增量补丁、自动更新框架或多个镜像源。
- 不改变单视频循环、固定话术生成、插话播放器和最终效果窗口的业务语义。
- 不把服务器 SSH 账号、密码或部署密钥写入客户端、仓库、日志或普通配置。

## 方案比较与选择

### 方案 A：逐文件下载，客户端内置清单（采用）

资源清单随已签名/已发布的桌面应用交付。清单列出资源组件、目标平台、相对路径、固定 URL、文件大小、SHA-256 和可执行标记。客户端下载各文件并逐个原子提交。

当前模型目录只有少量有效文件，Worker 也是 PyInstaller `--onefile` 产物；逐文件下载不需要 ZIP/TAR 解压库，能够直接对大模型文件断点续传，也不会出现压缩包解压到一半的状态。

### 方案 B：每个组件一个压缩包

下载请求更少，但客户端需要新增跨平台解压依赖、路径穿越防护、额外临时磁盘和解压进度。模型权重与 Worker 二进制本身可压缩收益有限，首版不采用。

### 方案 C：Go 控制面代理全部文件

可以复用 API 地址，但 3～6GB 文件会占用控制面进程和带宽，故障与业务 API 相互影响。首版使用独立静态文件服务，不让 Go API 中转资源字节。

## 资源拆分

### 媒体运行资源 `media`

按目标平台提供：

- `binaries/ffmpeg[.exe]`
- `binaries/ffprobe[.exe]`

首次导入视频时检查并自动下载。下载成功后继续原有 `probe_local_mp4` 流程；失败时不导入视频并提供重试、取消或导入本地资源目录入口。

### 固定话术运行资源 `voice-runtime`

按目标平台提供：

- `voice-worker/autolive-voice-clone-worker[.exe]`

首次自动准备人声或用户点击“准备人声”时检查并下载。

### 固定话术模型资源 `voice-models`

所有平台共享：

- Demucs `HTDemucs` 的 `refs/main` 与有效 snapshot 文件；
- faster-whisper-small 的 `refs/main` 与有效 snapshot 文件；
- XTTS-v2 的 `config.json`、`model.pth`、`speakers_xtts.pth` 和 `vocab.json`；
- Coqui TOS 接受记录及模型运行所需的固定元数据。

发布资源不包含 Hugging Face `.locks`、日志、`trees` 和已经复制到 snapshot 的 `blobs` 重复文件。资源准备脚本必须先复制到独立发布目录再清理，不能修改开发机模型缓存事实源。

固定话术功能依赖 `media + voice-runtime + voice-models`。用户导入视频时通常已经安装 `media`，因此第一次准备人声只补齐后两类。

## 客户端资源清单

每个目标平台随应用打入一个只读 JSON 清单。清单版本属于应用发布内容，不从 HTTP 服务器动态获取：

```json
{
  "schema_version": 1,
  "release": "v0.1.0",
  "target": "x86_64-pc-windows-msvc",
  "base_url": "http://101.96.208.132:7088/autolive-resources/v0.1.0",
  "files": [
    {
      "component": "media",
      "relative_path": "x86_64-pc-windows-msvc/binaries/ffmpeg.exe",
      "size_bytes": 1,
      "sha256": "64 位小写十六进制",
      "executable": true
    }
  ]
}
```

实际清单禁止占位大小或占位哈希。构建必须在资源文件完成后生成清单，再构建对应目标的桌面主程序。URL 只能由固定基地址和受校验相对路径组成，客户端不接受 UI、API、服务器响应或环境变量传入任意生产下载地址；开发测试可以通过测试构造函数注入本地 HTTP fixture。

## 本地安装布局

资源安装到 Tauri `app_data_dir()`，不再写安装目录或 `resource_dir()`：

```text
<app_data_dir>/runtime-resources/
  v0.1.0/
    x86_64-pc-windows-msvc/
      binaries/
      voice-worker/
    common/
      voice-models/
    installed.json
    partial/
```

`installed.json` 只在所需文件全部完成 SHA-256 校验并移动到最终路径后原子写入。开发环境继续允许现有绝对路径环境变量覆盖；正式版优先使用当前版本的应用数据资源目录，不再要求安装包资源目录包含大文件。

卸载主程序默认不自动删除数 GB 运行资源，避免升级后重复下载；设置页/缓存清理命令必须明确展示占用并允许用户主动删除。新版本使用独立版本目录，确认切换成功后才能清理旧版本。

## 下载状态与生命周期

Rust 拥有唯一下载任务状态，React 只通过 IPC 读取状态和发出开始/取消/重试命令。下载和 SHA-256 运行在受监督的阻塞任务中，不占用 Tauri 主线程或 React 渲染线程。

状态：

- `not_installed`：缺少当前组件；
- `checking`：检查清单、已有文件和磁盘空间；
- `downloading`：下载一个文件；
- `verifying`：核对大小和 SHA-256；
- `ready`：当前组件完整可用；
- `failed`：可重试失败；
- `cancelled`：用户取消，保留可信的 `.partial` 供续传。

同一时刻只允许一个资源安装任务。重复点击复用当前任务状态，不创建重复下载；导入新视频、视频循环和窗口开关不取消资源下载。应用退出时发送取消并等待任务结束或达到有限关闭预算。

## 断点续传与原子提交

每个目标文件先写入：

```text
partial/<sha256>.partial
```

恢复规则：

1. 若 partial 长度小于清单大小，发送 `Range: bytes=<length>-`。
2. 服务器返回 `206` 且 `Content-Range` 起点匹配时追加。
3. 服务器返回 `200`、范围不匹配、远端长度变化或 partial 超过目标大小时，删除 partial 并从 0 重新下载。
4. 下载完成先核对精确字节数，再计算整个文件 SHA-256。
5. 哈希不一致时删除 partial，标记失败；不得安装或执行。
6. 校验成功后创建父目录、设置需要的可执行权限，并通过同文件系统重命名提交。

网络瞬时失败最多自动重试 3 次，使用有限退避；HTTP 4xx、空间不足、哈希错误和清单错误不机械重试。取消不是错误，不删除可续传 partial。

## HTTP IP 安全边界

由于首版使用 HTTP 公网 IP，传输不提供 TLS 身份认证，安全依赖以下强制门禁：

- 清单随桌面应用交付，服务器不能修改 URL、大小和 SHA-256；
- 每个文件必须完成整文件 SHA-256 校验后才可提交；
- HTTP 重定向默认关闭，防止跳转到未允许主机；
- 只允许固定主机 `101.96.208.132`、固定端口 `7088`、固定前缀和 `http` 协议；
- 相对路径拒绝绝对路径、`..`、空段、反斜杠和平台前缀，最终路径必须保持在运行资源根目录；
- Worker 在校验前不可执行，模型在校验前不可加载；
- 客户端和服务器日志不记录 SSH 密码、部署私钥或用户本地媒体路径。

以后获得有效 HTTPS 域名时只发布包含新 HTTPS 基地址的新桌面版本，不降低哈希校验要求。

## 磁盘、性能与界面

开始组件下载前，按缺失文件总大小检查目标磁盘可用空间，并额外保留至少 `max(512MB, 缺失大小的 10%)` 安全余量。空间不足时显示所需、可用和资源目录，不开始下载。

界面使用现有 Ant Design 组件展示：

- 当前组件和文件；
- 已下载/总字节数和百分比；
- 当前速度与剩余大小；
- 取消、重试、选择本地资源目录；
- 下载完成后自动继续之前被挂起的“导入视频”或“准备人声”动作。

下载不使用全屏阻塞层，不锁定页面滚动。视频已经在播放时，语音资源下载不会暂停或降低原音轨；固定话术保持不可用，下载完成后再自动准备。

## 本地资源目录兜底

用户可以选择一个已经解压的资源根目录。客户端仍按内置清单逐文件校验大小和 SHA-256，并复制到应用数据资源目录；不能直接信任或从用户目录原地执行。导入允许部分资源，已验证文件跳过，缺失文件继续从服务器下载。

## 自建静态服务器

服务器环境已经只读确认：Debian 12、systemd 可用、约 804GB 可用空间。发布根目录使用：

```text
/fs/autolive-resources
```

采用成熟的 Caddy 静态文件服务预构建二进制，监听 `0.0.0.0:7088`，由独立 systemd service 管理。只开放 GET/HEAD，不开启目录浏览，不代理业务 API。版本文件路径不可覆盖；需要修复内容时发布新资源版本和新桌面应用清单。

服务器响应必须支持 Range，并对版本文件设置长缓存；服务启动后必须从公网验证普通 GET、HEAD、合法 Range、非法 Range、并发下载和重启恢复。公网端口不可达时，在路由器/防火墙增加 `101.96.208.132:7088 → 192.168.100.213:7088` 映射。

服务器部署只接收以下内容：

- Caddy 发布二进制和静态配置；
- 已构建资源文件；
- 运维所需的 systemd unit。

不上传仓库源码，不在服务器安装 Python/Rust/Node 构建环境。

## CI 与正式打包

桌面打包矩阵仍在 CI/开发机构建对应平台的 FFmpeg 和固定话术 Worker，准备公共模型，然后：

1. 复制并裁剪出独立资源发布目录；
2. 计算每个发布文件的大小和 SHA-256；
3. 生成当前目标的内置清单；
4. 构建不含大资源的 Tauri 安装包；
5. 将主程序产物上传到 GitHub Actions；
6. 使用专用 SSH 部署密钥把资源目录同步到服务器临时发布目录；
7. 服务器逐文件核对清单后，以版本目录原子发布。

CI 不使用用户提供的登录密码。实施时创建只允许写入资源发布目录的部署身份/密钥，并保存为受保护的 GitHub Actions Secret。服务器永远不接收源码。

Windows 恢复生成原生安装包，不再因数 GB 离线资源触发 WiX/MSI 体积限制；macOS 恢复正常 Tauri bundle。资源构建或部署失败不得把对应版本标记为正式可下载。

## 错误与恢复

- 服务器不可达：保留 partial，原视频已在播放时继续原音轨；显示重试和本地目录导入。
- 下载取消：保留 partial，下次从断点继续。
- 磁盘不足：不开始新文件，已安装资源保持可用。
- 哈希不一致：删除错误文件，不执行、不加载，明确提示资源校验失败。
- 应用崩溃/断电：未写 `installed.json` 的组件视为未完成；下次重新检查并续传。
- Worker/模型下载完成但能力探测失败：资源状态与 Worker 能力状态分开显示，不把“下载完成”伪装成“模型可用”。
- 新版本失败：继续使用旧版本已完成资源，不覆盖旧目录。

## 验收条件

- 三个平台正式安装包不包含 `voice-models`、`voice-worker`、FFmpeg 或 FFprobe 大文件。
- Windows 能生成原生安装包，不再因 MSI 资源体积失败。
- 未安装媒体资源时，首次导入视频显示下载进度，完成后自动继续导入。
- 未安装语音资源时，自动准备或手动准备先下载 Worker/模型，完成后自动继续准备。
- 资源下载期间主页面可滚动，最终效果窗口和原视频播放不被阻塞。
- 中断大文件下载后重试只下载剩余字节；服务不支持 Range 时安全地从头开始。
- 任一文件大小或 SHA-256 不一致时资源不可用。
- 本地资源目录导入同样执行完整校验，不能执行未验证 Worker。
- 服务器重启后 `7088` 自动恢复，公网 Range 请求返回正确 `206`。
- 客户端运行时网络请求不访问 GitHub、Hugging Face 或国外 FFmpeg 站点。
- 仓库、客户端产物和服务器配置中不存在用户提供的密码。
- Rust、React、Worker、构建脚本与三平台 CI 检查全部通过。
