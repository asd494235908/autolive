# 桌面端主页与独立播放器窗口设计

## 1. 目标

本轮修复桌面端的窗口职责、可读性、单源循环和运行时参数展示：

- 保留一个独立的播放窗口，窗口只承载视频画面和当前播放所需的音频。
- 主窗口承载播放控制、处理开关、音视频参数、自动变化状态、波形/频谱、Worker 和研究信息。
- 导入的同一个源视频在同一个播放窗口内持续循环，不生成 N 个视频、不创建第二个播放窗口。
- 音频/视频处理开启后，按周期生成一组新的运行时预览参数；参数变化不阻塞视频循环。

## 2. 非目标

- 不恢复 RTMP/OBS 推流、直播平台接入或断线重连。
- 不生成离线 N 版本 MP4。
- 不把尚未接入运行时 DSP 的 MFCC、SNR、共振峰、滤波 Q 值、相位扰动等参数标记为“已真实生效”。这些参数可以参与参数快照和实验展示，但运行时状态必须保留能力边界。
- 不创建多个播放窗口，不通过重新创建窗口实现换源。

## 3. 窗口职责

### 3.1 主窗口

主窗口使用 Ant Design 深色主题，展示：

- 素材信息和完整 SHA-256；
- 播放状态、轮次、播放控制和重新打开播放器按钮；
- 视频处理、声音处理、实时话术幻化三个独立开关；
- 当前参数、自动变化周期、当前周期和下一次变化倒计时；
- 波形、频谱和播放/Worker/研究状态；
- 参数校验、媒体引擎和缓存操作。

所有普通文字使用高对比度主题 Token，正文不低于 16px，状态值和标签有明确视觉层级。

### 3.2 播放窗口

播放窗口通过固定 label `final-effect` 单实例创建。窗口只渲染：

- 一个可见的 `<video>` 元素；
- 一个用于候选音轨的隐藏 `<audio>` 元素；
- 播放必须的媒体控制和错误兜底。

播放窗口不渲染状态卡片、参数表、波形、频谱、Worker 信息或研究面板。播放窗口关闭后，主窗口和播放状态仍可继续工作。

## 4. 状态与跨窗口通信

- Rust `PlaybackCore` 是播放状态的唯一事实源，窗口通过 `get_snapshot` 读取并通过既有 Tauri 命令执行控制。
- 使用浏览器原生 `BroadcastChannel` 建立 `autolive-playback-ui-v1` 通道：
  - 播放窗口发送受限的波形/频谱采样给主窗口；
  - 主窗口发送当前运行时预览参数给播放窗口。
- 通道消息只用于界面预览，不替代 Rust 播放状态，也不传输模型密钥、完整音频或视频文件。
- 组件卸载、窗口关闭和对象创建失败时必须关闭 Channel、取消定时器并释放 AudioContext/对象 URL。

## 5. 连续循环策略

1. `onEnded` 触发时，先本地将视频和候选音频回到 0 秒并调用 `play()`，不等待 IPC 返回。
2. 再异步调用 `complete_playback_loop` 更新 Rust 轮次；调用失败不能阻塞本地循环。
3. 增加 `timeupdate` 末尾检测作为部分 WebView 未可靠派发 `ended` 的兜底，并用 ref 防止一次结束触发两次。
4. 源媒体换源时重置结束门禁；暂停、停止时清理候选音频和本地循环状态。

## 6. 运行时参数自动变化

- 默认周期读取音频参数 `random_change_period_ms`，缺失或非法时使用 5000ms。
- 只有对应的声音处理或视频处理开关打开时，才自动变化对应参数；实时话术幻化仍是独立开关。
- 变化参数以当前用户参数为基线，在契约允许范围内生成有限幅度的可复现周期值；UI 显示周期号和倒计时。
- 当前运行时可真实作用于预览的基础路径：
  - 音频：Web Audio 增益/响度路径；
  - 视频：浏览器预览中的亮度、对比度、饱和度、色相、模糊、缩放和空间偏移。
- 高级参数没有对应运行时 DSP 时显示能力状态，不伪造执行结果；研究 Worker 仍按既有链路处理可生成的研究产物。
- 运行时参数变化只影响当前播放预览，不覆盖原始 MP4，不产生离线版本。

## 7. 验收标准

- 主窗口所有文字在深色主题下可读，标签和值不再出现黑字深底。
- 导入视频后最多存在一个 `final-effect` 播放窗口；重复点击只显示并聚焦现有窗口。
- 播放窗口只显示播放器，参数和诊断信息全部在主窗口。
- 视频播放结束后自动继续下一轮，连续播放不因 `complete_playback_loop` 失败而停住。
- 开启视频/声音处理后，主页可以观察到周期、周期号和当前参数变化；关闭对应开关后停止对应变化。
- 主窗口能收到播放窗口的波形/频谱数据；播放窗口关闭或通信不可用不影响视频播放。
