# 服务端镜像部署与桌面端控制面切换实施计划

> 当前版本范围声明（2026-08-19）：本版本不开发实时话术幻化。本文中的“保持实时话术幻化逻辑不变”只表示部署计划不扩展该历史/后续能力；speech-to-speech、模型直连和候选换轨不属于当前部署实施或验收范围。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 在本地构建 `linux/amd64` 的 Go 后端和 React 管理端镜像，上传到 `192.168.100.213` 部署，并让 Rust/Tauri 桌面端的控制面请求统一访问 `http://192.168.100.213:18090`。

**架构：** 使用 `autolive-admin` Nginx 容器作为唯一宿主机入口，静态提供 React 管理端并将 `/api/*` 反向代理到 Docker 内网中的 `autolive-api:8080`。Go API 和一次性迁移容器加入服务器现有 `shared-net`，通过 `postgres-shared:5432` 访问新建的 `autolive_control_plane` 数据库；镜像和构建产物全部在本地生成，服务器只负责加载和运行。

**技术栈：** Go 1.22、多阶段 Docker 构建、React 19、Vite、pnpm、Nginx、Docker Compose、PostgreSQL 现有 `postgres-shared`、Rust/Tauri 2、Tauri HTTP 插件。

## 全局约束

- 统一入口固定为 `http://192.168.100.213:18090`；不占用服务器现有 `8080`、`18080`、`18081`、`18082`。
- 后端 API 只在 Docker 内部监听 `:8080`，不发布宿主机 API 端口。
- PostgreSQL 使用现有外部网络 `shared-net` 和服务名 `postgres-shared:5432`，不新建 PostgreSQL 容器，不暴露新的数据库端口。
- 镜像目标平台为 `linux/amd64`；服务器禁止执行 Go、pnpm 或 Docker 构建。
- 数据库迁移必须由 `backend/cmd/migrate` 显式执行，API 只做版本一致性检查。
- 数据库密码、应用密钥、初始管理员密码、模型供应商密钥不得写入代码、Dockerfile、镜像层、日志或仓库。
- React 管理端继续使用 Ant Design 现有组件和同源 `/api`，不重写请求工具，不覆盖 Ant Design 内部样式。
- 桌面端不修改播放器、媒体处理和 FFmpeg，只修改控制面地址配置和 Tauri HTTP 权限；实时话术幻化本版本不开发，相关历史/后续逻辑不属于本计划实施范围。
- 不使用 Git worktree；当前工作区没有 Git 元数据，本计划用文件检查、测试和部署检查点代替提交。
- 每个任务完成后清理本次改动产生的未使用导入、类型、配置、脚本和构建产物引用。

### 任务 1：建立部署配置契约

**文件：**

- 新建：`deploy/docker-compose.yml`
- 新建：`deploy/.env.example`
- 新建：`deploy/初始化数据库.sql`

**接口：**

- 消费：`backend` 镜像中的 `/usr/local/bin/autolive-api` 和 `/usr/local/bin/autolive-migrate`。
- 生产：服务名 `autolive-api`、`autolive-migrate`、`autolive-admin`；API 内部地址 `http://autolive-api:8080`；数据库内部地址 `postgres://...@postgres-shared:5432/autolive_control_plane?sslmode=disable`。

- [ ] **步骤 1：写入 Compose 配置**

`deploy/docker-compose.yml` 使用以下关键结构：

```yaml
name: autolive

x-app-environment: &app-environment
  APP_ADDR: ${APP_ADDR}
  APP_VERSION: ${APP_VERSION}
  APP_STORAGE_MODE: ${APP_STORAGE_MODE}
  APP_MODEL_READ_SOURCE: ${APP_MODEL_READ_SOURCE}
  APP_DATABASE_URL: ${APP_DATABASE_URL}
  APP_SECRET_ENCRYPTION_KEY: ${APP_SECRET_ENCRYPTION_KEY}
  APP_ADMIN_USERNAME: ${APP_ADMIN_USERNAME}
  APP_ADMIN_PASSWORD: ${APP_ADMIN_PASSWORD}

x-migrate-environment: &migrate-environment
  APP_STORAGE_MODE: ${APP_STORAGE_MODE}
  APP_DATABASE_URL: ${APP_DATABASE_URL}

services:
  autolive-migrate:
    image: ${AUTOLIVE_API_IMAGE}
    environment: *migrate-environment
    command: ["/usr/local/bin/autolive-migrate"]
    restart: "on-failure:5"
    networks:
      - shared-net

  autolive-api:
    image: ${AUTOLIVE_API_IMAGE}
    environment: *app-environment
    depends_on:
      autolive-migrate:
        condition: service_completed_successfully
    restart: unless-stopped
    expose:
      - "8080"
    healthcheck:
      test: ["CMD-SHELL", "wget -q -O - http://127.0.0.1:8080/api/v1/health >/dev/null"]
      interval: 30s
      timeout: 5s
      retries: 5
      start_period: 10s
    networks:
      - shared-net

  autolive-admin:
    image: ${AUTOLIVE_ADMIN_IMAGE}
    depends_on:
      autolive-api:
        condition: service_healthy
    ports:
      - "18090:80"
    restart: unless-stopped
    networks:
      - shared-net

networks:
  shared-net:
    external: true
    name: shared-net
```

不要添加宿主机 `8080:8080`、`5433:5432` 或任何现有服务端口映射。

- [ ] **步骤 2：写入 `.env.example`**

文件只列出变量名和非敏感说明，内容至少包括：

```dotenv
AUTOLIVE_API_IMAGE=autolive-api:20260814-01
AUTOLIVE_ADMIN_IMAGE=autolive-admin:20260814-01

APP_ADDR=:8080
APP_VERSION=20260814-01
APP_STORAGE_MODE=postgres
APP_MODEL_READ_SOURCE=snapshot
APP_DATABASE_URL=postgres://autolive_app:REPLACE_ON_SERVER@postgres-shared:5432/autolive_control_plane?sslmode=disable
APP_SECRET_ENCRYPTION_KEY=REPLACE_WITH_64_HEX_CHARACTERS
APP_ADMIN_USERNAME=REPLACE_WITH_ADMIN_USERNAME
APP_ADMIN_PASSWORD=REPLACE_WITH_ADMIN_PASSWORD
```

服务器实际 `.env` 必须由部署人员在服务器上创建并设置 `chmod 600`，不能从该模板直接启动生产服务。

- [ ] **步骤 3：写入幂等数据库初始化 SQL**

`deploy/初始化数据库.sql` 不保存密码，由 `psql -v` 注入变量；逻辑必须等价于：

```sql
SELECT format('CREATE ROLE %I LOGIN PASSWORD %L', :'app_db_user', :'app_db_password')
WHERE NOT EXISTS (SELECT 1 FROM pg_roles WHERE rolname = :'app_db_user')\gexec

SELECT format('CREATE DATABASE %I OWNER %I', :'app_db_name', :'app_db_user')
WHERE NOT EXISTS (SELECT 1 FROM pg_database WHERE datname = :'app_db_name')\gexec

SELECT format('ALTER DATABASE %I OWNER TO %I', :'app_db_name', :'app_db_user')\gexec

SELECT format('GRANT CONNECT ON DATABASE %I TO %I', :'app_db_name', :'app_db_user')\gexec
```

数据库名固定为 `autolive_control_plane`，应用账号固定为 `autolive_app`；首次创建时通过变量注入密码，后续密码轮换必须作为显式运维步骤同时更新数据库角色和服务器 `.env`。

- [ ] **步骤 4：做静态检查**

运行：

```bash

rg -n '8080:8080|5433:5432|18080|18081|18082|latest' deploy
```

预期：Compose 配置可以解析；第二条命令没有输出。`.env.example` 中的 `REPLACE_` 只允许出现在模板，不得出现在服务器 `.env`。

- 生产：`/usr/local/bin/autolive-api`、`/usr/local/bin/autolive-migrate`，容器内监听 `:8080`。

- [ ] **步骤 1：先验证 Go 代码基线**

```bash

```

预期：现有 Go 单元测试全部通过。若失败，先修复或记录与镜像无关的基线问题，不在 Dockerfile 中绕过测试。

- [ ] **步骤 2：写入多阶段 Dockerfile**

`backend/Dockerfile` 使用 Go 构建阶段和带 CA/`wget` 健康检查能力的精简运行阶段，核心内容如下：

```dockerfile
FROM --platform=$BUILDPLATFORM docker.1ms.run/library/golang:1.22-alpine AS build

WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .

ARG TARGETOS
ARG TARGETARCH
RUN CGO_ENABLED=0 GOOS=${TARGETOS} GOARCH=${TARGETARCH} \\
    go build -trimpath -ldflags='-s -w' -o /out/autolive-api ./cmd/server && \\
    CGO_ENABLED=0 GOOS=${TARGETOS} GOARCH=${TARGETARCH} \\
    go build -trimpath -ldflags='-s -w' -o /out/autolive-migrate ./cmd/migrate

FROM docker.1ms.run/library/alpine:3.20
RUN apk add --no-cache ca-certificates wget
COPY --from=build /out/autolive-api /usr/local/bin/autolive-api
COPY --from=build /out/autolive-migrate /usr/local/bin/autolive-migrate
USER 65532:65532
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=5s --start-period=10s --retries=5 \\
  CMD wget -q -O - http://127.0.0.1:8080/api/v1/health >/dev/null || exit 1
CMD ["/usr/local/bin/autolive-api"]
```

迁移服务通过 Compose 覆盖 `CMD`，不再额外构建第二个镜像；迁移容器只注入数据库连接相关变量。

```bash
pnpm --dir admin-web build
```

预期：类型检查、认证/号池现有测试和 Vite 构建全部通过。

- [ ] **步骤 2：写入 Nginx 配置**

`admin-web/nginx.conf` 使用公开配置，不覆盖 Ant Design 样式：

```nginx
server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    location /api/ {
        proxy_pass http://autolive-api:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Request-Id $http_x_request_id;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

`proxy_pass` 不追加 URI 后缀，确保 `/api/v1/...` 原样转发到 Go 路由。

```dockerfile
FROM docker.1ms.run/library/nginx:1.27-alpine

COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

构建时保持 `VITE_API_BASE_URL` 为空，管理端通过浏览器当前来源请求 `/api`。
