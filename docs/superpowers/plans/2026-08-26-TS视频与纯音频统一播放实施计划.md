# TS 视频与纯音频统一播放实施计划

> 日期：2026-08-26  
> 范围：Rust/Tauri 桌面客户端与 React 桌面界面  
> 非范围：Go 控制面、管理系统、服务端媒体任务、实时话术幻化、RTMP/OBS、源文件覆盖

## 1. 背景与现状

桌面端当前已经在文件选择器、Rust 扩展名白名单和 FFprobe 探测入口中接受 `.ts` 与 `.m2ts`，但探测成功后仍将原始文件路径直接交给 WebView `<video>`。目标 WebView 对 MPEG-TS 容器及其中的编码组合没有稳定直放保证，因此当前只能称为“可选择、可探测”，不能称为“可稳定播放”。

当前 FFprobe 导入逻辑强制要求至少一个视频轨道，播放池 DTO 也没有媒体类型和兼容播放引用，因此 `mp3`、`wav`、`m4a`、`aac`、`ogg`、`flac` 等纯音频不能进入播放池。最终效果窗口已经使用 `<video>` 承担播放、暂停、时间、结束事件和顺序循环时钟；HTML 媒体元素本身可以播放只有音频轨道的兼容资源，因此本次不新建第二套播放器。

## 2. 目标

1. `.ts`、`.m2ts` 源视频在导入后具备稳定的 WebView 兼容播放引用；源文件保持只读。
2. 播放池升级为最多 100 项的本地有序媒体池，允许视频和纯音频混排。
3. 纯音频首版支持 `mp3`、`wav`、`m4a`、`aac`、`ogg`、`flac`。
4. 纯音频播放时最终效果窗口保持纯黑，不显示封面、波形、占位图片或上一视频残帧。
5. 当前项为纯音频时不启动视频处理和画中画；普通声音处理、插话、固定话术、静音、音量、暂停、继续、停止和顺序循环继续复用现有能力。
6. 整批替换、追加和单项替换继续遵守“全部探测和兼容准备成功后才原子提交”；失败或取消保留旧池。

## 3. 非目标

- 不把音频包装成带静态图片的视频。
- 不新增云端转码、服务端上传、媒体任务或持久化播放池。
- 不为所有历史容器承诺任意编码均可播放；只对 FFmpeg 可解码且兼容准备成功的 TS/M2TS 承诺播放。
- 不恢复实时话术幻化、speech-to-speech、VAD/ASR/LLM/TTS 或候选音轨换轨。
- 不引入新的媒体依赖；继续复用随包 FFmpeg、FFprobe、PortAudio 和现有 H.264 编码器降级逻辑。

## 4. 产品行为

### 4.1 统一媒体池

- 文件选择器标题和操作文案从“视频”调整为“媒体”。
- 视频格式保持：`mp4`、`mov`、`mkv`、`avi`、`webm`、`m4v`、`ts`、`m2ts`、`flv`、`wmv`、`3gp`。
- 音频格式增加：`mp3`、`wav`、`m4a`、`aac`、`ogg`、`flac`。
- FFprobe 以真实流为准：存在非封面视频流时为 `video`；只有音频流或只有音频流加 `attached_pic` 封面时为 `audio`；无可用音视频流时拒绝。
- 视频、音频可以混排，仍按 `A → B → … → A` 循环，单项池自循环。

### 4.2 TS 兼容准备

1. FFprobe 读取容器、视频/音频编码、时长和流类型。
2. H.264 + AAC 等兼容组合优先使用 FFmpeg 快速封装到 MP4，不执行视觉效果处理。
3. WebView 不可靠的编码组合使用现有 H.264 编码器选择与降级逻辑转为 H.264 + AAC。
4. 输出写入应用缓存中的 `.partial.mp4`，经 FFprobe 验证非空、可读、包含所需流后原子提交。
5. 缓存引用与源路径分离；普通声音处理继续从原始源文件解码。
6. 候选批次失败、取消或被新操作取代时清理本批暂存/完成缓存，不修改现有播放池。

兼容封装不属于视频效果输出，因此允许在确认编码兼容时使用 stream copy；视频处理开关开启后的正式效果产物仍必须重新编码视频。

### 4.3 纯音频播放

- 源 DTO 增加 `media_kind`、`playback_reference` 和 `compatibility_mode`。
- 最终效果窗口继续使用现有主 `<video>` 作为统一媒体时钟；音频项将渲染表面透明，露出纯黑容器，防止封面和上一帧泄漏。
- 音频项不请求按视频宽高调整窗口，使用最终效果窗口默认尺寸。
- 当前项为音频时，视频处理状态为 `not_applicable`，视频参数应用和画中画不可用；全局视频开关值可以保留，切回视频项后继续生效。
- PortAudio 开启时继续从 `source_path` 读取源音频；关闭或失败时由 WebView 主媒体元素播放音频。

## 5. 模块与文件职责

### Rust/Tauri

- `desktop/src-tauri/src/media_library/mod.rs`
  - 统一媒体扩展名白名单。
  - 增加媒体类型、兼容模式和播放引用字段。
  - 识别真实视频流、音频流及 `attached_pic`。
- `desktop/src-tauri/src/media_compatibility.rs`
  - 构建 TS 快速封装或转码参数。
  - 管理超时、取消、隐藏子进程、暂存文件、FFprobe 校验和原子提交。
  - 只负责播放兼容准备，不包含媒体效果算法。
- `desktop/src-tauri/src/media_engine.rs`
  - 复用或最小公开现有 H.264 编码器选择、进程执行和产物探测能力。
- `desktop/src-tauri/src/lib.rs`
  - 统一媒体池状态与切项。
  - 音频项的视频处理状态和播放引用复位规则。
- `desktop/src-tauri/src/commands.rs`
  - 批量探测后串行准备必要兼容缓存。
  - 保持整批原子提交和播放池编辑停止/释放语义。
  - 只允许已规范化源路径和受控应用缓存路径进入资产作用域。

### React/Tauri UI

- `desktop/ui/src/App.tsx`
  - 统一媒体文件选择器和 IPC DTO 校验。
  - 按 `media_kind` 选择源路径、纯黑音频渲染、视频处理/PiP 门禁。
  - 保留现有结束事件、顺序切项和 PortAudio 同步逻辑。
- `desktop/ui/src/desktop/playback-pool-panel.tsx`
  - “视频”文案改为“媒体”。
  - 视频展示分辨率/帧率；音频展示采样率/声道。

## 6. 错误、取消与资源生命周期

- 单文件探测沿用现有有界 FFprobe 输出和超时。
- TS 兼容任务必须有拥有者、取消令牌、总超时和 Join；不丢弃后台任务。
- 播放池编辑、清空、窗口关闭和应用退出必须停止相关媒体任务，并保护仍被当前播放池引用的缓存。
- 任一候选失败时保留旧播放池，错误定位到具体文件及阶段，不提交部分成功项。
- `.partial`、失败产物和无引用兼容缓存纳入现有本地缓存清理边界，不扩大删除目录。

## 7. 测试与验收

### 自动化

- Rust 单元测试：扩展名、音频流、封面流、无流、TS 参数选择、输出校验和取消清理。
- Rust 播放状态测试：视频/音频混排、单项音频循环、音频项视频状态、重复结束事件幂等。
- React 测试：统一选择器、DTO 校验、音频元数据、纯黑渲染、PiP/视频处理门禁和混合切项。
- 运行 `cargo fmt --all -- --check`、受支持组合的 `cargo clippy`、`cargo test`、`cargo check`。
- 运行桌面 UI 类型检查和测试；不在服务器构建。

### Windows 实机

- TS：H.264/AAC、MPEG-2/MP2、无音轨、损坏文件。
- 音频：六种白名单格式、带封面音频、无效扩展名、损坏文件。
- 混合池：视频 → 音频 → 视频，验证两轮完整循环。
- 验证音频期间无封面、无上一帧、无新弹窗、无视频处理、无 PiP。
- 验证普通声音、插话、固定话术、静音、音量、暂停、继续、停止、删除、替换、清空和取消。

## 8. 实施顺序

1. 先补充媒体模型、FFprobe 分类和失败测试。
2. 实现 TS 兼容封装/转码与原子缓存提交。
3. 接入播放核心和命令层，保证混合池与资源释放。
4. 接入 React 选择器、播放池展示和纯音频黑屏。
5. 同步产品/架构文档，执行自动化检查和 Windows 手工验收。

## 9. 回滚边界

- 源文件从不修改，无数据迁移。
- 回滚代码后删除应用缓存中的兼容产物即可，不影响用户源媒体。
- 播放池只存在当前进程，不需要兼容持久化数据。
