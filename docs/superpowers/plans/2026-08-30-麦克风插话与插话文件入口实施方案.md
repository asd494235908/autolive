# 麦克风插话与插话文件入口实施方案

> 状态（2026-08-30）：方案已确认，尚未实施代码、依赖、IPC、权限或 UI。本文件是该功能后续开发、审查和验收的唯一实施入口；没有真实运行证据前不得标记为“已接入/已生效”。

> 范围澄清：本文的 VAD 只判断本地麦克风帧中“有人声/无人声”，用于控制麦克风门控和主媒体静音。它不识别、转写、理解或改写用户说话，不接入 ASR、LLM、TTS、speech-to-speech、实时变声、候选音轨换轨或模型租约，因此不属于实时话术幻化。

## 1. 决策

采用一条本地、单进程、单音频出口的实现路线：

- 保留现有文件插话实现和语义，只把用户入口“随机插话”统一改名为“插话文件”。
- 在“声音功能”区域新增独立的“麦克风插话”入口。
- 麦克风插话启用后，主媒体和麦克风统一通过 PortAudio 输出，不允许主媒体走 WebView、麦克风走另一出口。
- 复用当前 vendored PortAudio，扩展为 Windows 全双工输入/输出和输入设备枚举；不再引入 CPAL 等第二套设备抽象。
- 第一版语音前端使用成熟的 SpeexDSP：AEC 回声消除、噪声抑制、可选 AGC 和 VAD。不得自行实现 AEC、降噪或 VAD 算法。
- 麦克风只做通话级清理和限幅，不进入现有音高、共振峰、声音预设或随机音效链。
- VAD 检测到用户说话时，主媒体音轨使用真正的 `gain = 0` 数字静音；停止说话后有界保持并平滑恢复。
- 麦克风实时叠加必须发生在 PortAudio 硬件回调前的低延迟末端，不能进入当前 `200–500ms` 主媒体预缓冲链。
- 功能只存在 Rust/Tauri 桌面进程，不新增 Go API、数据库、上传、录音文件、管理端页面或服务器构建步骤。

## 2. 目标与非目标

### 2.1 目标

- 首页“随机插话”按钮、抽屉标题和相关用户文案改为“插话文件”，现有随机目录和周期行为保持不变。
- 用户可以选择本机麦克风，主动开始或停止监听。
- 播放中的用户说话可触发麦克风插话；视频画面和播放时间轴继续前进。
- 用户说话期间只保留麦克风插话声音，主媒体、文件插话和固定话术均不可听。
- 处理扬声器回授、环境噪声、设备拔插、权限拒绝、暂停/继续、停止、换源和应用退出。
- 展示真实的设备、监听、说话、故障和恢复状态，不把配置成功伪装成已实际采集或输出。
- 保留当前 PortAudio 可听时钟和 mpv 音画同步身份，不让麦克风支路改写媒体源 PTS。

### 2.2 非目标

- 不做语音识别、字幕、关键词、唤醒词、说话内容记录或上传。
- 不做 speech-to-speech、实时变声、声音克隆、ASR/LLM/TTS 或模型调用。
- 不做录音、回放、音频文件导出、直播推流、OBS/RTMP 或平台接入。
- 不把麦克风状态、设备名或音频发送给 Go 控制面。
- 不支持多个麦克风同时混合，不支持跨主机音频，不承诺专业声卡的硬件直通监听。
- 第一版不把 WebView `getUserMedia` 作为 PortAudio 失败回退；跨出口无法保证回声参考、时序和真正的主轨静音。
- 不顺带重构现有文件插话、固定话术、普通声音候选或视频主链。

## 3. 当前仓库事实

- 首页当前只有一个“随机插话”按钮和同名抽屉，入口在 `desktop/ui/src/App.tsx`。
- 文件插话已经支持本地目录扫描、随机周期、声音预设、WebView/PortAudio 双出口和主媒体 ducking。
- `InterludeConfig` 当前允许 `ducking_depth_db = -60..0dB`，默认 `-60dB`；该语义继续只属于文件插话。
- `audio_cycle_output.rs` 已有文件插话 attack/sustain/release 包络及主轨混音，不应复制第二份文件插话状态机。
- `autolive-portaudio-output` 当前只暴露输出设备和输出流；FFI 结构已经包含 `max_input_channels` 和回调输入指针，但打开流时传入空的 input parameters。
- 当前主媒体 PortAudio 预缓冲水位为 `200–500ms`，用于抵抗 Windows 调度抖动。麦克风若在该缓冲之前混入，会造成不可接受的现场延迟。
- PortAudio callback 已承担最终硬件消费并上报 DAC 时间，适合作为主媒体静音和低延迟麦克风末端混音的唯一位置。
- 当前固定话术会暂停文件插话；新增麦克风后需要统一音频优先级，不能靠多个 React Effect 互相抢状态。

## 4. 用户交互契约

### 4.1 首页入口

“声音功能”区域显示两个并列 Ant Design 按钮：

- `插话文件`：打开现有文件插话抽屉。
- `麦克风插话`：打开新的麦克风插话抽屉。

现有“随机插话”相关用户文案统一调整：

- 抽屉标题改为“插话文件”。
- “启用随机插话”改为“启用插话文件”。
- 随机行为在字段说明中表达，例如“文件触发周期”“随机选择文件”，不再作为功能名称。
- 内部 Rust/TypeScript 的 `interlude` 命名本轮不强制重命名，避免无收益的大范围迁移。

### 4.2 麦克风抽屉

抽屉宽度沿用文件插话的 `560px` 且不超过 `100vw`，使用 Ant Design 公开组件和现有 `FeatureDrawer` 布局，不覆盖 `.ant-*` 内部样式。

第一版只提供：

- 麦克风设备选择，包含“系统默认设备”。
- `开始监听` / `停止监听` 主操作。
- 输入电平、实际采样率、实际 Host API 和设备状态。
- 监听状态：`未监听`、`正在打开`、`监听中`、`检测到说话`、`正在停止`、`故障`。
- VAD 灵敏度：`低`、`标准`、`高`，默认“标准”；UI 只保存档位，不直接暴露算法内部概率常量。
- AEC、噪声抑制和 AGC 的真实运行状态。
- 明确隐私提示：“音频仅在本机内存中处理，不录音、不上传”。

持久化规则：

- 可以保存设备 ID、灵敏度和清理选项。
- 不保存“正在监听”状态；应用每次启动后必须由用户主动开始监听。
- 保存的设备消失时显示失效状态，不静默切换到另一个真实设备；用户选择“系统默认设备”时才允许跟随系统默认值。

### 4.3 播放与优先级

运行优先级固定为：

`麦克风说话 > 固定话术 > 插话文件 > 主媒体`

- 麦克风进入说话态时，立即停止当前文件插话和固定话术，不从中间恢复；两者按各自规则等待下一次显式或周期触发。
- 主媒体画面、播放池顺序、`playback_generation`、`loop_index` 和媒体 PTS 不改变。
- 麦克风退出说话态后只恢复主媒体；不会自动重启刚才被打断的文件插话或固定话术。
- 播放暂停时挂起采集和 VAD；继续播放后重新进入监听态。
- 停止、清空播放池、换源、最终窗口关闭或应用退出时停止麦克风流并 Join 所有任务。

## 5. 音频数据路径

```text
主媒体 PCM ring ───────────────────────────────┐
                                               │
麦克风硬件输入 → input SPSC → DSP Worker ──────┼→ PortAudio callback → DAC
                         │                     │
                         └→ clean mic SPSC ────┘

PortAudio 实际 render PCM + ADC/DAC 时间戳 → render reference SPSC → AEC
VAD 原子状态 → callback 内主媒体 gain 包络（Speaking 时收敛到 0）
```

### 5.1 PortAudio callback

callback 是唯一最终混音点，只允许执行：

- 从现有主媒体 SPSC 取样。
- 把麦克风输入和 `inputBufferAdcTime` 写入有界 input SPSC。
- 从 clean mic SPSC 取已处理麦克风帧。
- 根据原子 VAD 状态推进主媒体静音/恢复包络。
- 执行有限值收敛、乘法、加法、限幅并写 output buffer。
- 把实际 render 参考和 `outputBufferDacTime` 写入有界 reference SPSC。
- 更新 callback、input overflow、output underflow、producer drop 和延迟原子指标。

callback 禁止：

- 分配内存、加互斥锁、等待 Channel、访问文件、调用 Tauri 或记录普通日志。
- 运行 SpeexDSP、重采样、设备枚举、状态序列化或任何可能阻塞的系统 API。
- 因麦克风样本不足而停止主媒体消费。

### 5.2 麦克风 DSP Worker

Worker 由一个明确的 `MicrophoneInterludeSession` 所有，处理固定大小的小帧：

1. 从 input SPSC 读取麦克风帧。
2. 按 ADC/DAC 时间戳匹配实际 render 参考。
3. 执行 SpeexDSP AEC。
4. 执行噪声抑制和可选 AGC。
5. 执行 VAD，经过启动门限、继续门限和 hangover 状态机得到稳定说话态。
6. 只在说话态向 clean mic SPSC 写清理后的麦克风 PCM；非说话态写静音或不写，由 callback 按既定规则处理。
7. 通过有界状态通道向 Tauri actor 发布低频摘要，不能逐帧向 React 发事件。

建议首版内部参数基线：

- 目标采样率：优先 `48kHz`；打开前必须使用 `Pa_IsFormatSupported` 验证输入/输出组合。
- DSP 帧：`10–20ms`，以 SpeexDSP 实际配置为准。
- VAD 启动：连续短窗确认，目标 `20–60ms` 内进入说话态。
- 尾音保持：默认 `400ms`，允许在内部常量级校准，不作为第一版高级 UI 参数。
- 主轨静音 attack：目标不超过 `50ms`。
- 主轨恢复 release：默认 `250ms`。
- 麦克风启动阶段不使用长 pre-roll，避免把现有低延迟路径重新变成高延迟监听；首音截断通过短窗门限和实机校准解决。

### 5.3 数字静音语义

文件插话继续使用可配置 `ducking_depth_db`。

麦克风插话使用独立的 `MuteWhileSpeaking` 语义：

- `Speaking` 稳态主媒体增益必须是精确 `0.0`，不能用 `-60dB` 冒充“只保留麦克风”。
- attack/release 只控制到 `0.0/1.0` 的过渡时间。
- callback 或 DSP 故障必须 fail-open：立即恢复主媒体增益到 `1.0`，停止麦克风会话，禁止卡在静音。

## 6. 开源依赖决策

### 6.1 保留 PortAudio

- 当前仓库已有 vendored PortAudio、Windows DLL、许可证、输出设备、SPSC callback 和健康状态。
- PortAudio 官方支持 input-only、output-only 和 full-duplex stream；全双工使用同一采样率并提供 ADC/DAC callback 时间。
- 扩展现有封装比并存 CPAL/WASAPI 第二套设备栈更小，也能保留当前可听时钟。

### 6.2 新增 SpeexDSP

选择 SpeexDSP 的原因：

- 同一成熟库提供 AEC、噪声抑制、AGC、残余回声抑制和 VAD。
- 支持 `10–20ms` 小帧及麦克风/扬声器参考输入。
- BSD-3-Clause 类许可证允许随桌面产品分发，必须附带版权和免责声明。
- 仓库有 Windows 构建目录，依赖体积和运行成本明显小于完整 WebRTC C++ 栈。

接入门禁：

- 实现前固定来源 commit/tag、二进制哈希、许可证文本、构建命令、编译器和目标架构。
- 只能在本地开发机或 CI 构建，服务器只接收发布产物。
- 以独立 Rust Crate 封装最小 FFI 和 RAII；主 crate 继续 `unsafe_code = "forbid"`。
- 新增 `unsafe` 必须记录指针、帧长度、线程归属、创建/销毁顺序和 callback 外调用不变量。
- 先做离线 AEC/VAD 技术门禁，再进入生产代码；若真实扬声器回声门禁不通过，停止实施并单独评审 WebRTC APM，不在同一版本并存两套 DSP。

### 6.3 暂不选择的方案

- WebRTC APM：能力更现代，但 C++、Abseil、Meson/Ninja、绑定和 Windows 可复现构建成本更高；仅作为 SpeexDSP 实机质量不达标后的替换候选。
- RNNoise：适合降噪，但不能单独提供完整 AEC，不满足扬声器回授门禁。
- Silero VAD：需要模型运行时且仍不解决 AEC，对本需求偏重。
- Sonora：纯 Rust 且宣称支持 Windows，但项目和发布历史较新，暂不承担生产主链。
- WebView `getUserMedia`：无法与当前 PortAudio 可听时钟、render 参考和数字静音形成单一事实源。

- PortAudio 许可证：<https://portaudio.com/license.html>
- SpeexDSP preprocessor/VAD：<https://raw.githubusercontent.com/xiph/speexdsp/master/include/speex/speex_preprocess.h>
- SpeexDSP AEC：<https://raw.githubusercontent.com/xiph/speexdsp/master/include/speex/speex_echo.h>

## 7. 状态模型和契约

### 7.1 Rust 领域状态

建议使用可辨识状态而不是互相矛盾的多个布尔值：

```rust
pub enum MicrophoneInterludeState {
    Disabled,
    Opening,
    Armed,
    Speaking,
    Hangover,
    Stopping,
    Failed,
}

pub enum MicrophoneSensitivity {
    Low,
    Standard,
    High,
}
```

快照至少包含：

- `state`
- 已选择设备的稳定 ID、脱敏显示名和 Host API
- `actual_sample_rate_hz`
- `input_level`
- `speech_probability` 或等价归一化值
- `aec_active`、`noise_suppression_active`、`agc_active`
- `input_overflow_count`、`output_underflow_count`、`dropped_frame_count`
- 稳定错误码和用户可行动的安全错误正文
- 会话 generation，拒绝旧异步响应覆盖新设备或新监听会话

### 7.2 IPC 草案

后续实现前先以测试固定 DTO；名称可在影响面复核后微调，但必须保持命令最小、输入有界：

- `list_portaudio_input_devices`
- `start_microphone_interlude`
- `stop_microphone_interlude`
- `get_microphone_interlude_status`
- `set_microphone_interlude_config`

约束：

- 设备 ID、字符串长度、采样率、灵敏度枚举和配置组合在 Rust 边界校验。
- `start` 使用单飞 + generation；重复相同请求幂等返回当前会话，冲突请求返回稳定 `busy/stale` 分类。
- `stop` 对不存在会话幂等成功，但仍要保证所有资源已经释放。
- 设备打开、停止和 Join 使用有界超时；超时不能假装底层任务已结束。
- React 只展示快照和提交用户意图，不承担逐帧 VAD、音频混音或资源所有权。

## 9. 并发、取消和资源生命周期

- `MicrophoneInterludeSession` 是输入流、DSP Worker、SPSC、状态和取消令牌的唯一所有者。
- PortAudio callback 不持有 Rust 普通引用；安全封装必须保证 callback 停止并确认后才能释放 user data、ring 或 DSP 会话。
- Worker 使用有界 SPSC/Channel；input/reference 过载时丢弃最旧或当前帧的策略必须固定并计数，禁止无界积压追赶历史语音。
- 设备打开、配置切换、停止、播放停止、换源、窗口关闭和应用退出都进入同一个串行 actor，不允许 React 并发直接操作裸资源。
- 切换设备必须先启动候选并验证，再原子提交；无法安全并行打开时，明确采用“停止旧流→打开新流→失败保持未监听”，不能伪装无缝。
- 每个线程有取消信号、退出条件、JoinHandle 和总停止超时；不得丢弃 JoinHandle。
- callback 或 Worker panic/FFI 错误必须使会话失败、主轨恢复、资源回收并上报一次结构化错误。
- 关闭顺序固定为：禁止新请求 → 主轨恢复 → callback 停止 → Worker 取消 → Join → 关闭 PortAudio stream → 销毁 SpeexDSP state → 释放 ring。

## 10. 失败与恢复

| 场景 | 行为 |
| --- | --- |
| 用户拒绝麦克风权限 | 不进入监听；主媒体不变；显示权限操作提示 |
| 无输入设备或格式不支持 | 拒绝启动；列出实际设备/采样率原因；不回退 WebView |
| AEC/VAD 初始化失败 | fail-open 恢复主媒体，停止会话并显示 DSP 错误 |
| 麦克风拔出 | 立即退出 Speaking，恢复主媒体，停止并 Join，状态标记设备丢失 |
| input overflow/reference drop | 计数并丢弃过期帧；达到连续门禁后停止会话，不积压历史音频 |
| clean mic underrun | 当前麦克风帧输出静音；主媒体是否恢复由短门禁决定，禁止永久静音 |
| PortAudio output failure | 沿现有音频后端失败路径处理；麦克风功能立即停止，不能假装仍监听 |
| 暂停播放 | 停止说话态并恢复主轨，挂起采集；继续后重新 Armed |
| 停止/换源/清空 | 取消并回收整个麦克风会话，不跨 playback generation 延续 |
| UI/IPC 超时 | 先查询 generation 和实际状态；结果未知不得重复启动第二个设备流 |

## 11. 隐私与安全

- 监听只能由当前用户显式启动，UI 必须持续显示可见监听指示。
- 麦克风 PCM 只存在有界内存环缓，不写日志、Tracing、错误正文、本地存储、临时文件或崩溃附件。
- 不上传麦克风数据，不调用控制面、模型服务或第三方网络。
- 日志只记录设备 ID 的安全摘要、状态、耗时、采样率、溢出计数和错误分类，不记录完整设备路径或 PCM。
- 设备名来自系统，视为不可信字符串：限制长度、清理控制字符，仅作为文本渲染。
- Tauri IPC 不接受任意设备路径、任意采样率或任意 DSP 参数；全部从枚举和固定范围映射。
- SpeexDSP 二进制和模型（若未来存在）必须列入运行资源哈希和发布清单；第一版不得运行时联网下载。

## 13. 测试与验收

### 13.1 自动测试

- 输入设备枚举：默认设备、指定设备、无设备、重复名称、非法 ID、超长名称。
- 格式门禁：48k 成功、不支持组合、输入/输出 Host API 差异和采样率变化。
- callback：空输入、输入溢出、主媒体欠载、clean mic 欠载、NaN/Inf、clamp、停止竞态。
- DSP：纯静音、纯语音、噪声、远端视频声、双讲、参考延迟、丢帧和状态重置。
- VAD：启动门限、继续门限、hangover、短噪声不触发、句间停顿不抖动。
- 优先级：麦克风抢占固定话术/文件插话，结束后只恢复主媒体。
- 生命周期：重复 start、重复 stop、start/stop 竞态、设备切换、拔插、暂停、换源、关窗和应用退出。
- React：DTO 守卫、旧 generation 拒绝、按钮文案、设备空态、权限错误、监听指示和焦点恢复。
- 回归：麦克风关闭时现有文件插话、普通声音周期、PortAudio 时钟和 WebView 回退行为不变。

### 13.2 实机门禁

- 清洁语音起点到 `Speaking`：目标不超过 `80ms`。
- `Speaking` 后主媒体达到数字静音：目标不超过 `50ms`。
- 麦克风到 DAC 的 P95 端到端延迟：目标不超过 `120ms`；同时记录 P50/P99。
- 主媒体稳态 Speaking 样本必须是精确零增益，不能只按听感判断。
- 默认环境连续播放 30 分钟：误触发目标小于 `1 次/30 分钟`，不得持续锁死 Speaking。
- 正常句间停顿不恢复主媒体；真正结束后约 `400ms + 250ms release` 平滑恢复。
- 扬声器播放高音量视频时 AEC 后不得持续触发 VAD；必须覆盖用户与视频同时发声的双讲场景。
- 30 分钟内 PortAudio input/output xrun 为 `0`，无持续 drop、线程泄漏或增长中的环缓积压。
- 拔出麦克风后 `500ms` 内恢复主媒体并进入可恢复故障态。
- 停止监听、关窗和退出后设备可被其他应用立即打开，进程中无残留 Worker。

## 14. 回滚与兼容

- 功能以“未开始监听”为默认值；未启用时不得改变现有 PortAudio output-only 路径。
- SpeexDSP 或 full-duplex 不可用时只禁用麦克风插话，文件插话、固定话术和主媒体保持原行为。
- 现有 `InterludeConfig`、存储键和文件插话 IPC 保持兼容，不因入口改名迁移内部字段。
- 新配置使用独立版本化存储键；损坏或未知版本时回到未监听默认值并显示可恢复错误。
- 若发布后出现 AEC/VAD 质量问题，可关闭麦克风入口而不删除 PortAudio 输出或文件插话能力。
- 替换 SpeexDSP 为 WebRTC APM 必须作为独立依赖决策和迁移，不在运行时同时保留两套主方案。
