# 桌面运行资源按需下载 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 `v0.1.0` 正式桌面包改为不内置 FFmpeg、固定话术 Worker 和语音模型的轻量安装包，并在首次使用时从 `http://101.96.208.132:7088/autolive-resources/v0.1.0/` 自动、安全、可续传地安装所需资源。

**Architecture:** Node 发布脚本从已经构建好的资源复制出不可变发布树并生成随应用打包的固定清单；Rust 作为资源安装状态和文件校验的唯一所有者，在应用数据目录执行断点下载、整文件校验与原子提交；React 只展示状态并在资源就绪后恢复原来的导入视频或准备人声动作。CI 仍在对应平台构建资源和桌面安装包，但只把轻量安装包上传为应用产物，并用专用 SSH 密钥把资源发布树同步到 Caddy 静态服务器。

**Tech Stack:** Node.js 22 标准库、Rust 2021、reqwest 0.12、sha2 0.11、sysinfo 0.39、Tauri 2、React 18、TypeScript 5.6、Ant Design 5、Caddy、systemd、GitHub Actions。

## Global Constraints

- 正式资源基地址固定为 `http://101.96.208.132:7088/autolive-resources/v0.1.0/`；生产代码不接受 UI、API、服务器响应或环境变量覆盖该地址。
- 正式安装包不得包含 `voice-models`、`voice-worker`、`ffmpeg` 或 `ffprobe` 大文件，只打包当前目标的只读 `runtime-resources.json`。
- 资源只安装到 `<app_data_dir>/runtime-resources/v0.1.0/`；正式版不再从 Tauri `resource_dir()` 查找大资源，开发环境保留现有绝对路径环境变量覆盖。
- 固定话术资源依赖关系是 `media + voice-runtime + voice-models`；首次导入视频只要求 `media`。
- 清单必须固定 `schema_version = 1`、`release = "v0.1.0"`、目标三元组、文件精确大小、64 位小写 SHA-256 和可执行标记。
- HTTP 只允许协议 `http`、主机 `101.96.208.132`、端口 `7088` 和路径前缀 `/autolive-resources/v0.1.0/`；关闭重定向。
- 相对路径拒绝绝对路径、`..`、空段、反斜杠和 Windows 平台前缀；任何文件必须完成精确大小和整文件 SHA-256 校验后才能执行或加载。
- 下载写入 `partial/<sha256>.partial`；合法 `206` 追加，`200` 或不匹配的 `Content-Range` 从头重建；瞬时失败最多重试 3 次；取消保留 partial。
- 下载前必须预留 `缺失文件总大小 + max(512MB, 缺失文件总大小的 10%)`；空间不足时不开始下载。
- 同时只允许一个受监督资源任务；重复请求复用当前状态；应用退出时取消并在有限时间内等待任务结束。
- 本地目录导入仍按内置清单校验并复制到应用数据目录，不能从用户目录原地执行。
- 下载 UI 使用现有 Ant Design 组件，不使用全屏遮罩，不禁止页面滚动；资源就绪后自动恢复被挂起的动作。
- 模型发布树不得包含 Hugging Face `.locks`、日志、`trees` 和已复制到 snapshot 的 `blobs`；只能清理隔离的发布副本，不能修改开发缓存。
- 服务器只接收 Caddy 二进制、静态配置、systemd unit 和已构建资源，不能接收源码或执行 Node、Rust、Python 项目构建。
- CI 部署只能使用专用 SSH 私钥 Secret，不能使用聊天中提供的登录密码；仓库、产物和日志不得出现该密码。
- 不新增 ZIP/TAR 解压依赖，不引入 CDN、多镜像、P2P、自动更新框架或 Go API 文件代理。
- 不改变单视频循环、固定话术生成、插话播放器和最终效果窗口的现有业务语义。
- 所有构建在本地开发机或 GitHub Actions 完成，不在资源服务器构建；不使用 Git worktree。

```js
export const RESOURCE_RELEASE = 'v0.1.0';
export const RESOURCE_BASE_URL = 'http://101.96.208.132:7088/autolive-resources/v0.1.0';

export function buildRuntimeResourceRelease({
  target,
  sourceRoot = join(desktopRoot, 'src-tauri'),
  outputRoot = join(desktopRoot, 'resource-release'),
  manifestPath = join(desktopRoot, 'src-tauri', 'runtime-resources.json'),
} = {}) {
  assertSupportedTarget(target);
  const files = copyComponentFiles({ target, sourceRoot, outputRoot });
  const manifest = {
    schema_version: 1,
    release: RESOURCE_RELEASE,
    target,
    base_url: RESOURCE_BASE_URL,
    files: files.sort((left, right) => left.relative_path.localeCompare(right.relative_path)),
  };
  writeJsonAtomically(manifestPath, manifest);
  return { manifestPath, releaseRoot: join(outputRoot, 'autolive-resources', RESOURCE_RELEASE), manifest };
}
```

实现必须使用 Node 标准库 `cpSync`、`readdirSync`、`createHash('sha256')`、`renameSync`，只从隔离副本删除目录名 `.locks`、`trees`、`blobs` 和日志文件；每个清单条目路径以 `{target}/` 或 `common/` 开头，媒体和 Worker 标记 `executable: true`，模型标记 `false`。

- [ ] **Step 4: 实现 forced-command dispatcher、不可覆盖发布命令和公网验证器**

部署密钥只绑定一个 forced-command dispatcher。dispatcher 禁止普通登录 shell，不使用 `eval`，只接受以下两类 `SSH_ORIGINAL_COMMAND`：

- rsync 接收端命令必须是 `rsync --server ... <release>/<scope>/`，其中 release 和 scope 通过固定格式/白名单校验；随后保持原始命令并执行 `exec /usr/bin/rrsync -wo /fs/autolive-resources-staging`，由系统成熟 rrsync 把写入限制在 staging 根目录。
- 只允许精确的 `publish-runtime-resources <release> <scope>`，release 必须符合版本格式，scope 只能是 `common` 或三个目标三元组；其他命令统一退出 64。

publisher 必须使用 `flock` 获取按 release 划分的发布锁，再检查目标不存在并原子移动；CI 的 job-level concurrency 只减少同版本并发，不能替代服务端发布锁。

```sh
#!/bin/sh
set -eu
set -f
set -- ${SSH_ORIGINAL_COMMAND:-}
test "$#" -eq 3
test "$1" = "publish-runtime-resources"
release="$2"
target="$3"
case "$release" in v[0-9]*.[0-9]*.[0-9]*) ;; *) exit 64 ;; esac
case "$target" in x86_64-apple-darwin|aarch64-apple-darwin|x86_64-pc-windows-msvc|common) ;; *) exit 64 ;; esac
source_dir="/fs/autolive-resources-staging/$release/$target"
destination="/fs/autolive-resources/autolive-resources/$release/$target"
test -d "$source_dir"
test ! -e "$destination"
install -d "$(dirname "$destination")"
mv "$source_dir" "$destination"
```

验证器使用 Node `fetch`：HEAD 核对长度；GET 计算 SHA-256；`Range: bytes=0-15` 必须收到 206、正确 Content-Range 和 16 字节；越界 Range 必须收到 416。
