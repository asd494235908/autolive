# 导入视频后自动准备人声与替换按钮修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复固定话术“准备人声”完成后替换按钮仍不可用的问题，并让导入 MP4 后在后台自动完成声音提取、语音识别、参考人声和 XTTS-v2 准备。

**Architecture:** 保留现有 Rust/Tauri → 本地 Voice Clone Worker 的处理链，不改视频处理、普通声音处理或实时音频幻化。React 监听当前源视频的完整 SHA-256 状态，哈希完成且 Worker 可用时只自动触发一次现有 `prepare_voice_clone_source` 命令；Rust 快照轮询继续作为准备进度和完成状态的唯一来源。替换按钮的禁用判断抽成可测试的纯函数，确保 `ready + 播放中 + 播放位置已同步` 时可用。

**Tech Stack:** React + TypeScript、Node `node:test`、TypeScript transpile test harness、Rust/Tauri、现有 Demucs/faster-whisper/XTTS-v2 本地 Worker。

## Global Constraints

- 保持单个源 MP4、单窗口循环播放；不生成 N 个 MP4、不建立话术版本队列。
- 导入视频后首项立即原声播放；人声准备异步执行，失败时只显示固定话术错误，原视频继续播放。
- 同一源视频使用现有 SHA-256 缓存；重新导入同一文件允许命中缓存，不重复执行耗时处理；切换源视频必须清理旧代际状态。
- 不改变视频处理、普通声音处理、实时音频幻化、插话和最终效果窗口的既有行为。
- 前端 Effect 必须有完整依赖和清理；自动触发必须有稳定去重键，不能在轮询中重复启动 Worker。
- 新增行为先写能失败的测试；交付前运行前端测试、构建、Rust 格式化、Clippy 和测试。
- 只修改与本功能直接相关的文件，保留当前工作区中其他已有修改，不使用 Git worktree，不在服务器构建。

## Task 2: 导入源视频后自动触发准备并接通替换按钮

**Files:**
- Modify: `desktop/ui/src/App.tsx`

**Interfaces:**
- Consumes Task 1 的 `getVoiceCloneAutoPrepareKey` 和 `shouldAutoPrepareVoiceCloneSource`。
- Uses existing Tauri commands: `probe_local_mp4`、`start_playback`、`prepare_voice_clone_source`、`get_snapshot`。
- Does not change Worker request schema or playback/audio processing commands。

- [ ] **Step 1: 写集成边界测试/静态失败测试**

在 `desktop/ui/src/voiceCloneStatus.test.mjs` 增加源码契约断言，确保主界面包含 `prepare_voice_clone_source` 自动调用和以 `mp4_hash_status === 'ready'` 为触发前提；先运行测试，当前源码应失败。

- [ ] **Step 2: 实现自动触发**

在 `DesktopApp` 增加 `useRef<string | null>` 去重键。Effect 依赖当前快照的源路径、SHA-256、哈希状态、播放代际、Worker available 和固定话术状态：

1. 通过 Task 1 函数计算代际去重键。
2. 只有 `ready + Worker available + idle + 未触发` 才写入 ref 并调用现有准备函数。
3. 自动调用失败不设置全局播放错误；Rust 快照进入 `failed` 后由固定话术区域显示错误，原视频保持播放。
4. 手动“准备人声”继续复用同一命令；自动准备返回缓存命中时立即进入 `ready`，未命中时由现有 500ms 快照轮询更新 `preparing → ready/failed`。
5. 不把源路径放入新的持久化状态；缓存仍由 Rust 使用源视频完整 SHA-256 管理。

把当前内联的替换按钮禁用表达式改为调用 `getVoiceCloneReplaceDisabledReason`，保证状态 ready 时按钮实际可点击，同时保留普通声音处理未提交、实时 Worker 占用和话术校验等保护。
