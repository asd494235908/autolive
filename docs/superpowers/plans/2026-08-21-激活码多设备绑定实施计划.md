# 激活码多设备绑定实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让管理员创建的同一激活码可按 `max_devices` 最多绑定 1～100 台不同设备，并在管理端显示绑定进度。

**Architecture:** 在现有 `activation_codes` 表中增加 `max_devices` 和 `bound_devices` 两个持久化字段，保留首次核销归属字段兼容历史数据。Memory 与 PostgreSQL normalized 两条核销路径共享同一状态机：锁定激活码，校验剩余配额，绑定设备并递增计数，达到上限后标记 `used`。React 管理端使用 Ant Design `InputNumber` 提交数量，列表展示 `bound_devices / max_devices`。

**Tech Stack:** Go 1.22 module / PostgreSQL migrations / `database/sql` / React 19 / TypeScript / Ant Design / `openapi-typescript` / Node test runner。

## Global Constraints

- 激活码明文只在创建成功响应中返回一次，数据库、列表、幂等重放和日志不得保存或返回明文。
- `max_devices` 默认 `1`，允许范围 `1～100`；`bound_devices` 必须满足 `0～max_devices`。
- 每次设备激活必须校验设备归属、状态、会话绑定和激活码配额，失败回滚全部业务写入。
- PostgreSQL normalized 路径不得回退到快照全量读改写；迁移必须前向兼容既有单设备激活码。
- 管理端统一使用 Ant Design，不手写替代组件；新代码拆分到已有领域文件或小型领域文件。
- 先写失败测试再写生产代码；构建在本机完成，服务器只加载发布镜像。

- [ ] **Step 3: Add migration 0022**

Use this migration shape:

```sql
ALTER TABLE activation_codes
    ADD COLUMN IF NOT EXISTS max_devices INTEGER NOT NULL DEFAULT 1,
    ADD COLUMN IF NOT EXISTS bound_devices INTEGER NOT NULL DEFAULT 0;

UPDATE activation_codes
SET bound_devices = CASE WHEN used_by_device_id IS NULL THEN 0 ELSE 1 END
WHERE bound_devices = 0;

ALTER TABLE activation_codes
    ADD CONSTRAINT activation_codes_max_devices_range
        CHECK (max_devices BETWEEN 1 AND 100),
    ADD CONSTRAINT activation_codes_bound_devices_range
        CHECK (bound_devices BETWEEN 0 AND max_devices);
```

Use `ADD CONSTRAINT` after the `ADD COLUMN IF NOT EXISTS` statements; this migration is applied once by the versioned migration runner, and the repository’s migration files do not re-run a version after it is recorded.
