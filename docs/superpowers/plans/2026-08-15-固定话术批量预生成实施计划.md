# 固定话术批量预生成 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 参考人声和 XTTS-v2 模型就绪后，后台串行预生成最多 10 条固定话术音频缓存，并在新增或修改文本后自动补生成，且不播放、不切换音轨、不影响视频循环。

**Architecture:** Rust/Tauri 增加一个有界批量命令，批次状态归 `PlaybackCore` 所有并复用现有常驻 Voice Clone Worker 与当前文本缓存；缓存生成与媒体资源放行/音轨应用拆开。React 根据“来源代次 + 文案文本修订号”触发批次，运行时快照负责展示总进度和逐项状态，localStorage 仍只保存文案业务数据。

**Tech Stack:** Rust、Tauri 2、serde、现有 CancellationToken/常驻 Python Worker、React 18、TypeScript、Ant Design、Node test runner。

## Global Constraints

- 最多处理 10 条文案，后端必须重新校验数量、唯一非空 `preset_id` 和 1～500 个 Unicode 字符的非空文本。
- 批次严格串行复用同一个常驻 XTTS Worker；不启动多个模型进程，不增加依赖或任务框架。
- 预生成只写入并验证音频缓存；不调用 `allow_voice_clone_audio_file`、不调用 `apply_voice_clone_playback`、不设置 `voice_clone_playback=playing`、不改变原音轨。
- 同一批次相同规范化文本只检查/生成一次，关联的多个文案项分别进入终态。
- 有效缓存必须比较缓存版本、源视频 SHA-256、参考音频 SHA-256、规范化文本、文本 SHA-256、模型、采样率和声道，并通过文件哈希与 FFprobe 校验。
- 切换视频取消旧批次并清空旧来源状态；同一视频正常循环不能取消或重启批次。
- 新增文案或修改文本时补生成；仅修改标题和删除文案不触发新批次。
- 单条输出/缓存校验失败后继续下一条；取消、Worker 退出、协议失败和超时停止剩余条目。
- 前端运行时状态不写入 localStorage，快照不得向前端暴露本地音频绝对路径。
- 页面在生成期间保持可滚动，不使用同步等待、整页遮罩或阻塞渲染。
- 不生成 MP4，不建立视频版本队列，不改动普通视频循环逻辑。
- 当前工作区相关源码已经包含用户未提交改动；实现者不得 reset、checkout、覆盖或提交这些文件，只修改本任务要求的最小区域并报告改动清单。
- 不使用 Git worktree，不在服务器构建。

pub struct VoiceClonePreGenerationItemState {
    pub preset_id: String,

pub struct VoiceClonePreGenerationState {

`VoiceClonePreGenerationState::default()` 返回 `idle` 和空计数。给 `PlaybackCore` 增加该字段，给 `PlaybackSnapshot` 暴露其 clone，并增加以下精确公共入口：

```rust
pub fn start_voice_clone_pre_generation(
    &mut self,
    batch_id: &str,
    source_generation: u64,
    items: Vec<VoiceClonePreGenerationItemState>,

pub fn mark_voice_clone_pre_generation_text_generating(
    &mut self,
    batch_id: &str,

    text_sha256: &str,

pub fn finish_voice_clone_pre_generation_text(
    &mut self,

    duration_ms: Option<u64>,

    batch_id: &str,

```

`finish_voice_clone_pre_generation_text` 只接受 `cached | generated | failed | cancelled`；按相同 `text_sha256` 一次更新全部关联项，`completed` 按条目增加，`cache_hits/generated` 按一次唯一文本工作增加。每个入口先核对 batch 和 generation；错误 status 返回 false，不写状态。

`clear_voice_clone_for_new_generation` 同时恢复默认预生成状态；`complete_loop` 不重置该状态。

- [ ] **Step 3: 实现纯触发与文案状态函数**

在 `voiceCloneStatus.ts` 增加精确输入类型和函数：

```typescript
export type VoiceClonePreGenerationTriggerInput = {
  sourceReady: boolean;
  sourceGeneration: number | null | undefined;
  presetCount: number;
  presetTextRevision: number;
  batchStatus: string;
  replacementStatus: string;
  playbackStatus: string;
  lastStartedKey: string | null | undefined;
};

export function getVoiceClonePreGenerationTriggerKey(
  sourceGeneration: number | null | undefined,
  presetTextRevision: number,
): string | null {
  return sourceGeneration === null || sourceGeneration === undefined
    ? null
    : `${sourceGeneration}:r${presetTextRevision}`;
}

export function shouldStartVoiceClonePreGeneration(input: VoiceClonePreGenerationTriggerInput): boolean {
  const key = getVoiceClonePreGenerationTriggerKey(input.sourceGeneration, input.presetTextRevision);
  return input.sourceReady
    && input.presetCount > 0
    && input.presetCount <= 10
    && input.batchStatus !== 'generating'
    && !['preparing', 'generating'].includes(input.replacementStatus)
    && !['preparing', 'playing'].includes(input.playbackStatus)
    && key !== null
    && key !== input.lastStartedKey;
}
```

`getVoiceClonePreGenerationSummary` 按测试中的中文文案返回摘要；逐项标签映射固定为：`pending=等待生成`、`generating=生成中`、`cached/generated=已准备`、`failed=生成失败`、`cancelled=已取消`。
