> 当前版本范围声明（2026-08-19）：本版本不开发实时话术幻化。本文虽然聚焦普通声音处理且已明确“不含实时话术幻化”，但其中所有实时音频架构相关文字均只作后续版本/历史边界说明，不属于当前版本开发、验收或发布范围。

> 状态：**软件链路已实施；硬件长时听感待验收**
> 日期：2026-08-18  
> 确认时间：2026-08-18  
> 范围：桌面端普通声音处理（不含实时话术幻化；插话仅作为出口 duck 参考）  
> 依据：`AGENTS.md`、`媒体参数范围与默认值.md`、当前 `AUDIO_VALUE_PRESETS` / FFmpeg `media_engine`

> 当前播放事实：普通声音默认不生成音频 MP4。下文出现 AAC/固定化文件时，仅指视频缓存内的源音频复制或有限输入/导出兼容护栏；当前普通声音播放路径是源音频流 → FFmpeg 多支路滤镜 → f32 PCM → PortAudio，PortAudio 关闭/失败时回退 WebView 源音频。

## 1. 目标与非目标

### 1.1 目标

1. **参考 Audacity**：音频 I/O 采用 **PortAudio**（跨平台回调、缓冲、Host API；Windows 上可走 WASAPI/ASIO）。
2. **多音轨参数修改**：每个勾选的完整参数预设 = 一条虚拟音轨（同源音频 × 该套参数）。
3. 周期随机时，从勾选集中选出 **1～N** 条音轨（默认 1～2）参与处理。
4. **合并输出单一音轨**：多条虚拟音轨混音后只留 **一条** 出口总线，再送给播放/PortAudio。
5. 响度/相位护栏、可复现 seed、无实时话术幻化。

### 1.2 非目标（本计划不承诺）

- 不做完整 Audacity 工程：Blockfile、多文件时间线、任意剪辑/包络编辑器。
- 不做 RTMP/OBS 推流、多平台分发。
- **不做 / 不依赖实时话术幻化**。
- 不生成 N 个离线 MP4 版本队列。
- 不把「多音轨」做成用户可无限堆叠的 DAW 工程视图（首版是预设驱动的虚拟轨）。

### 1.3 当前事实

| 项 | 现状 |
|---|---|
| 预设模型 | `AUDIO_VALUE_PRESETS`：每套 = 完整参数值 |
| 周期行为 | 从勾选集抽 **1–4 套** 整包应用；多轨等权合并 |
| 媒体出口 | 普通源音轨由 FFmpeg 各支路处理 → `amix` → `highpass` → `loudnorm` → `aresample` → f32 PCM → PortAudio；PortAudio 关闭/失败时 WebView 播放源音频 |
| PortAudio | **已接入**：后台解码/混音 + f32 SPSC 环缓 + 无锁回调；失败回退 WebView |
| Web Audio | 保留 WebView 播放与诊断；不作为 PortAudio 正式 PCM IPC 路径 |

### 1.5 AAC 编码兼容性护栏（2026-08-19）

部分源容器只提供音频声道数，没有标准声道布局；FFmpeg 可能将其标记为
`1 channels` 等未知布局。该布局直接交给 native AAC 会触发 `EINVAL`，并生成
`audio:0KiB` 的视频输出。当前每条 FFmpeg 音频支路在参数效果链之前统一经过
`aformat=sample_fmts=fltp:channel_layouts=stereo`，再进入等权混音、`highpass`、
`adenorm`、`loudnorm`、`aresample` 和 AAC；总线末端再次固定 `fltp`、双声道和目标采样率。
支路和最终混音总线在进入 `loudnorm` 前都经过 `aeval` 非有限样本护栏，将 NaN/Inf
转换为 0，避免非法浮点样本进入 AAC；处理失败仍保持旧轨/回退语义。输出采样率只允许
44100 或 48000 Hz；PortAudio 实时出口默认 44100 Hz，源素材为其它采样率时统一重采样，且与 PortAudio 输出契约一致。

媒体处理取消时，哈希阶段的 `FileHashError::Cancelled` 现在保持为媒体引擎的
`Cancelled`，不会再伪装成 `HashFailed`；停止播放同时清除本次取消留下的失败提示。

### 1.6 P1/P2 运行时护栏（2026-08-19）

- `audio_mixer` 只向混音队列提交完整双声道 f32 帧；跨 FFmpeg `read` 边界保留残余字节，
  解码成功但没有 PCM 输出或输出未按帧对齐时直接失败，不再静默循环。
- FFmpeg 解码错误输出采用有界尾部采集；stderr 使用管道并持续排空，媒体渲染加入
  `-loglevel error -nostats`，避免错误原因丢失或长日志填满管道导致进程假死。
- PortAudio 实际设备为单声道时，在写入 SPSC 环缓前将混音器的立体声帧等比下混为单声道；
  非有限值和未对齐帧直接拒绝，回调仍只取环缓并补零。
- 视频缓存交付前由 ffprobe 校验视频文件和复制的源音频流；普通声音处理不生成独立音频 MP4，不以音频文件交付校验作为播放前置条件。
- PortAudio 混音运行时失败会自动关闭硬件出口、切换到 WebView，并让前端恢复源视频声音；
  处理结果或 A/B 音轨失败、停止后不再保持静音接管状态。
- PortAudio 轮询不再以输出对象存在作为“正在播放”的依据；同时校验流运行标志和回调计数，
  回调超过约 1.5 秒无进度时自动关闭硬件出口并回退 WebView，防止轮询期间把无声硬件路径误判为正常输出。

### 1.7 长时运行稳定性与缓存操作（2026-08-19）

- PortAudio 混音器改为单个 FFmpeg 解码进程循环输出，避免每轮文件结束时重启解码造成静音窗口。
- 环缓写入支持部分写入；混音线程在环缓暂满时以可取消的短间隔重试，不再静默丢弃一段 PCM。
- 最终效果窗对 `sync_audio_output_source` 使用最新请求优先的串行队列，旧请求不会与新请求并行重启混音器。
- 主窗口提供“删除已生成缓存”按钮：仅删除未被当前/待切换引用的 `processed-*.mp4` 和超过 10 分钟的 partial；媒体处理进行中或声音处理正在播放时拒绝操作，避免删除活动音轨导致静音。
- FFmpeg 输出采样率统一限制为 44100/48000 Hz；异常或未识别源采样率回退 48000 Hz，避免将异常元数据直接传入 `aresample`/AAC。
- 支路与最终混音总线在 `loudnorm` 前增加 NaN/Infinity 护栏，防止 AAC 收到非法浮点帧。
- 已按 FFmpeg 官方滤镜文档及本机 bundled FFmpeg 逐项审查预设映射范围：`aecho` decay、`afftdn` nr、`aphaser` decay、`vibrato` 频率/深度、`atempo`、`loudnorm`、`anoisesrc` amplitude 均有对应边界；UI 预设入口增加有限值/范围归一化，1–20 号预设不会把越界值送入 IPC。
- 第 21 个预设保留定义供人工研究查看，但不进入默认随机池、周期抽样或本地持久化选择集；运行时只使用第 1–20 项。

### 1.8 本轮优先级修复实施（2026-08-19）

按“先阻断静音产物，再阻断切换静音，最后做硬件长测”的顺序执行：

1. **P0：阻断确定性静音根因**
   - 修复 `afade` 淡出链：有限输入的离线链路使用 `areverse → afade=in → areverse`；实时链路禁止 `areverse`，避免等待完整输入造成 FFmpeg 高延迟或无界内存增长。当前实时解码按有限输入逐轮顺序重启，不再依赖单个 `-stream_loop -1` 进程。
   - 生成完成后追加 FFmpeg `volumedetect` 内容校验；AAC/采样率/声道/格式通过但 `max_volume ≤ -80dB` 时拒绝提交、清理 partial，不计算 SHA-256，不切换当前音轨。
   - 已覆盖参数滤镜契约测试和 `max_volume` 解析测试。
2. **P1：阻断候选切换导致的硬件静音**
   - PortAudio 周期换轨先启动候选解码器；提交基础要求为 130ms 连续候选 PCM，其中 30ms 用于交叉淡化、其后至少保留 100ms；实际阈值取 `max(130ms, 当前动态播放水位)`，最高 750ms。候选在 5 秒有界预算内继续保留 PCM，覆盖 `loudnorm`/多支路滤镜启动期间已经推进的画面时钟；提交时按可听绝对时间裁掉落后 PCM。
   - 候选先通过追时钟提交校验，之后才停止旧混音任务；追时钟不足、解码失败或超时时直接销毁候选并继续旧轨。旧环缓不清空，已校验候选顺序接在旧数据之后，避免提交失败后旧环缓排空并进入静音。
   - 首次启动采用 50ms 原子 prime；周期提交由唯一 `audio_cycle_output` 从旧/新队列取得样本并原子追加完整 30ms 双向线性交叉淡化，成功后才切换 current。正常播放仍按 50ms 目标水位供给，候选失败不清空旧环缓。
   - SPSC 环缓写入跨越环尾时使用可跨两段的迭代写入，不能把“连续空闲段暂时为 0”误判为消费者无进度。初次启用先以 callback 静音暂停态启动硬件流并读取实际输出延迟；候选提交完成后才放行 callback，预热期间 WebView 继续输出。
   - 提交位置计入 UI 观测后经过的预热时间、旧环缓待播时间和 PortAudio 实际输出延迟；播放 generation、轮次、媒体引用或声音流版本变化会令旧候选过期。PortAudio 失败继续回退 WebView。
   - FFmpeg 当前轨与 Scheduled 候选按 `playback_speed × 1.1` 使用有界 `-readrate`，使 `atempo` 后仍有约 10% PCM 生产余量；首次启动/恢复的 CatchUp 候选按 `max(2, playback_speed + 1)` 使用追赶型 `-readrate` 和 500ms 初始突发。已知未来切换点的 Scheduled 候选提前 seek 并生成固定时间窗，填满后由有界队列反压。停止时确认 FFmpeg 子进程、stderr、解码线程和混音线程均已退出，不静默放弃 `JoinHandle`；运行态记录当前/候选 FFmpeg PID，任务数最多为 1+1；实时滤镜回归测试禁止 `areverse`。
3. **P2：限制运行时选择范围**
   - 默认/持久化/周期抽样统一排除第 21 项；第 21 项定义和参数值不改写。
4. **P3：验收边界**
   - Rust `--lib`、媒体契约测试、前端全量测试已通过；真实 PortAudio 设备连续 30 分钟听感压测仍需在目标机器执行，不能用单元测试替代。

## 2. 产品语义澄清

| 说法 | 正确含义 |
|---|---|
| 「勾选多个预设」 | 多条**虚拟音轨**的参数模板池 |
| 「随机选 1～2 种」 | 本周期激活的虚拟轨数量 |
| 「多音轨参数修改」 | 每条激活轨套自己的完整参数，分别处理同源音频 |
| 「合并输出单一音轨」 | 加权混音 → **一条**主总线 → PortAudio/WebView |
| 「出口」 | 主总线单轨（可被插话 duck；不接实时幻化） |

**已确认默认：**

- `mix_pick_min / mix_pick_max`：**可配置 1–4，默认 max=2**（硬上限 4）
- 权重：**等权 `1/k`**
- 相邻周期：候选预设超过 1 套时，本周期不选上一周期参与过的预设；隔一个周期可以再次出现；候选只有 1 套时允许持续重复
- 周期未就绪：**继续用上一出口，后台赶下一次**
- 输出后端：**PortAudio 与 WebView 互斥**；无 PortAudio/失败时用 WebView
- 目标响度：**-16 LUFS**（配合 True Peak 护栏）

## 3. 分阶段计划

### Phase A — 契约与 UI（低风险）

1. 扩展声音配置：
   - `selected_preset_ids: string[]`
   - `mix_pick_min / mix_pick_max: number`（范围 1–4，默认 max=2）
   - `mix_enabled: bool`（建议默认关，打开后才允许多轨合并）
2. UI：勾选完整参数值预设 + 「每周期随机轨数」控件。
3. 验收：配置可保存到本机会话状态；`mix_enabled=false` 或 `max=1` 时行为与现网单轨一致。

### Phase B — 多音轨参数处理 + 合并单轨（处理主路径）

1. 周期触发：从勾选集不放回抽样 `k ∈ [min,max]` 个预设 → `k` 条虚拟音轨。
2. 处理（两阶段可并存，首版先做 B1）：
   - **B1 有限输入/导出兼容**：`asplit=k` → 每轨参数滤镜 → `amix` → loudnorm → 单轨 AAC/PCM 文件；不作为当前普通播放的前置条件。
   - **B2 当前实时总线**：FFmpeg 直接从源视频音频流解码得到 f32 块，在后台混合器线程做总线护栏并写入 SPSC 环缓。
3. 验收：`k=1` 对齐现网；`k=2` 可听混合、无爆音；失败回退上一出口。

### Phase C — 预加载与切换平滑

1. 下一周期在后台算；**到点若未完成，继续上一出口，后台赶下一次**（已确认）。
2. 就绪后交叉淡化 20–40 ms 再切。
3. 取消/关窗可中止渲染。

### Phase D — PortAudio 输出后端（参考 Audacity，正式阶段）

**决策：I/O 走 PortAudio（对齐 Audacity）。**  
ASIO 作为 PortAudio 的 Host API 之一在 Windows 上启用，而不是单独再写一套 ASIO-only 引擎。

1. 输出后端：`portaudio` / `webview`（回退）。
2. 依赖：当前 PortAudio FFI 位于独立 `autolive-portaudio-output` crate；环缓使用成熟 `ringbuf`，主 crate 继续 `unsafe_code=forbid`。
3. 路径：主总线 f32 PCM → SPSC 环缓（50–100 ms）→ PortAudio 回调填硬件缓冲。
4. 设备 UI：Host API（MME/WASAPI/ASIO）、设备、SR、缓冲、xrun、回退 WebView。
5. 回调禁忌：无 FFmpeg、无磁盘、无 UI、无重锁；只搬样本。

### Phase E — 实时可调参数（有限）

1. 增益/EQ/轻相位等可在混合器线程按块更新（Audacity 式“当前缓冲无状态处理”思路）。
2. 降噪等仍先固化再听。
3. 不做实时话术幻化。

## 4. 建议架构

```
勾选预设池 ──► 随机激活 k 条虚拟音轨（每轨一套完整参数）
                 │
源音频 ──► 复制/分轨处理 ──► Track1..k DSP ──► Mix Bus (单轨)
                                              │
                                    loudnorm / limiter
                                              │
                              ┌───────────────┴───────────────┐
                              ▼                               ▼
                     WebView 缓存播放                  PortAudio 回调输出
                     （兼容回退）                     （Audacity 同思路；
                                                      可含 ASIO Host API）
```

模块边界：

- UI：预设勾选、`mix_pick_*`、PortAudio 设备/缓冲
- 调度：抽样 + seed 日志
- `media_engine`：多轨滤镜/`amix` 固化（可继续服务导出与稳健回放）
- `audio_mixer`（新）：虚拟轨块混合 → 主总线 f32
- `audio_output_portaudio`（新 crate）：环缓 + PortAudio；失败回退 WebView

## 5. 技术难点

### 5.1 产品/契约

| 难点 | 说明 | 缓解 |
|---|---|---|
| 「音轨」语义混淆 | 用户可能理解为多文件多轨工程 | UI 文案用「处理支路/参数套」，并明确出口仍是单轨 |
| 与插话抢出口 | 插话 duck 与普通声音缓存切换叠加 | 插话只 duck 最终出口；普通声音处理不读实时幻化状态 |
| 可复现性 | 随机抽样导致实验难复盘 | 每周期记录 `seed + preset_ids + weights` |

### 5.2 FFmpeg 多支路

| 难点 | 说明 | 缓解 |
|---|---|---|
| 滤镜图复杂度 | `asplit` + 多套 EQ/音高/混响/噪声 图易出错 | 每支路封装为函数；单元测试导出 filtergraph 字符串 |
| 音高/变速改变时长 | 多支路时长不一致，`amix` 需统一 duration | `amix=duration=first` 或先把各支路对齐到源时长 |
| 响度叠加爆音 | 等权混合易削波 | `amix` normalize 或按 `1/k` 权重；峰值限制 |
| CPU/耗时 | k=3 时渲染成本近似 ×3 | 限制 max；后台预渲染；超时取消 |
| 部分参数不可实时 | 降噪等需要更长上下文 | 固化链做；预览链跳过或降级 |

### 5.3 播放切换

| 难点 | 说明 | 缓解 |
|---|---|---|
| 切换咔哒/空音 | 新缓存未就绪就切 | 预加载 + 边界校验 + 失败保持旧轨 |
| 与视频处理联合 | 音视频同时应用时图更复杂 | 首版「多支路」仅音频；视频仍单链 |
| 关窗清理 | 关最终效果窗需停 Worker 并关开关 | 已有关窗关处理开关逻辑，多支路任务必须可取消 |

### 5.4 PortAudio / 多轨混单轨

| 难点 | 说明 | 结论 |
|---|---|---|
| 与 WebView 双出口 | 两套播放易双响 | 互斥切换；失败回退 WebView |
| 回调线程禁忌 | 回调内不能磁盘/锁/分配 | 环缓 + 成熟 PortAudio 绑定；禁止手写驱动 |
| Windows Host API 差异 | MME/WASAPI/ASIO 表现不一 | 设备设置里可选；默认 WASAPI Shared，有卡再开 ASIO |
| DSP 与 I/O 分离 | 避免两套效果引擎 | FFmpeg/混合器负责处理；PortAudio 只送主总线 |
| 被理解成完整 DAW | Audacity 工程能力诱惑大 | 明确只要「虚拟轨参数 + 混单轨 + PortAudio I/O」 |

原则吸收：有界 PCM 内存缓冲、f32、UI/渲染/回调三线程、延迟校准（后期）。

## 6. 推荐落地顺序（最短可验收路径）

1. Phase A+B：`mix_pick_max=2`，多虚拟轨参数处理 + 合并单轨（先 FFmpeg）。
2. Phase C：预加载/交叉淡化。
3. Phase D：PortAudio 输出（Host API 含 WASAPI/ASIO）。
4. Phase E：有限实时参数上混合器。

## 8. 随时变换 / 响度相位 / 缓冲采样率 / PortAudio 方案

> 约束：不含实时话术幻化；多音轨改参数后必须混成单一出口。

### 8.1 总体分层

| 层 | 职责 | 技术 |
|---|---|---|
| 处理层 | 虚拟轨参数、混音、响度/相位护栏 | FFmpeg `asplit`/`amix`/`loudnorm`（可演进到混合器线程） |
| 输出层 | 把单轨主总线送出 | **PortAudio**（对齐 Audacity；ASIO 作 Host API） |
| 回退层 | 无 PortAudio/设备失败 | WebView 播缓存 |

### 8.2 需求 1：随时变换 + 声纹不确定

目标：参数可周期切换，听感有变化，但不追求“规避检测”。

**做法：**

1. 勾选多套完整参数预设；周期到从中抽 `k∈[1,2]` 套。
2. 每套参数做**有界微扰**（现有预设已是小幅度），并加硬约束：
   - 音高 `|Δ| ≤ 0.08 st`
   - EQ 各段 `|Δ| ≤ 0.6 dB`
   - 颤音深度 ≤ 0.35%
   - 相位扰动 ≤ 2.5%
3. 切换必须带 **短交叉淡化**（建议 20–40 ms `afade/acrossfade`），禁止硬切。
4. 每周期落盘：`seed + preset_ids + weights + 参数快照`，保证可复现，而不是“黑盒乱变”。

**不承诺：** 声纹绝对不可识别；只承诺听感自然、变化有界、结果可复盘。

### 8.3 需求 2：响度/相位可调，但出口稳定、听不累

目标：能调，但混音结果不炸、不刺耳、不闷。

**混音稳定管线（每周期输出前强制执行）：**

```
支路1..k 处理后
  → amix（等权 1/k）
  → highpass=f=50
  → adenorm=level=-351:type=ac（静音/近静音 NaN/Inf 护栏）
  → loudnorm=I=-16:TP=-1.5:LRA=11
  → aresample
  → f32 PCM → PortAudio 播放；有限输入导出才写 AAC 文件
```

**参数建议：**

| 项 | 建议值 | 原因 |
|---|---|---|
| 目标响度 | `-16 LUFS`（播客/口播舒适区） | 比 -14 更省耳，比 -18 更稳 |
| True Peak | `≤ -1.5 dBTP` | 防编码器/DAC 削波 |
| 多支路权重 | 等权 `1/k`，或主辅 `0.7/0.3` | 避免能量叠加 |
| 相位 | 各支路同源 `asplit`，禁止任意长延时差 | 同源对齐是防梳状滤波关键 |
| 相位扰动 | 只允许小幅度；混合前可对辅轨轻微 decorrelate，但要限带宽 | 过大易空、易累 |

**听感护栏（自动拒绝/回退）：**

- 混合后短期响度相对源跳变 `> 3 LU` → 自动压回或丢弃本周期
- 检测到削波计数超阈值 → 回退旧轨；不使用 `alimiter` 冒充响度标准化
- 辅轨与主轨相关过低且刺耳频段抬升 → 降低辅轨权重

### 8.4 需求 3：缓冲区与采样率最佳设置

#### 采样率

| 场景 | 建议 | 说明 |
|---|---|---|
| 默认处理/导出 | **44100 Hz**；兼容请求仍支持 48000 Hz | 避免异常源元数据直接进入 AAC |
| 仅口播监听 | 44.1 kHz | 当前 PortAudio 与 WebView 诊断图统一设置 |
| 多支路混合 | 全链路统一到同一 SR 再 `amix` | 禁止支路 SR 不一致 |

规则：`PortAudio 实时 SR = 显式 44100/48000 → 默认 44100`；当前 UI 默认和自动重对齐目标均为 44100 Hz。

#### 缓冲（按路径）

**A. 当前路径（FFmpeg 流式处理 + PortAudio 播放）——首版默认**

| 参数 | 建议 | 说明 |
|---|---|---|
| 周期候选预热提前量 | `≥ 1.5 × 预估滤镜启动耗时`，受有界预算约束 | 到点尽量有 PCM 候选，失败沿用上一出口 |
| 切换交叉淡化 | 20–40 ms | 防咔哒 |
| 播放器内部缓冲 | 交给媒体元素/解码器 | 不强行改 WebView 低延迟 |

这不是 ASIO 回调缓冲；它是“渲染排队缓冲”。

**B. PortAudio 输出（正式）**

| 参数 | 建议起点 | 调参方向 |
|---|---|---|
| 硬件回调帧数 | **256 @ 44.1 kHz**（约 5.8 ms） | 内部参数，与 UI 的内存缓冲输入无关 |
| 应用侧环形内存缓冲 | **1024 KiB**（44.1kHz 双声道 f32 约 2.97 秒） | UI 可输入 128～2048 KiB；给 FFmpeg 多轨混音和调度抖动留恢复余量 |
| 解码到混音有界队列 | **8 个 PCM 块** | 吸收 FFmpeg 输出和混音线程之间的短时调度抖动，并维持有界背压 |
| Host API | 默认 WASAPI Shared；可选 ASIO | 独占模式仅高级用户 |
| 回调线程 | 只从环缓取 f32 填硬件缓冲 | 禁止 FFmpeg/磁盘/UI |

经验法则：UI 的 1024/2048 只表示 KiB 内存容量，不表示 PortAudio 回调帧数；硬件回调保持内部默认 256 帧。

### 8.5 PortAudio 正式接入（对齐 Audacity）+ 多轨合并单轨

| 问题 | 结论 |
|---|---|
| I/O 用什么？ | **PortAudio**（与 Audacity 同路线）。 |
| ASIO 呢？ | 作为 PortAudio 的 **ASIO Host API** 使用，不另起纯 ASIO 引擎。 |
| 多音轨怎么做？ | 每套预设 = 虚拟轨；分别改参数；**混成一条主总线**再输出。 |
| DSP 真相源？ | 当前普通播放由 FFmpeg 生成各支路/混音的 f32 流；PortAudio 负责送出。有限输入导出才允许落 AAC 文件。 |

**多音轨 → 单轨出口（核心）：**

1. 激活轨 `T1..Tk`，每轨参数完整且独立。
2. 同源音频分轨处理（FFmpeg `asplit` 或块处理复制）。
3. `Mix(T1..Tk, weights)` → 单总线。
4. `loudnorm=I=-16:TP=-1.5:LRA=11` → `aresample` → f32 PCM；后台总线再做 `-1.5 dBTP` 护栏 → 环缓 → PortAudio 回调，PortAudio 失败时回退 WebView 源音频。

**PortAudio 实现要点：**

1. 单独 crate（如 `autolive-portaudio-output`）承载 FFI；主 crate 保持 `unsafe_code=forbid`。
2. 环缓 `f32`，应用侧默认 1024 KiB、范围 128～2048 KiB；FFmpeg 到混音线程的有界队列 8 个 PCM 块；候选最低可播放余量 50 ms；硬件回调内部默认 256 帧 @ 44.1 kHz。
3. 线程：UI | 渲染/混合 | PortAudio callback。
4. 无设备/驱动失败 → 回退 WebView，不阻断导入播放。
5. 许可：PortAudio 许可合规；若分发 ASIO 相关组件，另记 Steinberg SDK 边界。

### 8.6 落地顺序

1. Phase A：勾选 + `mix_pick_*`。
2. Phase B：多虚拟轨参数处理 + `amix` 单轨出口（先 FFmpeg）。
3. loudnorm/限幅 + 交叉淡化 + seed 日志。
4. Phase C：预渲染。
5. **Phase D：PortAudio 输出**（Host API 含 WASAPI/ASIO）。
6. Phase E：有限实时参数上混合器线程。
