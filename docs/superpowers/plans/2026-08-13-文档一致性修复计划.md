# 文档一致性修复计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 将项目文档统一为“单源视频、单窗口循环、视频处理/声音处理/话术实时幻化三个独立开关”的唯一口径，并明确当前实现、目标设计和历史方案的边界。

**架构原则：** 根目录文档作为当前有效契约；`docs/superpowers/` 中的旧媒体任务文档只保留审计用途；旧源码和数据库迁移本轮默认不删除，若要删除必须另开代码清理任务。

**技术范围：** Markdown、Mermaid、OpenAPI 3.1、Go/Rust/React 现状核对、文档检查脚本和 Ruby YAML 解析。

## 全局约束

- 一个播放会话只能选择一个源视频，在同一个窗口内循环播放。
- 不生成 N 个离线视频、不生成多个 MP4、不维护视频版本队列。
- 仅保留视频处理、声音处理、话术实时幻化三个独立开关。
- 实时幻化不做运行时 Chromaprint/landmark 重复检测。
- 候选失败、超时、过期或同步门禁失败时，继续当前视频和上一条可用音轨。
- 不接 RTMP/OBS、直播平台、自动发布或平台检测规避能力。
- 文档修复阶段不直接删除已有源码、迁移和历史记录。

## 已确认决策

以下决策已由用户确认，并作为本轮文档修复的唯一口径：

1. 本轮只修改文档，不删除旧源码、旧管理端页面和 `variant_tasks` 数据库迁移；旧实现仅作历史审计依据。
2. Go 后端负责记录、管理和测试 OpenAI-compatible 模型账号，签发单账号短期直连租约并记录调用摘要；Rust 客户端使用租约直接调用供应商，不经过 Go 模型代理，不取得完整号池或长期 API Key。
3. 素材库可以管理文件或目录，但一次播放会话只选择一个源 MP4，并在同一个窗口内循环播放。
4. 三个开关的音频顺序固定为：`源/基础音轨 → 实时话术幻化（可选）→ 普通声音处理（可选）→ 最终音频输出`。
5. 实时幻化按播放轮次和片段边界自动调度；模型或候选来不及时，继续上一条可用音轨，不暂停、不静音、不重新弹窗。
6. Hugging Face `speech-to-speech` 作为首个 Worker 适配器，保留可替换的 Worker 接口。
