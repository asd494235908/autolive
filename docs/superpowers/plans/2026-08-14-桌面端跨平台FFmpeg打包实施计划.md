# 桌面端跨平台 FFmpeg 打包实施计划

> 当前版本范围声明（2026-08-19）：本版本不开发实时话术幻化。本文只实施 FFmpeg/FFprobe 本地资源打包，实时话术 Worker、speech-to-speech、候选音轨和模型租约不属于本计划范围。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Tauri 桌面端在 macOS Intel、macOS Apple Silicon 和 Windows x64 安装包内自带匹配架构的 FFmpeg/FFprobe，Rust 运行时自动定位资源，不依赖用户系统安装。

**Architecture:** 使用 Tauri `bundle.resources` 将打包前准备好的 `ffmpeg` 和 `ffprobe` 放入资源目录。脚本根据当前目标三元组选择第三方二进制，复制为资源目录内的标准名；Rust 通过 `resource_dir()/binaries/` 定位内置文件，并校验当前目标平台。开发环境仍允许 `AUTOLIVE_FFMPEG_PATH` 和 `AUTOLIVE_FFPROBE_PATH` 覆盖。

**Tech Stack:** Rust/Tauri 2、Node.js 脚本、FFmpeg/FFprobe、pnpm。

## Global Constraints

- 目标平台固定为 `x86_64-apple-darwin`、`aarch64-apple-darwin`、`x86_64-pc-windows-msvc`。
- 正式运行优先使用安装包内置二进制，不依赖系统 PATH；环境变量仅作为开发/测试覆盖。
- Rust 继续使用参数数组调用子进程，不经过 Shell，不新增自研媒体编解码器。
- FFmpeg/FFprobe 二进制不直接提交到源码仓库；由准备脚本从受控第三方资源目录复制。
- 打包脚本缺少当前构建目标平台的 `ffmpeg` 或 `ffprobe` 时必须失败，不生成缺少媒体能力的正式安装包；三个目标分别在对应构建环境执行。
- Windows 目标只支持 x64；Windows ARM64 不在本轮目标内，macOS 同时支持 Intel 和 Apple Silicon。
- 许可证以实际构建参数和随包材料为准，不能只根据资源文件名推断。本轮已下载的 macOS 资源为 Martin Riedl FFmpeg 9.0 构建并实测包含 `--enable-gpl`，Windows 资源为 BtbN n8.1 LGPL 构建；正式发布前必须完成许可证复核，或替换为满足 LGPL-only 要求的构建。

- [x] **Step 3: 增加最小路径契约实现**

实现以下固定映射：

```rust
fn target_triple() -> &'static str {
    if cfg!(all(target_os = "macos", target_arch = "x86_64")) {
        "x86_64-apple-darwin"
    } else if cfg!(all(target_os = "macos", target_arch = "aarch64")) {
        "aarch64-apple-darwin"
    } else if cfg!(all(target_os = "windows", target_arch = "x86_64")) {
        "x86_64-pc-windows-msvc"
    } else {
        "unsupported"
    }
}
```

内置路径固定为 `resource_dir/binaries/ffmpeg` 和 `resource_dir/binaries/ffprobe`；Windows 追加 `.exe`。目标三元组只用于判断当前构建是否受支持，任一目标为 `unsupported` 时返回结构化 `EngineUnavailable`。
