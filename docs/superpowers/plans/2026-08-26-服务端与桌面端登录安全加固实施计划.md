# 服务端与桌面端登录安全加固实施计划

> 日期：2026-08-26  
> 状态：主体实现、本地自动化与 Docker PostgreSQL 16 真库验证完成；2026-08-28 已补同 NAT 多设备限流、Rust 认证串行化和稳定设备标识修复；Windows Credential Manager、正式 HTTPS/DNS/TLS、多主机、Race 和确认后的未使用代码清理待完成  
> 适用范围：Go 控制面、PostgreSQL、React 管理端、Rust/Tauri 桌面端  
> 实施顺序：先同步文档，再修改契约和代码，最后统一验证与发布  
> 不包含：用户注册、邀请注册、MFA/WebAuthn、邮箱/短信找回密码、设备硬件指纹、设备密钥对和挑战签名

## 1. 目标

本批次只加固“管理员创建用户后，管理员登录管理端、普通用户登录桌面端”的既有链路。完成后必须满足：

1. 管理端与桌面端复用同一用户事实源，但会话 audience 硬隔离。
2. 桌面登录拒绝管理员账号；桌面 Token 无法访问管理接口，管理 Token 无法访问客户端接口。
3. Access Token 为 15 分钟；Refresh Token 为 30 天绝对有效期并支持 family 重放检测。
4. Access Token 过期后仍能按 Refresh Token 幂等注销当前会话。
5. 登录失败不直接暴露账号存在、禁用、产品权限或管理员身份。
6. 账号维度限流跨进程、跨实例、重启后继续生效；来源 IP 只在可信代理边界解析。
7. 新密码使用 Argon2id，旧 bcrypt 在成功登录后渐进升级。
8. 桌面端不保存登录密码；Refresh Token 不进入 WebView，只由 Rust 和系统钥匙串持有。
9. `main` 与 `final-effect` 的 Tauri capability 分离，最终效果窗口没有控制面 HTTP 或认证凭据能力。
10. 所有变更有前向迁移、OpenAPI、自动化测试和本地发布验证证据。

## 2. 实施前事实与问题（历史基线）

以下内容记录本批次开始前的迁移输入，已经由第 3～6 节方案替换，不再代表当前代码状态：

- Go 只有 `POST /api/v1/auth/login`，管理端和桌面端签发同一类型会话；`auth_sessions` 没有 audience。
- Access Token 当前为 1 小时，Refresh Token 为 30 天；Refresh 轮换会使旧 Token 失效，但消费记录不足以识别 family 重放。
- Logout 当前要求有效 Bearer Access Token，请求体中的 Refresh Token 没有用于定位撤销。
- 密码使用 bcrypt；用户不存在与密码错误的工作量、禁用/无产品权限的外部语义存在差异。
- 高风险接口限流只使用当前进程内的 `RemoteAddr`，多实例不共享，重启后清空，也没有账号维度状态。
- 桌面 WebView 当前能读取原始 Refresh Token，并能从系统钥匙串读取已保存登录密码。
- `main` 和 `final-effect` 当前共用 capability，包含控制面 HTTP 权限。

## 3. 固定设计决策

### 3.1 登录入口和 audience

- `POST /api/v1/auth/login` 保留为管理端登录入口，只允许具备管理身份的账号，签发 `audience=admin`。
- 新增 `POST /api/v1/client/auth/login` 作为桌面端登录入口，只允许普通用户，签发 `audience=desktop`；管理员账号统一按认证失败处理。
- `POST /api/v1/auth/refresh` 继续共用，但只从 Refresh 会话继承 user、product、device、audience 和 family，禁止请求体覆盖。
- `POST /api/v1/auth/logout` 改为只需 Refresh Token 即可幂等撤销当前会话；不要求 Access Token 仍有效。
- `/api/v1/admin/**` 只接受 `admin` audience；`/api/v1/client/**` 只接受 `desktop` audience。角色/RBAC 校验继续执行，但不能替代 audience 校验。

### 3.2 Token 生命周期

- Access Token：15 分钟。
- Refresh Token：从首次登录起 30 天绝对有效，轮换不延长。
- 每次登录创建新的 `token_family_id`，首代 `generation=0`。
- Refresh 在一个数据库事务内锁定旧代、校验、消费并创建下一代；并发请求只能一个成功。
- 已消费的 Refresh 记录保留到原绝对过期时间。再次收到该 Token 时撤销整个 family，并写不含 Token 的安全审计。
- 禁用用户、密码重置、管理员换密、设备解绑等既有撤销路径必须同时覆盖 family 中的有效会话。

### 3.3 注销

- 服务端按 Refresh Token 哈希定位并撤销当前会话；不存在、已撤销和重复注销均返回相同成功响应。
- 注销不允许用一个会话的 Access Token 撤销另一个 Refresh Token。
- 桌面端应先尝试远端注销，再删除本机 Refresh Token；若网络或服务端失败，仍清除本机状态并提示“本机已退出，但服务端注销未确认”。
- 本批次不增加“退出全部设备”入口；管理员禁用/重置密码的全会话撤销维持独立管理语义。

### 3.4 防枚举与限流

- 用户不存在、密码错误、用户禁用、无产品权限、管理入口的普通账号和桌面入口的管理员账号统一返回 `401 UNAUTHENTICATED` 与中性提示。
- 用户不存在时执行预生成 dummy hash 校验；dummy hash 在进程启动时准备，不在每次请求重新生成。
- 继续保留 `golang.org/x/time/rate` 作为进程内 IP 突发保护，不自行实现令牌桶。
- 新增 PostgreSQL 账号摘要桶，建议从第 5 次失败后等待 30 秒并指数退避，最长 15 分钟；成功登录清除账号失败状态，不使用永久锁号。
- 账号桶与来源 IP 桶都必须生效，但不得共用同一低阈值：账号从第 5 次失败起退避，来源 IP 从第 50 次失败起承担聚合滥用退避；进程短突发分别限制单账号和整个来源地址。使用专用 Secret 和 Go 标准库 `crypto/hmac` + SHA-256 计算带用途前缀的 HMAC 摘要；数据库不保存明文用户名或完整 IP。新增 `APP_AUTH_THROTTLE_HMAC_KEY`，生产模式要求解码后至少 32 字节且不得进入数据库、日志或普通配置；轮换时允许旧桶自然失效并重新计数。
- 新增 `APP_TRUSTED_PROXY_CIDRS`；只有直接来源命中该白名单时才解析标准转发地址。未配置时只使用 socket peer，客户端自带的 `X-Forwarded-For` 不可信。

### 3.5 密码

- 使用现有成熟依赖 `golang.org/x/crypto/argon2`，不引入新的认证框架。
- 新写入使用 Argon2id PHC 格式，首个基线：19 MiB memory、2 次 iterations、parallelism 1、16 字节随机 salt、32 字节输出。
- Argon2 校验必须有进程级并发上限；不能让无界登录请求同时占用内存。
- bcrypt 继续兼容读取；成功验证后再渐进升级。升级写入失败不应把已验证密码伪装成错误，但必须记录低敏失败指标。
- 新建/重置密码为 15～128 个 Unicode 字符，请求最多 256 字节；不 trim、不截断、不静默规范化，不强制大小写/数字/符号组合。
- 登录继续接受既有 bcrypt 凭证的当前长度，避免安全升级直接锁死历史用户。

### 3.6 桌面秘密所有权

- Rust 新增桌面认证会话所有者，负责登录 HTTP、Refresh、启动恢复、轮换、Logout 和 Keychain 更新。
- 同一 Rust 认证协调器串行登录、恢复、Refresh、Logout 和 Keychain 写删；React 合并同批 `401` 刷新，Logout 完成前禁止重登。
- 稳定 `device_id` 由 Rust 写入系统凭据库；合法旧 WebView 标识只作为首次迁移候选，稳定存储失败时不以临时身份注册。
- WebView 可持有短期 Access Token、过期时间、用户摘要和结构化错误，但不能获得 Refresh Token 或已保存密码。
- UI 将“记住账号和密码”改为“记住账号并保持登录”；LocalStore 只保存用户名偏好。
- 删除保存/读取登录密码 IPC。升级时尽力删除旧 `login-password-*` 和旧激活码凭据；清理失败显示真实警告，但不阻塞一次手动登录。
- 继续使用已安装的 `keyring` 4.1.5 和 `reqwest` 0.12.28，不重复实现系统凭据存储或 HTTP 客户端。

### 3.7 Tauri 权限

- `main` capability 仅保留主窗口所需控制面和本地媒体能力。
- `final-effect` capability 只保留窗口控制与媒体展示命令，不允许控制面 HTTP、Keychain、登录/Refresh/Logout、文件选择或无关 IPC。
- 自定义认证命令建立显式权限并在 Rust 内再次校验 `window.label() == "main"`。
- 正式 CSP 去除 `http://localhost:5173`、`ws://localhost:5173`；开发 origin 只放开发覆盖配置。
- 控制面默认要求 HTTPS；开发/测试明文 HTTP 仅允许回环地址，远程测试地址不得接收密码或 Access Token 明文。
- 正式控制面域名由发布配置生成并经过发布脚本校验，不长期保留 `admin.example.com` 模板。

## 4. 数据库迁移

新增 0025 之后的前向迁移，禁止修改 0001～0025。迁移至少包含：

### 4.1 `auth_sessions`

新增字段：

```text
audience                 admin | desktop | legacy
token_family_id          UUID/受约束文本
generation               非负整数
rotated_from_session_id  可空会话引用
rotated_at               可空时间
revoked_reason           固定低基数字符串
```

约束和索引：

- `(token_family_id, generation)` 唯一。

- Refresh 保留清理按绝对过期时间执行，不得提前删除已消费记录。
- 历史会话统一回填 `legacy`；严格 audience 开启时撤销全部 legacy 会话并要求重新登录，不推测旧会话来源。

```text
bucket_type
bucket_hash
failure_count
blocked_until
last_failed_at
```

- `(bucket_type, bucket_hash)` 唯一。

## 7. 测试矩阵

### 7.1 Go 单元与 HTTP

- 管理登录只接受管理账号并签发 `admin`。
- 桌面登录拒绝管理员并签发 `desktop`。
- 管理会话不能访问客户端路由，桌面会话不能访问管理路由。
- Refresh 继承原 user/product/device/audience/family。
- 用户不存在、密码错误、禁用、无产品权限和 audience 不匹配返回相同外部结果。
- dummy hash 路径执行且不在每次请求生成新 hash。
- 可信/不可信代理、伪造 `X-Forwarded-For`、IPv4/IPv6。
- 账号和 IP 双维度限流、成功清零、退避上限和 Context 取消。
- Access 过期后按 Refresh 注销成功；重复注销成功；另一个会话不能被误撤销。
- Argon2 PHC 正确/错误/畸形/超限参数，bcrypt 成功升级与写入失败语义。

### 7.2 PostgreSQL 集成

- 同一旧 Refresh 的两个并发请求只能一个创建下一代。
- 已消费 Refresh 重放撤销整个 family；其他 family 不受影响。
- 服务重启后仍能识别重放和阻塞状态。
- 两个 Go 实例共享账号失败次数，不丢更新。
- 事务取消、锁等待超时、连接断开和提交未知结果不产生两个有效 generation。
- legacy 回填、严格切换撤销、索引与约束可重复回放。
- Retention 保留未到绝对过期时间的已消费 Refresh，并有界清理过期记录和限流桶。

### 7.3 桌面与 Tauri

- React 状态、Web Storage、日志、错误、测试快照均不出现 Refresh Token 或密码。
- 启动恢复只向 WebView 返回 Access Token、过期时间和用户摘要。
- 401 并发请求只触发一次 Rust Refresh；轮换成功后 Keychain 只保留最新 Token。
- 钥匙串写入失败不覆盖可恢复旧 Token，不伪装成功。
- 正常注销、Access 过期注销、断网注销和重复注销均有正确本机/远端状态。
- 旧密码和激活码凭据清理失败可见但不泄露内容。
- `final-effect` 无法调用认证命令或控制面 HTTP；伪造窗口调用在 Rust 内被拒绝。
- 正式 CSP 不包含开发 origin，开发构建仍可连接本地 Vite。

### 9.2 回滚原则

- 数据库新增列、表和索引不在紧急回滚中删除。
- 可临时关闭严格 audience 路由开关以恢复新版服务端兼容读取，但不得恢复签发无 audience 会话。
- 不恢复已经撤销的 Token，不把 `legacy` 会话重新激活。
- 不回退到 WebView 读取 Refresh Token或保存登录密码。
- 不合并 `main` 与 `final-effect` 权限；若最终效果窗口受影响，应补充最小权限而不是恢复共享 capability。
