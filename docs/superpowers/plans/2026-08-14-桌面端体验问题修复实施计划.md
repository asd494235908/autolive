# 桌面端体验问题修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. 本轮暂只创建计划，不执行源码改动。

**Goal:** 修复桌面端可读性、主页/播放器职责、周期参数预览和单源循环问题，同时保留唯一独立播放窗口。

**Architecture:** `DesktopApp` 作为信息与控制所有者，`FinalEffectWindow` 只持有媒体元素；Rust `PlaybackCore` 继续作为播放状态事实源。主页调度运行时预览参数，通过受限 `BroadcastChannel` 下发给播放器；播放器优先本地循环，IPC 只做轮次同步。

**Tech Stack:** React 18、Ant Design 5、Tauri 2、TypeScript、Rust、浏览器原生 `BroadcastChannel`/Web Audio API、现有 FFmpeg/FFprobe 本地媒体链路。

## Global Constraints

- React 统一使用 Ant Design，主题只用 `ConfigProvider` 公开 token 和组件 Props，不覆盖 `.ant-*`。
- 单视频、单 `final-effect` 窗口、同一源循环；不生成 N 个 MP4、不引入 RTMP/OBS、不改 Go 控制面。
- 运行时参数只作用于本地连续预览；未接入 DSP 的高级参数显示不可用，不伪造已生效。
- 播放循环先本地重启，再同步 Rust；IPC 失败不能阻塞媒体播放。
- 开发直接在当前工作区和当前分支进行，不使用 Git worktree；构建在本地/CI，不在服务器构建。
