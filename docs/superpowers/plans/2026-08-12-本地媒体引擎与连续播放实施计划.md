# 本地媒体引擎与连续播放实施计划

> 文档状态：早期方案已废止（2026-08-13）。当前只实施单源视频、单窗口循环、三个独立开关和当前音轨安全替换；本文中的下一项切换和版本队列计划不得实施。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or **superpowers:executing-plans** to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Current scope:** 当前首版只在本地不接推流的前提下，循环播放单个源视频，并由独立开关控制视频处理、声音处理和实时音频幻化；以下“下一项切换”任务是已废止的离线 N 版历史实施计划。

**Goal:** 记录本地媒体引擎探测、重新编码和早期连续切换设计，仅供审计；当前不实施下一项或版本队列。

**Architecture:** Rust 核心负责媒体引擎探测、无 shell 参数构造、任务目录安全、渲染结果哈希和连续播放协调器；Tauri 只暴露主窗口受限 IPC；React 负责显示能力状态、调用本地 Worker 和维护一个窗口内的当前/预加载媒体元素。Go 控制面继续只接收阶段摘要和产物哈希。

**Tech Stack:** Rust 2021、Tauri 2、Serde、现有 `mp4`/`sha2`、FFmpeg/FFprobe（仅本地媒体处理）、React + TypeScript + Ant Design。

## 全局约束

- 不接 RTMP/OBS，不上传本地视频，不把 FFmpeg 用作推流器。
- 不接受前端传入任意可执行路径或 shell 文本；命令只能使用固定的本地媒体引擎探测结果和参数数组。
- 源 MP4 只读；输出阶段必须使用 staging 和不覆盖提交。
- 启用视频效果时禁止 `-c copy`，必须重新编码。
- 没有 FFmpeg/FFprobe 时必须返回明确不可用状态，不伪造输出。
- React 使用 Ant Design，不修改 `.ant-*` 样式。
- 所有新行为先写失败测试，再写最小实现；完成后检查未使用导入、依赖和死代码。
