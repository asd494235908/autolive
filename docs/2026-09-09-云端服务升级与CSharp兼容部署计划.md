## 2. 本次范围与兼容判断

发布 API 与管理端候选镜像，分两步切换。API 优先；确认 C# 正常后，再更新管理端页面。保留现有数据库、网络、服务名、9090 入口和全部有效密钥。C# 安装包、本地 mpv/GPU83/音频/RTMP/虚拟摄像头及运行资源服务器不随本次替换。

相对 `75f5ae5` 的主要服务端变更：

- 新增 `/api/v1/client/sync/items` 及迁移 0028 的三张同步表，接口仅允许 `douyin_desktop` 产品。当前 C# 登录产品仍为 `autolive`，没有调用这些同步接口。
- 登录限流调整：IP 突发容量从 5 提升到 60，增加账号桶；持久化失败退避的账号阈值仍为 5，地址阈值为 50。必须验证同出口多账号及错误密码限流，不把放宽理解为取消保护。
- 授权到期查询增加激活码状态筛选，仅认可 active/used；独立抖音产品的 profile 增加产品、成员、设备及到期校验。
- 当前五个 C# 认证接口的主要响应字段未发生变更。C# 严格拒绝未知字段，所以未来字段扩展仍必须做兼容验证。
- 管理端包含登录页面和会话处理改动，需使用旧管理员会话及新登录分别验证。

当前 C# 链路：登录 → 自动设备授权 → 工作台；恢复和刷新成功后再次设备授权；30 秒心跳，401 时刷新并有限重试。普通网络失败允许已授权会话离线续播，但首次登录/冷启动恢复不能据此保证成功。

已知独立缺口：C# 收到明确授权失效后会锁定工作台，但当前状态变更分支没有统一停止已有视频/RTMP。这不是本次服务端升级引入的问题，也不能靠部署修复。若要求“后台撤权后所有输出立即停止”，必须另行完成 C# 修复及真实验收后才能宣称满足；本次测试必须如实记录，不能把锁界面当成资源已停止。

## 3. 执行前必须补齐的事实

执行人员使用既有受控 SSH 登录方式，不把密码或密钥写入计划、命令记录或仓库。只读核验：

1. 确认真实部署目录、Compose 项目名、所有 Compose/override 文件；记录 API、管理端镜像 tag、image ID/digest、挂载、网络和端口。不要打印完整 `docker inspect` 或解析后的环境变量，防止泄露密钥。
2. 确认 PostgreSQL 主机/容器和数据库身份、持久化方式、剩余空间；只记录脱敏信息。确认生产使用 PostgreSQL 会话存储，而非内存模式。
3. 查询迁移账本实际版本及校验状态；仓库最新为 28。只有确认已到 27 时才按“只新增 0028”评估；否则逐项审查所有待执行迁移，重新评估窗口和回滚。
4. 检查旧镜像是否仍可启动，确认旧程序可以在升级后的数据库上运行。迁移只增表不代表程序一定允许更高 schema 版本，必须在还原库演练。
5. 确认准备验收的 C# 安装版本、包内 profile 和目标地址；准备专用 `autolive` 普通账号及有效设备授权，以及专用管理员账号。不要使用线上用户账号做撤权、注销或密码试错。
6. 检查 9090 现有映射和代理路径。仓库 Compose 默认 `127.0.0.1:18090`，不能覆盖现有云端配置。现有入口为测试 HTTP，HTTPS/域名及生产包迁移作为单独发布，不在此次同时切换；不将本次称作正式 HTTPS 生产准入。

这些事实未核实前，可以准备本地产物，但不能切换线上。健康接口只能证明当前可达，不证明数据库备份、迁移和会话连续性。

## 4. 本地验证与产物

不使用 Git worktree。以确认的提交制作仅含 backend/admin-web/契约和构建所需文件的本地发布目录，记录提交、锁文件、构建工具版本和差异；既有未提交 C# 工作不进入服务端镜像。

发布前执行全量服务端测试及完整服务端构建，因为这是正式执行发布时的门禁；不因此重建无关 C# 安装包。预估测试、镜像构建与还原演练 20～60 分钟，取决于缓存和数据库大小；超过 10 分钟的验证在执行前再次说明实际范围与预计耗时。局部测试不能证明持久化会话和迁移兼容性。

本地命令入口（在对应目录执行，任一步失败即停止）：

```powershell
# backend
go test ./...
go test -race ./internal/httpapi ./internal/service ./internal/store
go build ./cmd/...
# admin-web，使用 package.json 声明的 pnpm 版本
pnpm install --frozen-lockfile
pnpm api:check
pnpm typecheck
pnpm test
pnpm build
```

按仓库集成测试入口，在独立 PostgreSQL 还原库执行迁移及认证会话演练；不对线上直接跑集成测试。Race 检查如本机缺少 C 工具链，在本地 Linux 构建环境完成并记录，不能默默跳过。

使用现有 `backend/Dockerfile` 和 `admin-web/Dockerfile`，在本地构建 `linux/amd64`。管理端 Dockerfile 消费已构建的 dist；固定记录实际基础镜像 digest。候选 tag 使用 `20260909-<提交SHA>-<批次>`，不得覆盖旧 tag。导出 API/admin 镜像归档，生成 SHA-256 与清单；本机启动两镜像，验证代理、API、迁移程序和平台架构。

重新执行现有 C# ControlPlaneHttpClientTests、ControlPlaneAuthCoordinatorTests、ControlPlaneHeartbeatSchedulerTests，验证登录、刷新、取消、错误与心跳状态。当前已有 34 项通过的代码检查证据，但这仍是本地测试，不代替下面的真实升级演练。

## 5. 备份与升级演练

1. 新建本次发布备份目录，权限仅部署管理员可读。备份实际 Compose/override、受控 .env、镜像标识及代理配置，敏感文件不得上传仓库。
2. 对目标应用数据库做一致性逻辑备份；包含账号、设备、激活码、绑定、Access/Refresh 会话及迁移账本。若恢复依赖数据库角色或授权，另备必要定义。禁止只备份业务表或用历史备份代替。
3. 校验备份完整性，恢复到隔离数据库并验证能读取业务数据。备份包含会话凭据材料，应按敏感数据保护，不能向旧客户端暴露演练环境。
4. 在隔离环境用旧版本创建专用 C# 登录会话，再迁移并切到新 API：验证原会话心跳、原 Refresh Token 刷新、新令牌授权和后续心跳；覆盖正常重启和旧镜像回滚。不得并行使用同一 Refresh Token，否则会触发重放保护污染结论。
5. 验证 0028 及所有待执行迁移不会破坏旧数据，记录旧→新、新→旧程序的 schema 兼容结果。演练失败就停止发布。

## 6. 云端实施顺序

预留约 10～20 分钟操作窗口；这不是承诺中断时长，实际切换及迁移时间以演练为准。已有单 API 架构不承诺零停机。

1. 上传镜像归档与校验清单，服务器复核 SHA-256 后 `docker load`。服务器只接收发布产物，不上传源码构建。
2. 保存当前配置与镜像基线；保留原数据库连接、密钥、会话数据、9090 映射和网络。只替换本次镜像 tag 与 APP_VERSION。
3. 使用真实部署 Compose 文件组合运行一次性迁移容器，并核对退出码 0、账本版本与日志。迁移失败不重建 API，也不盲目循环重跑。
4. 只重建 API，不执行 `docker compose down`，不停止共享 PostgreSQL，不删除 volume，不对宿主机执行 prune。
5. 通过 `/api/v1/health` 和 `/api/v1/readyz` 校验候选版本与 JSON 内容；验证管理端现有代理仍指向新 API。超过演练确定的启动阈值（初始建议 3 分钟）仍未就绪，进入回滚。
6. 执行 C# 关键业务验收。通过后再切换管理端镜像，确认页面和登录行为；管理端失败可以独立回滚。
7. 观察至少 20 分钟，覆盖一次 15 分钟 Access Token 生命周期和多次心跳。确认刷新确实发生，不用“等了 20 分钟”代替刷新成功证据。
8. 记录新旧镜像标识、归档摘要、迁移结果、实际中断时间、匿名化验收结果。保留旧镜像、备份及部署配置，清理安排单独执行。

不在计划中提供假定服务器布局的直接替换命令。执行时以步骤 3 核实的 Compose 文件、项目名及授权方式生成具体命令，避免默认文件把现有端口改掉。

## 7. 必须真实通过的验收

| 场景 | 通过标准 |
| --- | --- |
| 新登录与设备授权 | 普通账号登录、autolive 设备授权、有效到期时间、进入工作台成功；管理员不能冒充桌面账号 |
| 旧会话跨发布 | 更新前已运行的 C# 在更新后继续心跳；旧 Refresh Token 合法轮换成功，不强制所有用户重登 |
| C# 冷启动恢复 | 关闭并重新打开，凭据恢复→刷新→重新授权→工作台成功 |
| 原设备身份 | 重启和升级没有额外创建设备或占用新名额 |
| 断网恢复 | 已授权会话暂时离线，恢复后心跳与授权状态正确；不允许冷启动凭空授权 |
| 禁用/到期/撤销 | 只对专用测试账号验证；界面正确限制并报告真实输出是否停止，现存收尾缺口不能写成通过 |
| 视频/切换/RTMP | 新旧会话均执行一次本地播放与切换；已有 RTMP 观察是否被升级间接中断，单独记录画面/声音/网络结果 |
| 管理端 | 原会话和新登录、用户/设备/授权查看、页面刷新正常；不在真实用户上做破坏性验收 |
| 数据与会话 | 授权到期、绑定及已有用户数据一致；记录脱敏统计，不导出 Token 或激活码明文 |
| 运行状态 | 迁移成功、API ready、无异常重启、认证 5xx/401/429 没有异常增长 |

初次切换后登录/授权/旧令牌刷新任一普遍失败即回滚；不要仅因首页可打开就宣布完成。

## 8. 回滚

- API 或 C# 关键验收失败：恢复旧 API tag 与 APP_VERSION，保持同一数据库和密钥，重建 API，复查旧版本健康、登录、刷新及心跳。
- 管理端单独失败：只恢复旧管理端镜像，保留已验收的新 API。
- 新表保留，不执行自动 down migration、不删同步数据。旧程序兼容较新 schema 的结论必须来自还原库演练。
- 若旧程序拒绝新 schema：不得临场绕过版本检查；按演练通过的数据库恢复/前滚方案处理。恢复整个数据库会丢失备份后的写入和会话轮换状态，必须先停止写入并明确恢复时间点、数据损失及重新登录影响，取得对应操作授权后实施。
- 迁移失败且旧 API 未切换：先核对事务/账本，保持旧服务，依据失败原因前滚修复；不假设所有迁移都完整回滚。

## 9. 计划验证与消融

计划编写时已阅读历史部署记录、Compose、Dockerfile、迁移 0028、API 版本差异和 C# 登录授权链路，并检查线上 readyz 的 JSON 与版本。后续执行已核验真实容器、数据库和配置，并完成备份恢复；各项实际结果以执行记录为准。已确认旧 API 拒绝 schema=28，回滚不能仅替换旧镜像，必须先完成隔离演练；线上尚未上传镜像、迁移或切换。

消融检查：复用已有 Compose、Dockerfile、数据库和健康接口；不增加第二套发布框架、常驻蓝绿环境或新数据库服务；不同时迁移域名/HTTPS和 C# 安装包。保留临时隔离还原库，因为真实会话连续性与数据库回滚无法仅靠单元测试证明。保留备份、迁移退出码、C# 真登录与刷新、版本回滚，因为这些直接决定现有用户是否受影响。

验收类别分开报告：文档格式/链接检查、本地测试、本地构建、容器健康、管理页面操作、C# 实际业务结果；没有外部模型调用要求。计划阶段不运行全量产品构建，发布执行阶段必须完成上述门禁。
