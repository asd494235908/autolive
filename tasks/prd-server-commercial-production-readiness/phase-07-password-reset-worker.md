# Phase 7：密码重置 Worker

Parent PRD：[PRD：服务端商业化与生产就绪](../prd-server-commercial-production-readiness.md)
状态：Not Started
最后更新：2026-08-22

## 目标

建立公开自助密码重置和可恢复邮件投递 Worker，保证不枚举账号、Token 不落明文、成功后撤销会话。

## 主 PRD 上下文

- 目标：G-3、G-8
- 成功标准：SC-3、SC-9
- 需求：FR-12、FR-13、FR-34、FR-35，NFR-1、NFR-2、NFR-4、NFR-5、NFR-12
- 场景：场景 4

## 阶段发现门禁

- [ ] 确认邮件供应商、发件域、重置 URL origin、模板多语言与送达限额
- [ ] 确认 users 是否已有邮箱/验证状态；没有时先设计邮箱验证流程
- [ ] 重读密码哈希、用户重置、会话批量撤销、限流和审计实现
- [ ] 重读 Retention Scheduler/Outbox 租约和优雅关闭模式
- [ ] 确认重置 Token TTL、同账号最大未消费数量和投递死信升级规则

## 范围

### 包含

- 已验证邮箱、reset token 哈希、公开请求/确认端点、投递 Outbox/Worker。
- IP + 账号摘要限流、中性响应、重试/死信、会话撤销、审计和脱敏观测。
- React 管理端的投递状态/死信查询和受限手工重试。

### 不包含

- 不用邮件发送新密码，不保存原始 Token/邮件正文。
- 不实施短信、客服人工找回或无验证联系方式的自助重置。
- 不在本阶段默认开放公开注册；默认仍为管理员创建/邀请用户。

## 运营模式边界

- 自助密码重置服务于已存在且有已验证邮箱的全局用户，不泄露其是否属于某个 product。
- 若后续明确开放注册，必须单独增加启用开关、邮箱验证、防枚举、限流和滥用治理；注册后产品成员关系仍需明确邀请/购买流程，不能自动获得所有产品。

## 实施清单

- [ ] 为用户已验证邮箱、password_reset_tokens 和 password_reset_deliveries 增加前向迁移与索引。
- [ ] 生成高熵随机 Token，数据库仅存带领域分离的哈希，限制 TTL/单次使用/用户未消费数量。
- [ ] 公开请求对存在/不存在/未验证邮箱返回相同状态和近似延迟，限制请求体。
- [ ] 请求事务内写 reset token 哈希和 delivery Outbox；生成链接所需明文 Token 只存在必要内存边界。
- [ ] 实现 EmailDeliveryAdapter 最小边界，使用 provider message ID 做投递核对，不在业务代码手写具体协议工具。
- [ ] Worker 有批次/并发/超时/退避/最大尝试/死信/取消/优雅关闭，且不跨网络调用持有 DB 事务。
- [ ] 确认端点锁定 Token 行，单事务更新密码、消费 Token、撤销会话并写审计 Outbox。
- [ ] 清理过期/已消费 Token 与投递记录，尊重安全调查的保留冻结。
- [ ] 将状态查询与重试分别绑定 `password_resets.read`/`password_resets.retry`，重试要求原因、幂等键和审计。
- [ ] React 页只展示脱敏账号摘要、状态、尝试次数、下次时间和错误分类，不返回 Token、邮件正文或完整重置 URL。

## 验证策略

使用可控邮件适配器和时钟做单元/API 测试，用 PostgreSQL 集成覆盖单次消费、并发、Worker 重启和会话撤销。

## 验证清单

- [ ] 存在/不存在/未验证邮箱的外部响应不可用于账号枚举
- [ ] Token 过期、重放、并发消费、更换密码后旧会话失效
- [ ] 投递超时、可重试/不可重试错误、进程重启、死信和 SIGTERM
- [ ] Token、邮箱、重置 URL 和邮件正文不进日志/metrics/trace/审计/快照
- [ ] Go 全量、Race、PostgreSQL integration 和一次受控投递冒烟通过
- [ ] React typecheck/test/build 和投递列表、死信、无权限、重试确认的浏览器冒烟通过

## 退出标准

- [ ] 重置流程无账号枚举、明文 Token 落库或重复消费
- [ ] Worker 在供应商异常和进程重启后可恢复，死信可告警/核对
