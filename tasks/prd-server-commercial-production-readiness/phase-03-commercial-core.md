# Phase 3：商业核心事实

Parent PRD：[PRD：服务端商业化与生产就绪](../prd-server-commercial-production-readiness.md)

## 目标

建立不可变套餐版本、金额快照订单、订阅和权益状态机，为微信支付和下载授权提供唯一商业事实源。

## 阶段发现门禁

- [ ] 重新核对产品的套餐、价格、时长、设备权益和续费语义
- [ ] 检查用户/设备/激活码是否已形成 normalized 唯一事实源
- [ ] 检查幂等、审计 Outbox、事务提交分类和管理员资源权限模式
- [ ] 确认首期是按时长订阅，不在本阶段引入用量计费/多币种/税费

## 范围

### 包含

- plans、plan_versions、orders、subscriptions 及必要权益快照。
- 套餐版本发布/退役、订单创建/关闭、订阅交付/到期/管理员调整。
- 订单和订阅的幂等、唯一约束、审计和查询投影。

### 不包含

- 不调用微信支付，不实现退款/优惠券/发票/多币种。
- 不允许已发布套餐版本原地修改历史订单价格/权益。

## 实施清单

- [ ] 为四类事实新增前向迁移、状态 CHECK、外键、唯一键和常用索引。
- [ ] 定义套餐版本价格为整型分、币种为 CNY、时长/权益为不可变发布快照。
- [ ] 分文件创建 plan/order/subscription repository 与 service，不继续堆入 `controlplane.go`。
- [ ] 为订单创建、关闭和订阅交付实现幂等命令与行锁状态转换。
- [ ] 订阅到期使用服务端时钟派生，需持久化终态时由有界 Worker 执行。
- [ ] 管理员手工调整必须有原因、幂等键、细粒度审计与最后管理员权限防护。
- [ ] 将订阅权益查询接入后续下载授权，但本阶段不生成对象存储 URL。
- [ ] 同步 OpenAPI、错误码、管理类型和架构/数据字典。

## 验证策略

单元测试验证状态机和金额，PostgreSQL 集成测试验证并发/幂等/回滚，API 测试验证权限、错误码与脱敏。

## 验证清单

- [ ] 已发布套餐不可修改，退役套餐不影响历史订单/订阅
- [ ] 同幂等 key 只创建一份订单/交付，不同指纹冲突稳定返回 409
- [ ] 金额无浮点、负数、溢出和币种混淆
- [ ] 并发交付/到期/管理员调整不越过非法状态
- [ ] Go 全量、Race、PostgreSQL integration、OpenAPI 与服务端契约通过

## 退出标准

- [ ] 套餐版本、订单和订阅事实可在重启/并发/故障后恢复
- [ ] 支付和下载阶段只能通过领域入口交付/读取权益
